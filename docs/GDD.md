## 0. 문서 기준

### 0-1. 이 문서의 역할

이 문서는 게임의 제품 방향, 세계관 전제, 핵심 플레이, 시스템 연결, MVP 범위, 개발 순서를 한 번에 확인하는 **통합 설계 허브**다.

세부 스토리 정설·용어·화자 표현·경제 규칙을 전부 중복해서 보관하는 백과사전은 아니다. 문서 분할이 완료되면 상세 내용은 각 기준 문서가 소유하고, 이 문서는 제품 전체의 연결과 우선순위를 설명한다.

# 1. 제품 정의

## 1-1. 한 줄 정의 **[정설+설계 결정]**

> 모험가 경쟁에서 밀려난 수색꾼이 코어가 파괴되어 죽어가는 폐던전에 홀로 들어가, 남들이 지나친 물건을 회수하고 욕심과 위험을 계산하며 같은 입구로 살아 돌아오는 2D 탑다운 저전투 루팅·탈출 게임.

## 1-2. 기본 사양

| 항목 | 기준 |
|---|---|
| 장르 | 루팅·탈출 탐험 / 생존·수집 / 경량 성장 |
| 시점 | 2D 탑다운 |
| 플레이 | PC 싱글플레이 전용 |
| 기본 입력 | 키보드·마우스 우선 |
| 전투 비중 | 낮음. 회피·우회·지연·퇴각 우선 |
| 월드 구조 | 거점과 하나의 반복 탐험형 폐던전 |
| 맵 구조 | 고정된 큰 지도 + 구역별 제한적 변화 |
| 목표 런 길이 | 15~25분 **[밸런스 조정]** |
| 구현 기준안 | TypeScript + HTML5 Canvas **[설계 결정]** |
| 초기 언어 | 한국어 |

## 1-3. 플레이어에게 약속하는 경험

- 비싼 물건을 발견했을 때 기쁘지만, 들고 나갈 수 있을지 바로 걱정된다.
- 약한 캐릭터라도 관찰과 도구 사용으로 위험을 능동적으로 다룰 수 있다.
- 같은 던전을 반복해도 배운 공간 지식은 유효하고, 상황은 조금씩 달라진다.
- 싸우지 않고 빠져나온 판단도 명확한 성공으로 보상받는다.
- 귀환 정산에서 작은 이익과 생활의 개선을 체감한다.
- 세계관을 몰라도 플레이할 수 있지만, 발견물을 모으면 이 세계의 구조가 천천히 보인다.

## 1-4. 명확히 하지 않는 게임

- 선택받은 영웅의 세계 구원 서사
- 마왕을 최종 보스로 삼는 전투 RPG
- 모든 적을 처치하고 방을 정리하는 핵앤슬래시
- 매 런 전체 지형이 바뀌는 완전 절차 생성 게임
- 장비를 잃을 때마다 처음부터 다시 시작하는 극단적 하드코어 익스트랙션
- 멀티플레이·온라인 경쟁 게임

# 2. 핵심 설계 기둥

## 2-1. 욕심과 퇴각

플레이의 중심 질문은 “이길 수 있는가?”보다 “이걸 더 챙기고도 돌아갈 수 있는가?”다. 가치, 무게, 퇴로, 장비 상태, 위험 징후가 한 판단에 함께 작용해야 한다.

## 2-2. 약하지만 무력하지 않은 수색꾼

플레이어는 정면 전투에 약하지만 단순히 도망만 다니지 않는다. 관찰, 하네스, 문과 장치, 소음 유인, 짐 버리기를 이용해 상황을 바꾼다.

## 2-3. 익숙한 공간의 변화

큰 지도와 방의 용도는 유지한다. 문 개폐, 붕괴, 아이템 후보, 위험 이벤트, 적 위치가 제한적으로 달라진다. 학습은 보존되고 암기는 완전한 정답이 되지 않는다.

## 2-4. 죽어가는 장소의 물성

폐던전은 스스로 복구하지 못한다. 변화는 재생이 아니라 붕괴, 노출, 오작동, 소실이다. 고유 물품을 가져간 자리와 사라진 방은 누적 진행을 보여준다.

## 2-5. 생계형 성장

성장은 영웅으로 각성하는 과정이 아니라, 위험한 일을 더 안정적으로 처리하는 숙련의 축적이다. 장비, 하네스, 감정 능력, 정보, 거점 서비스가 조금씩 개선된다.

# 3. 세계관과 서사 기준

## 3-1. 마왕과 던전의 관계 **[정설]**

- 마왕은 오래전에 봉인되었다.
- 던전은 마왕이 만든 시설이 아니며 세계 곳곳에서 자연 발생한다.
- 던전 발생 원리는 아직 완전히 밝혀지지 않았다.
- 마왕과 던전을 직접 연결하는 이야기는 객관적 진실이 아니라 종교적 해석, 민간 소문, 정치적 선동일 수 있다.
- 마왕 부활을 믿거나 획책하는 소수 세력은 존재할 수 있으나 핵심 진행에는 포함하지 않는다.

## 3-2. 던전과 코어 **[정설]**

던전은 마력이 뒤엉켜 생기는 변질 공간이다. 중심부에는 공간 유지, 마력 순환, 구조 복구, 방어 장치 활동을 가능하게 하는 코어가 형성된다.

코어의 정체가 생명체인지 장치인지 자연 기관인지는 확정하지 않는다. 코어 방에는 눈으로 상태를 확인할 수 있는 물리적 형태가 존재한다.

| 상태 | 세계관 작용 | 게임 표현 |
|---|---|---|
| 활성 코어 | 공간 유지, 자가 복구, 에너지 축적 | 본편 탐험 대상이 아닌 배경 설정 |
| 손상 코어 | 불규칙한 마력 흐름과 방어 장치 이상 | 기록·흔적·설명으로 노출 가능 |
| 파괴 코어 | 축적과 복구 정지, 자연 소멸 시작 | 폐던전의 현재 상태 |
| 잔존 에너지 | 남은 공간 유지, 장치 오작동, 잔재 응축, 물건 노출 | 반복 변화와 위험·보상 규칙 |

## 3-3. 폐던전 **[정설]**

폐던전은 코어가 파괴되어 범람 위험은 사라졌지만, 내부 구조·위험·회수품이 남아 있는 던전 전체다. 해당 던전의 주요 보상은 과거 공략대가 대부분 회수했다.

폐던전이 여전히 위험한 이유는 다음과 같다.

- 고장 난 골렘과 방어 장치가 불규칙하게 작동한다.
- 함정이 정상 순서가 아니라 오작동한다.
- 통로와 천장이 무너진다.
- 잔존 마력이 감각과 공간을 흔든다.
- 퇴로가 다음 방문 또는 탐험 중에 막힐 수 있다.
- 지도와 실제 구조가 어긋날 수 있다.

## 3-4. 범람 **[정설]**

범람은 활성 던전에 축적된 에너지와 몬스터·마력 현상이 외부로 넘치는 재난이다. 폐던전은 코어가 파괴되어 범람 위험이 사라지거나 극히 낮다. 이 때문에 행정 조직과 대형 길드의 우선순위에서 밀려난다.

`범람`은 물에 잠긴다는 뜻이 아니다. 코드와 맵에서 침수 공간을 표현할 때는 `Flooded`를 별도 환경 상태로 사용하고, 세계관 용어인 범람과 혼동하지 않는다.

## 3-5. 잔여 구역 **[정설]**

잔여 구역은 폐던전 전체의 다른 이름이 아니다. 과거 공략 중 지나쳤거나, 발견하지 못했거나, 공식 지도에 제대로 기록되지 않은 작은 미답파 공간이다.

잔여 구역은 다음 기능을 갖는다.

- 기본 루트 바깥의 추가 회수 공간
- 고유 유물·기록물이 있는 1회성 발견 공간
- 실패한 수색꾼과 과거 공략대의 흔적을 보여주는 서브 스토리 공간
- 퇴로가 불안정하지만 더 큰 보상을 기대할 수 있는 선택 구역
- 하네스의 새 기능으로 재해석되는 재방문 목표

## 3-6. 플레이어 정체성 **[정설]**

플레이어는 모험가를 동경했지만 전투력, 마력 적성, 신체 능력, 장비와 배경이 부족해 주류 공략 경쟁에서 밀려난 인물이다. 게임 시작 시점부터 이미 수색꾼으로 일하고 있다.

| 항목 | 기준 |
|---|---|
| 현장 명칭 | 수색꾼 |
| 제도상 상위 분류 | 모험가 |
| 행정 표현 | 폐던전 파견 인원 |
| 임무 표현 | 정찰 파견 |
| 초반 목표 | 오늘의 수입과 다음 탐험 비용 마련 |
| 장기 목표 | 안정적 생계, 거점·장비 개선, 더 깊은 구역 수색 |
| 강점 | 관찰, 손재주, 가치 판단, 도구 활용, 퇴각 판단 |
| 약점 | 정면 전투, 과적, 소음, 부상, 장기 교전 |

저주나 특별한 체질 때문에 약하다는 설정은 사용하지 않는다. 현재 약함은 평범한 능력치 부족이다.

## 3-7. 사회와 경제 **[정설]**

던전은 하나의 산업이 되었다. 정예 모험가와 대형 길드는 신규·고수익 던전에 집중하고, 폐던전의 위험한 잔업은 수색꾼에게 외주화한다.

- 수색꾼 길드는 출입 허가, 표식, 기초 정보, 장비 대여, 감정·거래 자격을 제공할 수 있다.
- 길드는 품목 기준가, 회수세, 감정 수수료를 통해 수익을 얻는다.
- 폐던전 내부 사고는 기본적으로 수색꾼 본인 책임이다.
- 폐품은 상인·공방, 잔재는 감정사·연구자·수집가에게 수요가 있다.
- 고유 유물과 핵심 기록물은 판매보다 등록과 정보 해금에 사용한다.

## 3-8. 톤 **[정설]**

핵심 정서는 “세계가 구원된 뒤의 폐허”보다 **화려한 모험가 시대의 그늘**이다.

- 던전: 어둡고 절제된 탐험 긴장감
- 거점: 생활감, 계산, 약간의 유머
- 공포: 놀래키는 호러보다 욕심을 더 부릴지 돌아갈지 고민하는 불안
- 보상: 생환, 작은 이익, 개선, 인정, 수집, 올바른 판단
- 피해야 할 톤: 선택받은 용사, 세계 멸망의 긴급성, 전투 무용담, 과도한 절망

# 4. 전체 플레이 구조

## 4-1. 제품 순환 **[설계 결정]**

```text
실행 → 타이틀 → 거점 → 출정 준비 → 폐던전 탐험
     → 귀환 또는 실패 → 정산 → 거점 → 저장 → 다음 출정
```

## 4-2. 한 런의 흐름

### 준비

- 목표 구역 또는 의뢰 확인
- 장착 하네스 모듈 선택
- 휴대 도구와 소모품 선택
- 적재 여유와 예상 비용 확인

### 진입 초반

- 입구와 안전한 기본 루트 확인
- 저위험 폐품으로 최소 수익 확보
- 이번 런의 문·통로·위험 상태 파악

### 탐색 중반

- 잔여 구역 단서와 고가 회수품 탐색
- 하네스 자원과 도구를 사용할지 보존할지 결정
- 가치 대비 무게와 퇴로를 비교

### 위험 상승

- 오작동 장치, 붕괴, 경비 골렘의 압박 증가
- 필요하면 회수품을 버리고 기동성 회복
- 새로운 구역보다 귀환 동선을 우선 검토

### 귀환

- 들어왔던 입구로 복귀
- 확보품·장비 손상·의뢰·새 발견을 정산
- 판매·감정·등록·수리 후 다음 런 준비

## 4-3. 성공과 실패

| 결과 | 처리 |
|---|---|
| 생환 | 들고 나온 물품만 확보하고 거점 진행에 반영 |
| 부분 성공 | 목표를 놓쳤더라도 회수품과 정보가 있으면 정상 정산 |
| 행동 불능 | 현재 런의 미확보 회수품을 잃고 거점 복귀 |
| 퇴로 상실 | 제한 시간 또는 비상 탈출 실패 시 행동 불능과 동일 처리 |

## 4-4. 실패 손실 **[설계 결정]**

- 현재 런에서 주운 회수품은 잃는다.
- 장착한 기본 하네스와 영구 장비는 사라지지 않지만 내구 손상과 수리비가 발생한다.
- 안전 귀환 전의 고유 유물·기록물은 획득 확정으로 저장하지 않으며 다음 런의 후보에 남는다.
- 돈과 거점·연구 진행도는 유지한다.
- 재출정이 불가능한 파산을 막기 위해 기본 장비와 최소 회복 수단은 보장한다.

## 4-5. 저장 **[설계 결정]**

- 거점 진입, 정산 완료, 주요 등록·구매 후 자동 저장한다.
- 탐험 도중 자유 저장·불러오기는 제공하지 않는다.
- 세션 중단용 일회성 임시 저장은 MVP 이후 검토한다.
- 저장 데이터에는 스키마 버전, 안정적 ID, 획득한 1회성 물품, 던전 변화 상태를 포함한다.

# 5. 던전과 레벨 구조

## 5-1. 공간 원칙 **[설계 결정]**

- 입구가 기본이자 유일한 탈출 지점이다.
- 큰 지도와 방의 정체성은 고정한다.
- 방 전체가 매번 재생성되지 않는다.
- 일부 문, 통로, 붕괴 지점, 상호작용 오브젝트, 위험 배치가 달라진다.
- 좁은 복도를 연속 배치하지 않는다.
- 방은 실루엣, 바닥 패턴, 주요 오브젝트, 조명으로 용도를 구분한다.
- 조사 가능한 지점은 장식과 형태·명도·움직임으로 구분한다.
- 돌아오는 길에도 입구 방향을 추론할 환경 단서를 둔다.

## 5-2. 기준 방 구성

| 구역 | 기본 기능 | 대표 보상 | 대표 위험 |
|---|---|---|---|
| 무너진 입구 | 진입·탈출·첫 상태 확인 | 저가 폐품, 흔적 | 귀환 병목, 후반 봉쇄 위험 |
| 낡은 전실 | 튜토리얼과 기본 루트 분기 | 공략대 잔흔 | 불안정 장치 |
| 저장창고 | 무게·가치 선택 학습 | 폐품, 부품 | 적재물 붕괴 |
| 예배실/의례 흔적 | 민간 신앙과 마왕 관련 오해 전달 | 부적, 기록 조각 | 넓은 노출 구역 |
| 폐숙소 | 생활 흔적과 실패한 탐험자 단서 | 소형 폐품, 개인 기록 | 시야 차단, 소음 |
| 경비실 | 방어 체계와 골렘 정보 | 장치 부품, 열쇠 정보 | 경보, 고장 난 골렘 |
| 기록실 | 던전·코어·공략 기록 | 핵심 기록물 후보 | 불안정 서가, 마력 반응 |
| 침식된 마력 구역 | 잔존 에너지의 활동성 표현 | 잔재, 미확인 물품 | 감각 교란, 구역 변화 |
| 보관고 | 고가 회수 선택 | 잔재·고유 유물 후보 | 개방 작업, 소음 증가 |
| 봉쇄된 하층 진입문 | 장기 진행과 더 깊은 구역 암시 | 지도·열쇠 단서 | 현재 진입 제한 |
| 잔여 구역 | 작은 선택형 비밀 공간 | 1회성 발견물 | 불안정 퇴로 |

예배실은 던전이 마왕과 직접 연결된 증거가 아니라, 과거 탐험자나 지역 사람들이 두려움 때문에 남긴 의례 흔적으로 사용한다.

## 5-3. 반복 변화 규칙

| 변하는 것 | 범위 |
|---|---|
| 아이템 | 방별 후보 풀 안에서 위치와 종류 변화 |
| 위험 | 방별 위험 이벤트 후보 중 일부 활성화 |
| 문·통로 | 일부만 잠김·막힘·개방됨 |
| 골렘·장치 | 지정 스폰 후보 안에서 위치·상태 변화 |
| 잔여 구역 | 여러 후보 중 일부가 단서와 함께 노출 |
| 다른 수색꾼 흔적 | 발자국, 빈 상자, 버린 가방, 경고 표식으로 등장 |

| 변하지 않는 것 | 이유 |
|---|---|
| 큰 지도와 방의 용도 | 플레이어의 공간 학습 보존 |
| 입구 위치 | 귀환 구조의 기준 |
| 획득 완료한 고유 유물·기록물 | 원본성 유지 |
| 핵심 진행 이벤트의 최초 발생 | 중복 방지 |

## 5-4. 잔존 에너지와 보상 노출 **[정설+설계 결정]**

반복 런에서 새 보물이 생성되는 것이 아니다. 잔존 에너지가 유실되며 잔해 밑의 물건, 느슨해진 장치, 응축된 잔재가 새로 상호작용 가능한 상태가 된다.

- 한 런의 기본 보상 노출량은 일정 범위로 유지한다.
- 던전이 죽어간다고 보상과 위험이 매번 단순 감소하지 않는다.
- 고유 유물·기록물을 회수한 방은 이후 소실, 봉쇄, 상호작용 감소로 변한다.
- 방 소실은 콘텐츠 고갈 처벌보다 폐던전의 누적 소멸을 보여주는 장치로 쓴다.
- 변화는 탐험 시드로 재현할 수 있게 한다.

## 5-5. 공식 지도와 잔여 구역

공식 지도에는 과거 공략대의 주요 루트가 기록돼 있다. 지도는 미완성 백지가 아니라, 현재 폐던전과 조금씩 어긋나는 오래된 정답지다.

- 방문한 방과 확인한 통로를 표시한다.
- 무너진 길과 현재 열린 길을 별도로 표시한다.
- 개인 표식, 지도 가장자리의 덧그림, 좌표 조각으로 잔여 구역을 암시한다.
- 잔여 구역의 정확한 위치를 바로 공개하지 않는다.
- 지도와 인벤토리를 열면 게임 시간은 일시정지한다. 난이도는 메뉴 조작 속도가 아니라 현장 판단에서 만든다.

## 5-6. 현재 프로토타입 대응 **[현재 구현→설계 변환]**

| 현재 코드 | GDD 대응 | 처리 |
|---|---|---|
| `Entrance` | 무너진 입구·전실 | 유지 후 세부 역할 분리 가능 |
| `Storage` | 저장창고 | 유지 |
| `Archive` | 기록실 | 표시 이름만 한국어 기준과 연결 |
| `Flooded` | 침수 구역 또는 침식된 마력 구역 | `범람`과 혼동되지 않도록 역할 확정 필요 |
| `Exit` | 봉쇄된 하층 진입문 | 별도 탈출구로 사용하지 않고 `LowerGate` 계열 ID로 변경 권장 |
| `C_AB`, `C_BC`, `C_B` | 구역 연결 복도 | 임시 ID 유지 가능, 의미 기반 ID로 점진 전환 |
| `RUN_START_POS=(120,100)` | 입구의 플레이어 시작점 | 프로토타입 수치로 유지 |
| `CHASER_SPAWN=(650,120)` | 경비 추적자 후보 스폰 | 프로토타입 수치로 유지 |

# 6. 플레이어 행동과 상태

## 6-1. 핵심 행동

| 행동 | 목적 |
|---|---|
| 이동 | 방과 복도 탐색, 위험 회피 |
| 조사 | 물건·흔적·장치의 정보 확인 |
| 회수 | 잔류물을 인벤토리에 적재 |
| 하네스 사용 | 분석·안정화·우회·견인·비상 대응 |
| 도구 사용 | 소음 유인, 문 고정, 임시 조명 등 상황 변화 |
| 버리기 | 무게를 줄이고 도주·귀환 능력 회복 |
| 지도 확인 | 퇴로와 잔여 구역 단서 판단 |
| 퇴각 | 입구를 향해 탐험을 종료하는 능동적 결정 |

## 6-2. 플레이어 상태

| 상태 | 기능 |
|---|---|
| 건강 | 피해와 행동 불능 판단. 세부 수치는 단순화 |
| 부상 | 이동·상호작용 효율에 일시적 불이익 |
| 적재 부담 | 이동 속도와 소음에 영향 |
| 소음 | 주변 장치·골렘의 탐지에 영향 |
| 하네스 충전 | 특수 행동의 공용 자원 |
| 장비 내구 | 반복 사용과 실패의 비용 |

공포 수치는 초기 MVP에 넣지 않는다. 분위기와 정보 제한만으로 긴장이 부족한지 확인한 뒤 별도 시스템으로 검토한다.

## 6-3. 적재 모델 **[설계 결정]**

인벤토리는 **제한 슬롯 + 무게 부담 단계**를 결합한다.

- 슬롯은 물건 개수와 크기 선택을 만든다.
- 총무게는 이동 속도와 소음에 영향을 준다.
- 무게는 정상·부담·과적의 세 단계로 표시한다.
- 과적 상태에서도 이동은 가능하지만 추적 상황에서 매우 불리하다.
- 대형 물품은 여러 슬롯을 차지하거나 하네스 견인이 필요하다.
- 정확한 슬롯 수, 무게 한도, 감속률은 G1 플레이테스트에서 정한다.

## 6-4. 가치 정보

- 폐품은 대략적인 기준가를 즉시 확인한다.
- 미확인 물품은 무게와 외형만 알고 가치·분류는 감춘다.
- 플레이어 성장으로 감정 전 가치 범위를 더 정확히 추정한다.
- 고유 유물·기록물은 돈 대신 등록·정보 보상을 표시한다.
- UI에는 가격뿐 아니라 무게 대비 가치 비교를 제공한다.

# 7. 하네스 엔지니어링

## 7-1. 정의 **[설계 결정]**

하네스 엔지니어링은 수색꾼이 착용하는 모듈식 작업 하네스를 조정해, 폐던전의 망가진 설비와 불안정한 잔류물을 다루는 기술 체계다.

하네스는 전투용 강화복이 아니다. 적재 프레임, 고정 장치, 마력 감지기, 연결 도구, 비상 방전기를 결합한 생존·회수 장비다. 성장의 중심은 공격력보다 더 많은 상황을 처리하는 능력이다.

## 7-2. 핵심 동작

| 동작 | 기본 효과 | 주요 선택 |
|---|---|---|
| 분석 | 위험·잔류물·장치 상태를 읽음 | 충전을 써서 정확도를 높일지 결정 |
| 연결·우회 | 고장 난 문과 장치에 임시 접속 | 새 경로 확보와 경보 위험 사이 선택 |
| 안정화 | 붕괴 지점·마력 반응·유물을 잠시 안전하게 함 | 시간을 들여 안전을 얻을지 결정 |
| 견인 | 무겁거나 고정된 물건을 이동 | 고가품과 느린 귀환 사이 선택 |
| 비상 방전 | 골렘·장치를 잠깐 멈추거나 밀어냄 | 충전을 생존에 쓸지 탐색에 남길지 결정 |

## 7-3. 모듈 구조

| 계열 | 예시 역할 |
|---|---|
| 감지 모듈 | 위험 예고, 미확인 분류 추정, 잔여 구역 반응 |
| 작업 모듈 | 문 우회, 함정 정지, 잔해 안정화 |
| 운반 모듈 | 무게 한도, 대형품 견인, 짐 버리기 속도 |
| 비상 모듈 | 방전, 문 임시 고정, 짧은 탈출 가속 |

출정 전 제한된 모듈만 장착한다. 모든 기능을 한 번에 가져갈 수 없게 해 런의 목표에 따른 준비 선택을 만든다.

## 7-4. 자원 규칙 **[설계 결정]**

- 하네스는 한 런 동안 공유하는 충전 자원을 사용한다.
- 분석의 기본 정보는 무료로 제공하되, 정밀 분석과 물리적 작업이 충전을 소모한다.
- 충전은 던전 안에서 쉽게 회복되지 않는다.
- 일부 위험한 잔존 에너지 지점에서 충전할 수 있지만 장비 손상 또는 경보 위험이 있다.
- 장비 내구와 충전은 별개다. 내구는 거점 수리 비용, 충전은 런 중 선택을 담당한다.

## 7-5. 성장 축

- **관찰 숙련:** 분석 속도와 정보 정확도
- **현장 정비:** 연결·우회·안정화 효율
- **회수 기술:** 적재, 견인, 대형품 처리
- **비상 대응:** 짧은 무력화와 퇴로 확보
- **운영 효율:** 충전량, 모듈 슬롯, 수리 효율

성장은 선형 스킬 트리보다 모듈 해금과 제한된 업그레이드 선택으로 시작한다. MVP에서는 분석·안정화·비상 방전 세 동작만 구현한다.

## 7-6. 하네스 설계 금지선

- 모든 잠긴 문을 여는 만능 열쇠로 만들지 않는다.
- 충전량만 늘려 문제를 무시하게 만들지 않는다.
- 공격 콤보와 대미지 빌드의 중심으로 만들지 않는다.
- 하네스 없이는 기본 탐색조차 불가능하게 만들지 않는다.
- 모듈 설명과 조작이 인벤토리 관리보다 복잡해지지 않게 한다.

# 8. 잔류물·아이템·감정

## 8-1. 분류 **[정설+설계 결정]**

`잔류물`은 길드·행정이 회수 가능한 물품 전체를 가리킬 때 쓰는 상위 표현이다.

| 분류 | 의미 | 반복 | 기본 처리 | UI 기준색 |
|---|---|---:|---|---|
| 미확인 물품 | 아직 감정되지 않은 임시 상태 | 실제 분류에 따름 | 감정 전 가치·분류 비공개 | 회색 |
| 폐품 | 물리적으로 남은 잡동사니·부품 | 반복 | 판매, 수리·제작 재료 | 갈색 |
| 잔재 | 마력과 기억의 흔적이 엉긴 물질·현상 | 낮은 확률 | 감정 후 판매·연구·수집 | 파란색 |
| 고유 유물 | 특정 사건·인물과 연결된 단 하나의 원본 | 1회 | 판매 불가, 등록·정보·보상 | 보라색 |
| 핵심 기록물 | 세계관과 사건의 진실을 여는 원본 기록 | 1회 | 판매 불가, 연구자 보관 | 초록색 |

색상만으로 구분하지 않고 아이콘·명칭·문자 표기를 함께 사용한다.

## 8-2. 감정

- 거점 감정사는 여러 물품을 비용과 함께 확정 감정한다.
- 휴대용 감정 도구는 던전 안에서 제한 횟수 또는 낮은 정확도로 사용한다.
- 감정 전에도 무게·외형·위험 표시는 확인할 수 있다.
- 잔재의 기본 기억 표현은 짧은 텍스트로 제한한다.
- 환청·환시·대규모 환경 연출은 후순위다.

## 8-3. 획득 규칙

- 구역마다 맥락에 맞는 아이템 후보 풀을 둔다.
- 기록실에서는 기록물, 경비실에서는 장치 부품, 폐숙소에서는 생활 흔적이 주로 나온다.
- 풀 안에서 실제 등장 아이템과 위치를 시드 기반으로 결정한다.
- 고유 유물과 기록물은 안전 귀환·등록 후 영구 획득 플래그를 저장한다.
- 이미 획득한 원본은 이후 후보에서 제외한다.

## 8-4. 보호 규칙

- 고유 유물, 핵심 기록물, 특정 의뢰품은 판매할 수 없다.
- 버리기 전 확인을 표시하되, 추적 중 빠른 조작을 방해하지 않도록 보호 물품은 빠른 버리기 대상에서 제외한다.
- 저장과 데이터에서는 표시 이름이 아니라 안정적 ID로 원본성을 관리한다.

# 9. 위험·적·추적·전투

## 9-1. 위험 유형

| 유형 | 사전 징후 | 비전투 대응 |
|---|---|---|
| 붕괴 | 먼지, 균열, 낙석음 | 안정화, 우회, 신속 통과 |
| 함정 오작동 | 끊긴 리듬, 불규칙 빛 | 분석, 타이밍 통과, 임시 정지 |
| 마력 침식 | 화면·소리 왜곡, 하네스 경고 | 체류 단축, 안정화, 다른 경로 |
| 경비 장치 | 경보등, 작동음 | 전력 우회, 시야 차단, 문 고정 |
| 고장 난 골렘 | 발소리, 긁힌 흔적, 탐지음 | 유인, 우회, 짧은 무력화 |
| 퇴로 변화 | 진동, 지도 경고, 잔해 이동 | 조기 귀환, 대체 통로, 짐 포기 |

모든 큰 위험은 발생 전에 최소 하나의 시각 또는 청각 단서를 제공한다.

## 9-2. 전투 규칙 **[설계 결정]**

- 기본 공격 버튼과 반복 대미지 전투를 두지 않는다.
- 하네스 비상 방전, 투척 유인물, 문 차단으로 적을 잠시 지연한다.
- 일부 소형 위협은 환경이나 제한 소모품으로 제거할 수 있지만 파밍 대상이 아니다.
- 고장 난 골렘과 추적자는 영구 처치할 수 없다.
- 위험 회피 결과를 정산과 플레이 평가에서 긍정적으로 보여준다.

## 9-3. 추적자 **[설계 결정]**

현재 프로토타입의 추적자는 첫 던전의 **고장 난 경비 골렘** 역할로 통합한다. 평소에는 지정 구역을 배회하지만 경보가 누적되거나 고가품을 무리하게 회수하면 적극 추적 상태가 된다.

### 추적 단계

1. **휴면/순찰:** 소리와 시야에 제한적으로 반응한다.
2. **의심:** 발소리·조사 흔적을 확인하고 마지막 위치로 이동한다.
3. **추적:** 플레이어를 압박하며 입구 귀환 동선을 바꾸게 한다.
4. **수색:** 시야를 잃으면 주변을 확인한 뒤 단계가 낮아진다.

### 출현·강화 조건

- 경비실 또는 고가 보관고의 경보 작동
- 반복적인 큰 소음
- 하네스 강제 우회 실패
- 잔존 에너지 활동 구역에서 장시간 체류

단순 체류 시간만으로 무조건 등장시키지 않는다. 플레이어 행동과 경고 단서를 통해 위험이 커졌음을 이해할 수 있어야 한다.

## 9-4. 추적 대응

- 짐을 버려 속도와 소음을 낮춘다.
- 방전으로 잠깐 멈춘다.
- 문을 임시 고정한다.
- 소음 도구로 다른 구역에 유인한다.
- 지도에서 확인한 우회로를 사용한다.
- 위험 구역을 통과하게 유도해 경로를 지연한다.

## 9-5. 난이도 원칙

- 정보 부족으로 억울하게 실패하게 하지 않는다.
- 적 체력 증가보다 경고 시간, 감지 민감도, 수리비, 보상 여유를 조절한다.
- 기본 난이도에서도 실패 후 즉시 재기할 수 있다.
- 색각, 화면 밝기, 상호작용 홀드, 화면 흔들림 보조 설정을 후반 제품 단계에 포함한다.

# 10. 거점·경제·성장

## 10-1. 거점 형식 **[설계 결정]**

MVP의 거점은 실제 이동 공간이 아니라 빠른 메뉴형 허브로 만든다. 기능과 NPC 관계가 안정된 뒤 작은 시각적 공간으로 확장할 수 있다.

## 10-2. 거점 기능

| 기능 | 담당 | 역할 |
|---|---|---|
| 정산·허가·의뢰 | 길드 관리자 | 수입·비용·평판·출정 목표 정리 |
| 판매·구매 | 상인 | 폐품 매입, 기본 도구·소모품 판매 |
| 감정 | 감정사 | 미확인 물품과 잔재 확인 |
| 기록 등록 | 연구자 | 핵심 기록물 보관, 해설, 수집 목록 |
| 수리·개조 | 공방/하네스 화면 | 장비 수리, 모듈 해금·장착 |
| 종교적 반응 | 성직자 | 마왕·봉인·저주에 대한 사회적 시선 전달 |

전직 모험가와 다른 수색꾼은 튜토리얼·서브 스토리용 선택 NPC다. 봉인 관리인은 별도 직업으로 만들지 않는다.

## 10-3. 경제 흐름

```text
출정 비용·소모품·장비 마모
→ 폐던전 탐험
→ 회수품 판매·감정·등록
→ 회수세·감정료·수리비 차감
→ 순이익
→ 하네스·장비·거점 서비스 개선
→ 더 깊고 위험한 수색
```

## 10-4. 가격과 거래

- 길드가 기본 기준가와 회수세를 주도한다.
- 상인과 공방은 특정 폐품을 우대할 수 있다.
- 잔재는 감정 후 판매하거나 연구·수집에 사용할 수 있다.
- 암시장은 MVP와 첫 출시 범위에서 제외한다.
- 정산 화면에는 총 판매액보다 순이익을 크게 표시한다.
- 경제는 생계 압박을 주되, 한 번의 실패가 장기 진행을 막지 않게 한다.

## 10-5. 성장 구조

| 성장 축 | 효과 |
|---|---|
| 하네스 모듈 | 새로운 분석·작업·비상 행동 해금 |
| 운반 장비 | 슬롯·무게 부담·견인 효율 개선 |
| 탐색 도구 | 지도, 조명, 소음 유인, 문 고정 선택 확대 |
| 감정 숙련 | 미확인 물품의 정보 범위와 가치 추정 개선 |
| 장비 정비 | 내구도·수리 효율·실패 손실 완화 |
| 거점 서비스 | 보관함, 감정, 연구, 의뢰 편의 향상 |
| 사회적 신뢰 | 더 좋은 정보·허가·의뢰 접근 |

공격력과 체력의 수치 상승은 보조 수준으로 제한한다.

# 11. 내러티브 진행과 발견물

## 11-1. 메인 진행 **[정설+설계 결정]**

### 1단계 — 변두리 수색꾼의 생업

- 폐품으로 오늘의 비용을 마련한다.
- 수색꾼의 낮은 사회적 위치와 현실을 배운다.
- 모험가 시대의 화려함을 멀리서 바라본다.

### 2단계 — 폐던전의 규칙 학습

- 코어가 없어도 내부 위험이 남는 이유를 체험한다.
- 반복 진입, 적재, 퇴각, 하네스 사용에 익숙해진다.
- 공식 지도 바깥의 잔여 구역을 처음 발견한다.

### 3단계 — 발견물을 통한 세계 이해

- 던전 자연 발생과 코어 연구 기록을 모은다.
- 과거 공략대와 실패한 수색꾼의 흔적을 연결한다.
- 연구자의 해석이 마왕과 던전의 직접 인과를 점차 부정하는 방향으로 변한다.

### 4단계 — 자기 방식의 인정

- 더 깊은 잔여 구역과 봉쇄된 하층의 일부 목표를 달성한다.
- 고유 유물·기록 목록과 거점을 충분히 성장시킨다.
- 영웅이 되지 않아도 수색꾼으로 안정적인 생계와 인정을 확보한다.

## 11-2. 결말 방향 **[설계 결정]**

기본 결말은 세계 구원이 아니라 **수색꾼으로서 자립**이다. 첫 던전의 주요 수집 목표, 거점 개선, 하층 관련 핵심 목표를 달성하면 하나의 완결 상태를 제공한다.

마왕 부활 세력과 세계의 근원은 선택적 떡밥으로 남긴다. 관련 발견물을 모두 모아도 거대한 최종 전투로 이어지지 않고, 세계에 아직 설명되지 않은 불안이 남아 있음을 보여주는 추가 해석 정도로 마무리한다.

## 11-3. 발견물 유형

| 유형 | 전달 내용 | 주 배치 구역 |
|---|---|---|
| 유명 모험가의 흔적 | 화려한 시대의 이면 | 전실, 경비실 |
| 실패한 수색꾼의 흔적 | 생업의 위험과 잔여 구역 단서 | 폐숙소, 숨은 통로 |
| 던전 발생 기록 | 자연 발생 가설 | 기록실 |
| 코어 연구 기록 | 코어·소멸·잔존 에너지 | 기록실, 침식 구역 |
| 회수 시장 기록 | 길드 가격과 외주 구조 | 저장창고, 거점 |
| 봉인과 소문 | 마왕과 던전을 연결하는 사회적 오해 | 예배실/의례 흔적 |
| 봉쇄 하층 단서 | 장기 수색 목표 | 경비실, 기록실, 보관고 |

## 11-4. 전달 방식

1. 던전에서 짧은 설명의 발견물을 얻는다.
2. 안전 귀환 후 연구자나 관련 NPC에게 등록한다.
3. 짧은 해설과 도감 항목이 열린다.
4. 중요한 정보는 언제든 다시 확인할 수 있다.
5. 같은 물건에 모든 NPC가 반응하게 만들지 않고 필요한 담당자만 반응한다.

## 11-5. 실패한 수색꾼 서브 스토리

같은 표식, 필체, 장비, 지도 메모가 여러 런에 걸쳐 이어진다. 인물은 직접 등장하지 않아도 된다. 흔적은 잔여 구역의 단서와 “누군가 여기까지 왔지만 돌아오지 못했다”는 긴장을 함께 제공한다.

## 11-6. 연구자의 지식 변화

| 진행 | 인식 |
|---|---|
| 초반 | 마왕 전승과 던전 기록의 관계를 판단 유보 |
| 중반 | 던전 발생이 봉인보다 지맥·마나 이상과 더 자주 겹친다고 봄 |
| 후반 | 마왕의 이름은 던전을 설명하려 덧씌운 공포일 수 있으며 직접 인과의 증거가 부족하다고 정리 |

연구자의 지식 변화와 연구자가 사용하는 어휘는 별도 문서에서 관리한다.

상황 표시:

- 상호작용 안내
- 예상 가치·무게
- 소음 반응
- 의뢰·고유 물품 획득
- 문·구역 상태 변화

## 12-4. 인벤토리와 지도

- 열면 싱글플레이 시간이 멈춘다.
- 가치·무게·분류·판매 보호 여부를 한 화면에서 비교한다.
- 정렬과 필터는 MVP 이후 넣되, 핵심 정보는 처음부터 제공한다.
- 빠른 버리기는 가장 최근 선택한 일반 회수품에만 적용한다.

## 12-5. 접근성 기준

- 분류를 색상에만 의존하지 않는다.
- 밝기/감마를 첫 실행과 옵션에서 조절한다.
- UI 크기와 자막·텍스트 크기를 제공한다.
- 화면 흔들림과 번쩍임 감소 옵션을 제공한다.
- 길게 누르기 시간을 조정하거나 토글로 바꿀 수 있게 한다.
- 상호작용 지점을 과도하게 숨겨 난이도를 만들지 않는다.

# 13. 시각·사운드 방향

## 13-1. 시각 원칙

- 탑다운에서 통행 가능 영역과 방의 역할이 즉시 읽혀야 한다.
- 어둡지만 조사 대상, 위험 징후, 퇴로는 식별 가능해야 한다.
- 던전의 변화는 새로 생긴 장식보다 사라짐, 붕괴, 비어 있는 자리로 표현한다.
- 수색꾼은 영웅적 갑옷보다 작업복, 가방, 하네스, 임시 장비가 중심이다.
- 거점은 던전보다 따뜻하고 생활감 있는 색온도를 사용한다.

그림체는 현재 표본 비교 단계다. 최종 스타일을 고르기 전에도 실루엣·가독성·색상 규칙은 먼저 검증한다.

## 13-2. 메인 화면 이미지 기준

- 홀로 폐던전 입구 또는 거대한 내부 공간을 바라보는 수색꾼
- 하네스와 적재 장비가 캐릭터 정체성을 보여줌
- 멀리 보이는 잔존 마력과 고장 난 경비 장치
- 보물보다 퇴로와 위험이 함께 보이는 구도
- 세계를 구하는 영웅 포즈보다 생계형 탐험의 고독을 강조

## 13-3. 사운드 원칙

- 평상시는 환경음과 하네스 기계·마력음을 중심으로 한다.
- 위험은 음악 전환보다 발소리, 경보, 구조물 진동으로 먼저 알린다.
- 하네스 분석·연결·충전 부족 상태를 서로 다른 음색으로 구분한다.
- 추적자는 접근 방향과 상태를 소리로 파악할 수 있어야 한다.
- 거점은 던전보다 가벼운 생활 소음과 짧은 음악을 사용한다.

# 14. 기술 구조와 데이터

## 14-1. 구현 기준 **[설계 결정]**

현재 `GameCanvas.tsx` 프로토타입과 엔진 없는 구현 선호를 살려 **React/Vite/TypeScript + HTML5 Canvas**를 기준안으로 삼는다.

- React는 타이틀, 거점, 정산, 옵션 등 제품 UI를 담당한다.
- Canvas 게임 루프는 이동, 충돌, 시야, 위험, 상호작용을 담당한다.
- 게임 규칙은 React 컴포넌트와 분리한 TypeScript 모듈에 둔다.
- Python은 콘텐츠 검수·데이터 변환·테스트 도구에만 선택적으로 사용한다.

G0에서 현재 저장소 구조와 성능을 확인해 최종 확정한다. 다른 엔진으로 이전할 근거가 없다면 기존 프로토타입을 유지한다.

## 14-2. 모듈 경계

```text
App/             부팅, 화면 흐름, 전역 게임 상태
Core/            ID, 이벤트, 시간, 공통 타입
Gameplay/        플레이어, 탐색, 상호작용, 위험, 인벤토리, 탈출
Harness/         모듈, 충전, 분석, 작업, 비상 행동
Meta/            거점, 경제, 감정, 연구, 장비, 성장
Infrastructure/  저장, 설정, 입력, 오디오, 로그
UI/              타이틀, HUD, 지도, 인벤토리, 거점, 정산, 옵션
Data/            아이템, 방, 루트, 위험, 경제, 텍스트
Tests/           단위, 통합, 스모크, 시드 재현
```

## 14-3. 주요 상태

- Boot
- Title
- Hub
- Loadout
- Exploration
- Results
- Failure
- Pause
- Loading

화면 전환은 중앙 상태 관리자를 거치고, 개별 UI가 장면을 직접 소유하지 않는다.

## 14-5. 기술 원칙

- 표시 이름과 코드 ID를 분리한다.
- 밸런스 수치와 콘텐츠는 코드에 직접 고정하지 않는다.
- 저장 데이터에 스키마 버전을 둔다.
- 테스트용 던전과 실제 콘텐츠를 분리한다.
- 시드·던전 버전을 오류 로그에 남긴다.
- UI가 게임 규칙을 직접 소유하지 않는다.
- 한 작업 티켓에서 관련 없는 리팩터링을 섞지 않는다.

## 17-2. 문서 책임

| 영역 | 질문 |
|---|---|
| GDD | 어떤 게임이며 시스템이 어떻게 연결되는가? |
| Story | 세계에서 무엇이 사실이고 왜 그런가? |

| Project | 무엇을 확정했고 무엇이 미정이며 왜 바뀌었는가? |
| Archive | 이전 시점의 원본은 무엇이었는가? |

## 17-3. 운영 규칙

- 하나의 상세 정의는 한 문서만 소유한다.
- Story는 “왜”, Design은 “어떻게”, Reference는 “무엇이라 부르는가”를 담당한다.
- 공식 용어, 화자별 표현, 문체 규칙을 분리한다.
- 활성 문서 파일명에는 버전을 붙이지 않는다.
- 원본은 삭제하지 않고 Archive에 읽기 전용으로 보존한다.
- 분할 중 새 변경은 `migration_changes.md`에 먼저 기록한다.
- 결정은 `DEC`, 미결정은 `Q`, 이관 변경은 `MIG-CHG` ID로 관리한다.
- 표시 명칭과 내부 코드 ID·저장 키를 분리한다.
- Archive와 보류안을 현재 설정으로 사용하지 않는다.
- 해소된 질문은 관련 본문에 통합하고 질문 목록에서 닫는다.
- 새 질문은 관련 문서 바로 아래와 중앙 `open_questions.md`에 연결한다.

# 20. 검증 기준

## 20-1. 핵심 재미

- 플레이어가 한 런에서 최소 한 번 더 들어갈지 돌아갈지 고민한다.
- 가치와 무게 때문에 적어도 하나의 회수품을 포기하거나 교체한다.
- 위험을 맞기 전에 징후를 알아차릴 수 있다.
- 싸우지 않고 해결한 선택이 만족스럽다.
- 입구로 돌아왔을 때 안도감이 있다.

## 20-2. 반복성

- 연속 런에서 배치와 위험이 달라도 방의 정체성은 유지된다.
- 이전에 배운 지도 지식이 다음 런에 도움이 된다.
- 고유 유물과 기록물이 중복 생성되지 않는다.
- 보상량의 편차가 실력보다 운을 크게 만들지 않는다.
- 고유 물품 회수 뒤 구역 변화가 누적 소멸로 읽힌다.

## 20-3. 성장과 경제

- 귀환 정산에서 총액, 비용, 순이익을 이해할 수 있다.
- 성장 뒤 강해졌다기보다 노련해졌다고 느낀다.
- 실패해도 다음 출정이 가능하다.
- 감정·연구·판매의 역할이 서로 다르다.
- 하네스 모듈 선택이 실제 플레이 방식을 바꾼다.

## 20-4. 서사와 톤

- 플레이어가 영웅보다 수색꾼으로 느껴진다.
- 마왕과 던전의 관계가 객관적 사실과 사회적 믿음으로 구분된다.
- 긴 설명을 읽지 않아도 폐던전과 잔여 구역의 차이를 이해한다.
- 던전의 긴장과 거점의 생활감이 함께 유지된다.
- 세계관 발견은 선택적이지만 모으면 일관된 해석이 된다.
