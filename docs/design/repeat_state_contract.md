# 반복 탐험 상태·시드 계약 검토안

## 지위와 사용 범위

DEV-0501은 현재 시제품에서 G5를 구현하기 위한 상태 계약을 검토한다. 이 문서는 `draft`이며 단독 구현 권한이 아니다. 아래 **기존 기준**, **현재 코드**, **제안**을 구분해 읽는다. 새 구현은 해당 작업에서 confirmed 기준·현재 승인된 시험 규칙과 다시 대조한다. 제품 코드, 저장 키/스키마, 확률·수량·보상, 정식 지도·이름·하층 콘텐츠를 이번에 추가하지 않았다.

2026-10-21 사용자 진행 지시로 G5 기술 준비를 시작했다. [G4의 미평가·사용자 보류](../project/g4_meta_review.md#dev-0435-누적-결과와-현재-판단)는 유지한다. 계약 정리는 G4 전체 사람 평가 통과나 G5 반복성 구현·재미 검증을 뜻하지 않는다.

`pending_departure`의 `reserved`는 시작 전 예약, `started`는 시작 저장 완료다. 재실행 때 전자는 유료 도구 예약을 반환하고 후자는 미정산 출정을 정리하며 유료 휴대분을 반환하지 않는다. 현재 `recover_departure()`는 시작된 중단을 일반 실패 정산으로 실행하지 않으며 내구 손상을 새로 계산하지 않는다. 이 구별을 시드 도입으로 바꾸지 않는다.

## 제안: 상태 소유와 입력·출력

아래 이름은 설명용 책임 이름이며 새 클래스·저장 키·콘텐츠 ID 선언이 아니다.

| 계층 | 입력 | 출력·수명 | 불변 조건 |
|---|---|---|---|
| 고정 정의 | 검증된 지도·구역·연결·후보 정의와 콘텐츠 버전 | 모든 방문이 참조하는 변경 불가 정의 | 방 ID·용도·입구는 시드로 교체하지 않음. 공개 지도와 비공개 후보를 구분 |
| 영구 진행 | 마지막으로 저장 성공한 원본 보관/등록, 최초 완료, 구역 변화·이전 관찰 | 다음 방문 입력의 복사본 | 생성 함수가 원본 상태를 수정하지 않음. 등록·소실 완료를 새 시드로 취소하지 않음 |
| 방문 계획 | 고정 정의 + 영구 진행 복사본 + 시드 + 생성 규칙 버전 | 후보 제외 후 선택된 배치·위험·접근 상태의 계획, 한 출정에 고정 | 계산만으로 보상/등록/연구/저장 변경 없음. 외부가 반환값을 바꿔도 내부 정의에 영향 없음 |
| 방문 실행 | 고정된 계획 + 플레이 행동 | 임시 획득·소비·현재 위험·실제 문/통로·지도 관찰, 종료까지 | 지도 읽기·메뉴·프레임 수가 배치를 다시 추첨하지 않음. 소비 대상을 같은 방문에서 재생성하지 않음 |
| 결과 확정 | 잠긴 귀환/실패 결과 + 거점·영구 상태 복사본 | 저장 성공한 다음 거점 상태 또는 재시도 가능한 실패 | 같은 출정의 보상·원본·변화가 한 번만 반영. 저장 실패는 이전 상태를 보존 |

구역의 **실제 상태**, 지난 방문에서 **알았던 정보**, 이번 방문에서 **확인한 정보**를 분리한다. 과거에 열린 통로였다는 기록이 이번에도 통행 가능함을 보장하지 않는다. 생성기가 숨은 위치를 알고 있어도 관찰 없이 공개 지도나 단서에 위치·보상을 표시하지 않는다. 최초 개방 이벤트 완료와 이번 문이 열려 있는지도 별개다.

영구 진행 입력에는 생성 후보에 영향을 주는 기존 개선 보유도 포함한다. 개선 발견은 원본 등록과 다른 책임이며, 원본 제외 집합에 섞거나 이미 보유한 개선에 새 보상을 부여하지 않는다. DEC-112의 구매/무료 발견 방식과 기존 안전 귀환 정산을 보존한다.

## 제안: 재현에 필요한 입력

재현 단위는 **시드 + 고정 콘텐츠/후보 버전 + 생성 규칙 버전 + 생성 직전 영구 진행**이다. 시드 숫자 하나만으로 모든 과거 방문을 재현한다고 약속하지 않는다. 원본 보관/등록·소실 상태가 바뀌면 같은 시드라도 후보가 달라지는 것이 정상이다.

- 후보를 안정적 ID 순서로 정규화하고 중복 ID·잘못된 구역/통로 참조를 먼저 거절한다. 표시 이름·사전 순회 순서·장면 자식 순서에 의존하지 않는다.
- 생성 전용 난수 흐름을 사용하고 구역·변화 종류별로 분리하는 안을 권한다. UI·효과음·AI의 난수 사용이 배치를 바꾸지 않게 한다. 정확한 난수 알고리즘·정수 표현·하위 시드 계산은 DEV-0502에서 선택·기록하고 고정 입력의 기대 결과로 검사한다.
- 콘텐츠 버전은 지도·후보 의미의 호환성, 생성 규칙 버전은 같은 입력을 결과로 바꾸는 규칙의 호환성이다. 저장 스키마는 직렬화 형식이다. 세 책임을 구분하되 새 키·버전 값은 저장 연결 작업에서 정한다. 현재 `CONTENT_VERSION`을 근거 없이 변경하거나 별도 호환성을 이미 지원한다고 주장하지 않는다.
- 기록에는 사용한 시드·버전, 생성 직전 진행의 내용 또는 복원 가능한 검사용 스냅샷, 선택 결과를 대조할 요약이 필요하다. 해시만 남기면 같음은 비교해도 과거 상태는 복원할 수 없다. 오류 재현용 자료는 플레이어의 중간 저장 기능과 구별한다.
- 재현 보장은 우선 방문 시작의 선택 결과에 한정한다. 실제 이동·충돌·AI·시간까지 동일한 플레이를 재현하려면 입력/이벤트 기록이 추가로 필요하며 이번 계약에 포함하지 않는다.
- 다른 시드가 언제나 다른 결과를 내야 하는 것은 아니다. 여러 후보가 있는 시험에서 변화 가능성을 검증하되 결과 충돌을 오류로 처리하지 않는다.

## 제안: 후보 선택 순서와 제외 규칙

1. 정의의 ID·참조·위치·필수 입구 연결과 버전 호환을 확인한다. 실패하면 부분 계획을 게임에 적용하지 않는다.
2. 영구 소실·영구 봉쇄 구역의 내부 배치와 접근 후보를 제거한다. 일시적인 문 상태와 혼동하지 않는다. 상호작용 감소는 해당 콘텐츠가 지정한 대상만 제외하며 구역 전체 소실로 추측하지 않는다.
3. 등록 완료 원본과 거점 보관 원본의 합집합을 제외한다. 같은 원본이 여러 후보 위치에 있어도 한 방문에서 최대 한 개만 선택한다. 임시 발견·감정만으로 다음 방문의 영구 제외 집합을 늘리지 않는다.
4. 나머지를 구역의 의미와 허용 위치 안에서 선택한다. 같은 위치 충돌·정원 초과·후보 중복을 검증하고, 선정 후에도 소실 구역/완료 원본이 없는지 검사한다. 후보 부족을 보상 복제나 무한 재추첨으로 보충하지 않는다.
5. 숨은 구역의 단서가 실제 접근 조건과 모순되지 않는지 확인하고, 입구/필수 이동과 상호작용 가능성을 확인한 계획만 공개한다. 단서를 모든 구역의 공통 열쇠로 확정하지 않는다.

후보가 없는 선택 항목은 비워 둘 수 있지만 필수 입구·필수 진행 연결이 성립하지 않으면 생성 실패로 반환한다. 실패 시 출정을 시작하지 않고 기존 예약 복구 경로로 돌아가는 안이다. 구체적인 필수 경로·수량·가중치와 일반 지형 도달성 알고리즘은 해당 구현/콘텐츠 작업에서 검증한다. 작은 시험 지형 검사로 모든 지형 안전성을 보장하지 않는다.

## 제안: 확정·중단·재시도 경계

| 시점·입력 | 출력·확정 조건 | 저장 실패·중단·중복 처리 |
|---|---|---|
| 출정 검토/취소 | 준비 상태만 확인, 확정된 영구 진행 유지 | 내구0 주의 안내 취소 등으로 소비·시드 소비·저장하지 않음 |
| 예약 전 계획 작성 | 같은 생성 입력에서 완전한 계획 또는 오류 | 계산 실패는 준비/돈/원본 변경 없음. 일부 대상부터 활성화하지 않음 |
| 예약 저장 | 기존 도구 예약과 방문 식별·재현 자료를 함께 저장하는 안 | 저장 실패 시 이전 거점 유지. 같은 요청 재시도에서 계획을 몰래 재추첨하지 않음 |
| 초기화와 시작 저장 | 계획 적용·초기화 검증, 시작 저장 성공 후 입력/위험 활성화 | `reserved`의 기술 실패는 기존 복구 경로. 복구 저장 실패 중 다른 거래/출정 잠금 유지 |
| 안전 귀환·부분 성공·지원되는 비상 귀환 | 잠긴 회수 결과에서 거점 보관·수입·변화 후보를 계산, 정산 저장 성공 후 확정 | 결과 화면만으로 영구 획득/변화가 확정되지는 않음. 저장 재시도에서 보상/원본/시드를 추가 생성하지 않음 |
| 행동 불능 등 실패 | 임시 회수품 상실, 기존 거점/등록 진행 유지 | 실패한 원본은 다음 후보에 남음. 실패 전에 등록·소실을 확정하지 않음. 손상/도구 처리는 현재 정산 규칙 유지 |
| 등록 | 실제 거점 원본의 등록 저장 성공 시 연구 해금, 해당 콘텐츠가 정한 다음 방문 변화 예약 | 보관만으로 연구를 열거나 모든 방을 닫지 않음. 등록 재시도에 변화 중복 예약 금지 |
| 시작 전 중단 후 이어하기 | 저장된 `reserved`를 기존 방식으로 복구한 거점 | 같은 예약 반환을 두 번 적용하지 않음. 미시작 방문에 보상/방 변화 없음 |
| 시작 후·정산 저장 전 중단 후 이어하기 | 저장된 `started`를 기존 방식으로 정리한 거점 | 임시 획득·관찰·미저장 결과는 복구된 사실로 취급하지 않음. 일반 실패 손상을 새로 부과하지 않음 |
| 정산/등록 저장 성공 직후 종료 | 파일에 성공한 상태로 이어하기 | 이전 결과 콜백·버튼으로 재보상/재등록하지 않음. 같은 출정 처리 여부를 저장 상태와 대조 |
| 다음 정식 출정 | 최신 확정 진행으로 새 계획 생성 | 앞선 방문과 시드가 다르더라도 방 정체성·원본 제외·누적 소실은 보존 |

**시드 예약 정책 제안:** 한 출정 요청과 그 저장 재시도는 같은 계획을 사용한다. 시작 전 예약 취소/복구 후 다시 정식 출정을 요청할 때 이전 시드를 재사용할지는 아직 제품 정책으로 정하지 않는다. 이 선택과 연속 방문 시드 발급·소비 시점은 저장 연결 작업 전에 명시한다. 게임 밖의 디버그 재현과 플레이어의 재추첨 수단을 혼동하지 않는다.

**지도 보존 제안:** 안전 귀환 정산 저장 때 확인한 정보의 누적을 반영하되 이전 관찰임을 구분한다. 실패/중단 때 새 지도 정보를 보존할지는 미확정으로 남기고 관련 구현 전에 선택한다. 현재 시제품은 모두 방문 내 메모리이므로 이 제안을 이미 저장하는 규칙으로 읽지 않는다.

**방 변화 제안:** confirmed 기준대로 안전 귀환·등록 완료 이후 다음 방문 변화로 연결한다. 보관 중인 원본의 중복 제외와 방 변화는 별개다. 어느 물품/구역에 소실·봉쇄·상호작용 감소를 적용할지와 기존 등록 저장에 소급 적용할지는 후속 결정 사항이며 이번에 매핑을 만들지 않는다. 최초 NPC 반응·스토리 이벤트도 실제 정의와 완료 근거 없이 자동 완료 처리하지 않는다.

## 제안: 저장 호환과 실패 검증

현재 스키마10·거점15필드 및 `g2_prototype_1`은 유지한다. 다음 저장 연결 작업에서는 아래를 함께 다룬다.

- 기존 저장에서 이미 보관/등록한 원본은 계속 제외한다. 새 방 변화·지도 관찰·최초 사건이 없다는 이유로 미획득 원본을 완료 처리하거나 과거 발견을 만들어 넣지 않는다.
- 구형1~9의 기존 전환과 현재10을 각각 검사한다. 새 필드의 기본값·필수 여부·전환 순서와 저장 버전은 그 작업에서 기록한다. 빠진 필드의 묵시적 보완으로 손상 파일을 정상화하지 않는다.
- 알 수 없는 필수 버전·안정적 ID·불가능한 상태 조합, 중복 원본, 다른 콘텐츠의 구역 참조는 거절하고 원본 파일을 덮어쓰지 않는다. 이름 변경과 ID 삭제는 다르게 취급한다.
- 돈·도구·원본·방 변화·방문 처리 완료를 한 후보 상태로 검사한 뒤 저장한다. 파일 쓰기/교체 실패는 메모리에만 새 진행을 확정하는 경로를 만들지 않는다.
- 저장 재시도, 파일 교체 전후 종료, 새 프로세스 복원에서 한 번만 반영됨을 검사한다. 현재 임시 파일 교체 구현만으로 모든 운영체제/저장 매체의 전원 장애 복구를 보장하지 않는다. 백업·복구 UI 등 일반 사용자 저장 복구는 G6 책임이다.
- 탐험 도중 자유 저장/불러오기와 중간 방문 재개는 추가하지 않는다. 시작 기록은 거점 복구·중복 방지·재현 책임이다.

## 다음 구현 한 작업과 이후 책임

다음 권고는 **DEV-0502 — 반복 탐험 상태·시드 기반 구현**이다. confirmed 상태 계층·원본성·후보 제외를 기준으로, 기존 시제품 ID와 검사용 후보를 사용한 **메모리 내 상태/생성 기반과 자동 검사**에 한정한다. 생성 전용 난수/정규화·버전·복사 경계를 구체화하고 위 DEV-0502 사례를 검사한다. 사용자가 검토한 DEV-0501을 승인 커밋으로 분리하고 다음 진행을 지시한 뒤 착수한다.
