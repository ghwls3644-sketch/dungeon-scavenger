# 회수세 최소 규칙 검토안

## 상태와 승인 경계

DEV-0420 제안 이력과 [DEV-0421 시험 적용](#dev-0421-회수세-시험-적용)을 함께 관리하는 draft다. **현재 구현은 아래 DEV-0421 적용 절을 따른다.** 기존 절의 미적용·후속 표현과 스키마 8은 DEV-0420 당시 상태다. confirmed [경제 규칙](economy_rules.md#회수세의-과세-대상), [GDD 10-4](../GDD.md#10-4-가격과-거래)·DEC-116을 함께 읽고 이 draft를 단독 기준으로 사용하지 않는다.

2026-10-10 사용자는 판매액 40+의뢰 보상 10, 비교 세율 10%의 질문에서 **판매 대금에만 부과하고 의뢰 보상은 전액 지급**하는 안을 선택했다. 귀환 자동 판매와 거점 보관품 판매에 같은 과세 기준을 적용한다([DEC-116](../project/decisions.md#dev-0420-회수세-과세-대상-선택)). [MIG-CHG-052](../project/migration_changes.md#mig-chg-052-dev-0420-회수세-최소-규칙-정리)에 먼저 기록했다.

승인은 과세 대상의 방향이다. 아래 **10%·판매 거래별 합산 후 소수점 버림·별도 최소 세액 없음은 미적용 시험 제안**이며 사용자 승인이나 최종 밸런스가 아니다. 구체적인 징수 시점·UI·저장 전환은 후속 구현 착수 때 confirmed 규칙·DEC-116과 재대조하고 시험 범위를 먼저 기록한다. 남은 판단은 [Q-029](../project/open_questions.md#회수세-검토-경계)가 소유한다. 문서 완성과 회수세 기능 완료, G4 전체 완료를 구분한다.

## 과세 대상 비교와 채택

판매 40+의뢰 보상 10, 세율 10%는 차이를 보이기 위한 예다.

| 안 | 과세 대상 | 회수세 | 지갑 입금 | 판단 |
|---|---:|---:|---:|---|
| 판매 대금만 | 40 | 4 | 46 | 사용자 채택. 판매와 의뢰 보상 표시를 분리하고 보상 10은 전액 지급 |
| 판매 대금+의뢰 화폐 보상 | 50 | 5 | 45 | 미채택. 표시 보상과 실제 추가 수령액이 달라짐 |

세금은 감정료·수리비를 공제하기 전 **판매 대금**을 기준으로 하는 시험안을 제안한다. 순이익에 세금을 매기는 안은 과세 대상을 소모 원가와 혼합하고 구형 원가 미기록 물품의 거래를 막을 수 있어 채택 방향의 첫 시험에서 제외한다. 거래처 우대/난이도별 요율은 최종 밸런스 후속이며 새 면허·평판·세금 채무를 만들지 않는다.

## 판매와 징수 시점 제안

| 사건 | 세금 처리 제안 | 중복/손실 방지 |
|---|---|---|
| 일반 또는 기존 비상 안전 귀환의 자동 판매 | 실제 판매 가능한 물품의 합계에서 계산, 정산 저장 때 함께 확정 | 탐험 중 줍기·진척·결과 미리보기에 징수하지 않음 |
| 거점 보관품 판매 | 사용자가 확정한 이번 판매 묶음에서 계산, 판매 저장 때 함께 확정 | 미판매로 보관하던 기간에는 부과하지 않음. 판매된 물품은 제거하여 재판매/재징수 거절 |
| 의뢰 보상 | DEC-116에 따라 과세 대상 제외, 지급 조건은 DEC-115 유지 | 판매 실적과 보상 양쪽에 같은 회수품 세금을 중복 부과하지 않음 |
| 미확인·보호·가격 미설정·판매 미선택 물품 | 실제 판매가 없으므로 회수세 없음 | 가상 감정가로 돈을 차감하거나 보호 해제하지 않음. 나중에 정상 판매하면 그 거래에서만 부과 |
| 빈손 안전 귀환·실패·시작 후 미정산 종료 | 이번 판매액 0이면 이번 회수세 0 | 벌금/정액 최소 세금·기존 보유금 추가 차감 없음. 실패 전에 완료한 거점 판매의 세금은 해당 기간에 남음 |
| 감정·수리·등록/연구·개선·무료 보급·예약 반환 | 회수품 판매와 구분 | 다른 서비스 비용이나 무료 발견 가치를 회수품 판매액으로 바꾸지 않음 |

귀환 정산으로 새 보고 기간이 열린 뒤 보관품을 감정/판매하면 **그 이후 기간**의 거점 판매와 세금으로 기록한다. 원래 물품을 주운 출정의 완료 보고서를 수정하지 않는다. 기존 자동 판매품은 보관되지 않으며, 보관품 판매는 그때 처음 생기는 실제 판매다. 이전 세금이 없는 물품에 임의의 납세 표시를 붙여 거래를 면제하지 않는다.

## 합산과 반올림 비교

다음 7·14는 경계 계산용 가격이며 현재 품목가나 새 콘텐츠를 바꾸는 값이 아니다. 세율은 비교용 10%다.

| 단위 | 가격 7 두 개를 한 번에 판매 | 7씩 두 번 판매 | 영향 |
|---|---:|---:|---|
| 물품마다 버린 뒤 합산 | 0+0=0 | 0+0=0 | 같은 판매 합계라도 물품 분할에 따라 세금이 크게 줄어듦 |
| 판매 거래별 총액에서 버림 — 첫 시험 제안 | floor(14×0.1)=1 | 0+0=0 | 이번 화면과 입금이 바로 맞음. 여러 거래로 쪼개면 절사 차이가 생김 |
| 기간 누계의 목표 세액에서 이미 낸 세액을 차감 | 1 | 첫 0, 둘째 1 | 기간 안에서는 분할 차이를 없애지만 이전 거래/기간 종료에 따라 같은 판매의 세금이 달라짐 |
| 소수 세액을 다음 거래·기간으로 이월 | 1, 나머지 0.4 | 첫 0, 둘째 1, 나머지 0.4 | 장기 분할 차이를 줄이지만 잔여 세액·요율 변경·이월 저장 규칙이 필요 |

첫 구현의 제한된 시험 후보는 **귀환 정산 1회 또는 거점 판매 확정 1회**를 한 거래로 보고 판매액을 합산한 뒤 한 번 버리는 방식이다. 출정 전체 기간에 다시 합산하여 세금을 재계산하지 않는다. 최근 보고서에는 각 거래에서 확정한 세금의 합계를 표시한다. 위 예에서 두 번 팔아 낸 세금 0을 보고서에서 총액 14의 세금 1로 바꾸면 지갑과 어긋난다.

일반 반올림을 쓰면 7 한 건이 1, 7 두 건 합계 14는 1이어서 역시 단위에 따라 차이가 난다. 자동 보정·올림·최소 1·숨은 이월은 넣지 않는 시험안이다. 거래 분할로 줄어드는 세액은 명시적인 한계로 Q-029에 남기고, 최종 경제 검토에서 거래별 절사 유지 또는 이월 방식을 판단한다.

정수 계산은 부동소수점 변환 없이 처리한다. 예를 들어 분모 100·정수 비율 r(0~100)의 시험 범위에서는:

    회수세 = (판매액 // 100) × r + ((판매액 % 100) × r) // 100
    이번 정산 입금 = 이번 판매액 - 이번 회수세 + 의뢰 보상
    거점 판매 입금 = 이번 보관품 판매액 - 이번 회수세

10%는 r=10인 비교값이다. 명시적 r=0은 경계 검사용 무과세이며 누락된 정책과 다르다. r=100은 경계 검사만 하고 최종 요율로 제안하지 않는다. 음수·비정수·분모 0·범위 밖 비율과 int64 범위를 넘는 판매/보상/보고 합계는 후보 전체를 거절한다. 판매액×r을 먼저 계산해서 오버플로한 뒤 나누지 않는다. 순액이 작더라도 표시할 세전 합계가 int64를 넘으면 현재 보고의 표현 범위에 맞춰 거절한다.

## 손익과 현금 표시 제안

[DEC-114의 비용 표시](expedition_cost_reporting.md)를 유지한다. 아래 계산의 기간은 직전 정산 이후 거점 준비부터 이번 정산까지이며, 회수세는 해당 기간에 **실제로 확정한 판매 거래의 세금 합계**다.

    기간 수입 = 이번 회수품 판매 + 기간의 거점 보관품 판매 + 의뢰 보상
    운영 비용 = 실제 감정료 + 실제 수리비 + 사용/소실한 유료 도구 원가 + 회수세
    준비·탐험 손익 = 기간 수입 - 운영 비용
    현금 변화 = 기간 수입 - 실제 감정료 - 실제 수리비 - 회수세
               - 새 유료 도구 구매액 - 영구 개선 구매액
    정산 후 보유금 = 기간 시작 보유금 + 현금 변화

세후 입금만 수입에 넣은 뒤 비용에서 세금을 또 빼지 않는다. 과거 거점 세금을 이번 정산 입금에서 다시 차감하지 않는다. 모든 재고 원가가 기록되어 있으면 기존 등식 **손익 - 현금 변화 = 영구 개선 구매액 + 기말 유료 재고 원가 - 기초 유료 재고 원가**가 그대로 성립해야 한다. 원가 미기록은 기존 정확한 손익 보류를 유지하되, 판매/세금/실제 현금은 확정된 값으로 표시한다.

| 화면 | 필요한 최소 정보 |
|---|---|
| 거점 판매 견적 | 판매 총액·회수세·실제 받을 금액·판매 뒤 보유금. 확정 전 요율/대상/상태가 바뀌면 새 견적으로 다시 확인 |
| 정산 전 결과 | 이번 판매 총액·전액 지급하는 의뢰 보상·이번 회수세·이번 정산 입금. 아직 저장 전임을 구분 |
| 큰 손익과 최근 보고 | 세전 수입·실제 낸 회수세·다른 운영 비용·손익, 별도 현금 변화/보유금. 거점과 귀환 세금의 범위를 구별 |
| 미판매·구형·오류 | 미판매 이유, 세금 도입 전 기록/전환 후 기록 범위, 원가 미기록, 저장 실패·재시도. 정식 문구와 화면 배치는 후속 |

## 저장과 구형 보고 계약

저장 필드명·스키마 번호는 이번에 만들지 않는다. 아래 필요한 정보와 불변 조건을 후속 작업에서 구체화한다.

- **판매 거래의 후보**는 판매 원본/수량·가격·적용 정책/요율·세전 금액·세금·입금액·보유금을 서로 대조한다. 판매 저장 성공 전에는 물품 제거, 지갑과 기간 세금을 어느 하나도 확정하지 않는다.
- **귀환 정산의 후보**는 판매·보관품·의뢰 보상·이번 세금·도구 반환/원가·장비 손상·발견 개선·의뢰 초기화·최근 보고·다음 기간을 함께 저장한다. 실패하면 기존 상태와 재시도 가능한 결과를 유지한다. 같은 출정 ID로 정산을 재요청해도 한 번만 지급/징수한다.
- 성공 뒤 결과 화면 재개·최근 보고 열기·새 프로세스 이어하기는 이미 확정된 값을 읽는다. 세금을 다시 결제하거나 현재 요율로 과거 세금을 다시 평가하지 않는다. 판매 성공 뒤 이전 견적 재사용도 거절한다.
- 견적 작성 뒤 정책·가격·판매 원본·잔액이 바뀌면 이전 승인을 새 금액에 재사용하지 않는다. 정산 미리보기도 바뀐 금액을 다시 보여준 후 확정한다. 저장 중 오류/재시도와 불확실한 완료는 기존 저장 복구 경계에 따라 중복 없이 처리한다.
- **구형 스키마 1~8**은 현재 구현에서 세금을 걷지 않았던 기록이다. 마지막 보고의 실제 세금은 0·도입 전 기록으로 읽기 보완하고 기존 지갑/판매/보상/손익을 보존한다. 당시 세율이 0%였다고 발명하거나 현재 요율로 소급 징수하지 않는다.
- 구형 열린 기간은 기존 거래 합계와 실제 잔액을 유지하고, 전환 뒤 새 판매만 과세 기록에 넣는다. 과거 수입을 포함한 기간 총액에 세율을 곱해 검증하면 T09처럼 잘못된 소급 세금이 생긴다. 구형 원가 미기록·partial 범위도 유지한다.
- 구형 예약은 기존 반환, 시작한 채 종료된 기록은 기존 실패 복구를 따른다. 실제 새 판매가 없으면 새 세금도 없고 기존 돈에 벌금을 만들지 않는다. 읽기만으로 저장 파일을 쓰지 않으며 정상 후보 저장 성공 때만 새 형식으로 전환한다.
- 새 형식에서 세금 정보가 빠지거나 잘못되면 구형으로 추측해 세금 0으로 고치지 않는다. 미래 버전·손상 기록은 기존 오류 경로를 따른다. 금액은 현재처럼 int64 범위의 정확한 정수/문자열 계약을 유지한다.
- 최근 보고는 확정한 거래별 세금의 합과 구형 무과세 범위를 재현할 수 있어야 한다. 여러 거래의 버림 결과를 합계 한 번의 버림으로 바꾸지 않는다. 필요한 거래 근거/요약의 검증 방식과 크기 한계는 후속 스키마 검토에서 결정하며 영구 전체 거래 이력은 이번 범위로 요구하지 않는다.

## DEV-0421 회수세 시험 적용

2026-10-10 사용자 다음 작업 요청 뒤 MIG-CHG-053에 범위를 먼저 기록했다. confirmed 경제·아이템·반복 탐험과 DEC-116을 기준으로 **명시적 시험 세율 10%·판매 확정 한 번의 총액에서 절사·별도 최소 세액/이월 없음**을 적용한다. 최종 밸런스 승인이나 Q-029 해결을 뜻하지 않는다. 판매 7+7을 나누면 세금 0, 한 번에 14면 1인 차이를 유지한다.

- 공통 [RecoveryTax](../../src/meta/recovery_tax.gd)가 int64 금액을 나누어 곱하는 방식으로 넘침 없이 계산한다. 누락 정책은 -1로 거절하며 명시적 0%와 구분한다. 시험 유효 범위는 정수 0~100%다. 미판매·보호·미확인·가격 미설정·실패에는 판매 세금을 만들지 않는다. 정상/기존 비상 안전 귀환 모두 의뢰 보상을 전액 지급한다.
- SaleQuote/SettlementResult는 판매 총액·적용 요율·세금·실제 입금을 고정한다. 거점 판매는 후보 재대조, 정산은 가격 목록/요율 변경 시 미리보기 갱신 후 재확인을 요구한다. 새로 가격이 설정된 보관 대상도 갱신한다. 판매/정산 후보 저장 성공 후 지갑·물품·세금·보상·보고를 함께 바꾸며 중복 처리하지 않는다.
- 비용 보고의 수입은 세전 판매+의뢰 보상이며 실제 낸 회수세를 운영 비용과 현금 변화에서 한 번 뺀다. 지갑 입금은 이번 판매-이번 세금+보상이다. 이미 거점에서 낸 세금을 다시 빼지 않는다. T01~T09를 실제 도메인으로 실행해 위 표와 일치했다. 손익과 현금 변화의 재고/투자 등식, 원가 미기록의 손익 보류를 유지한다.
- 스키마 9는 거점 13필드를 유지한다. costs.period에 tax_sales와 tax_legacy_income을, 마지막 보고에 loot_tax를 추가한다. 각 거래는 gross/paid 십진 정수 문자열과 rate 정수의 정확한 3필드다. 거점 합계는 거래별 실제 세금의 합으로 검증한다. 현재 기간과 최근 보고만 보존하며 기존 파일 16 MiB 한도를 유지한다.
- 구형 1~8은 원래 필드 모양을 확인한 뒤 도입 전 판매를 별도로 보완한다. 기존 최근 귀환의 rate=-1/paid=0은 당시 세율을 추측하지 않는 표식이며 새 거래에는 허용하지 않는다. 기존 돈/보상/보고·예약 반환·시작 후 실패 복구를 유지하고 읽기만으로 원본을 쓰지 않는다. 신형 누락/손상·구형에 신형 필드 혼합·미지원 버전은 거절한다.
- 견적에 세율·판매 총액·세금·실제 입금/보유금을, 결과와 최근 보고에는 세금 범위·의뢰 보상 전액 지급·이번 정산 입금·도입 전 판매를 표시한다. 긴 금액/음수/원가 미기록과 오류 재시도·스크롤/확정을 두 해상도에서 검사했다.

검사 근거는 [DEV-0421 기록](../project/project_context.md#dev-0421-회수세-정산보고-연결-검사)과 [자동 검사 JSON](../project/dev0421_automated_results.json)이다. 구형 혼합 기간·현재 거래 기록의 검증과 크기 한도는 이번 시험 계약으로 구체화했으나 장기 성능/정식 표시·최종 절사·요율·생계 압박과 사람 이해는 Q-029에 남긴다. 휴대용 감정은 다음 별도 작업이며 G4 전체 완료는 보류한다.
