# 거점 목표·의뢰 규칙 검토안

## 상태와 범위

DEV-0417의 제안 이력과 DEV-0418의 제한된 시험 적용을 함께 관리하는 `draft`다. **현재 구현은 [DEV-0418 선택 의뢰 시험 적용](#dev-0418-선택-의뢰-시험-적용)**을 따른다. 아래 기존 제안 절은 DEV-0417 당시 상태이며 “미적용”·스키마 7은 당시 설명이다. `draft` 문서를 단독 구현 기준으로 사용하지 않는다. GDD와 confirmed 상세 규칙, 사용자 결정과 다음 구현 작업의 시험 범위를 함께 읽는다.

사용자는 **자유 수색+선택 의뢰 1개·추가 보상**을 선택했다([DEC-115](../project/decisions.md#dev-0417-거점-목표의뢰-방식-선택)). 의뢰 없이 출정할 수 있고 미달성해도 기존 회수품 정산을 유지하는 방향을 채택했다. 아래 수량/보상·실적 판정·반복/저장은 이를 구체화하는 미적용 제안이며 답변으로 세부 정책까지 확정하지 않는다. [Q-028](../project/open_questions.md#거점-목표의뢰-검토-경계)에 미정 범위를 둔다. 2026-10-09 사용자가 검토된 문서 결과의 로컬 커밋을 승인했다. 세부 시험안의 최종 정책 승인과는 구분한다.

## 현재 기준과 구현

| 기준 | 유지할 요구 | 현재 구현과 남은 부분 |
|---|---|---|
| [GDD 4-2·4-3](../GDD.md#4-2-한-런의-흐름) | 출정 전 목표 구역 또는 의뢰 확인, 귀환 정산. 목표를 놓쳐도 회수품과 정보는 정상 정산 | [거점 화면](../../src/ui/hub_panel.tscn)에 `목적지: 시험 구역` 안내만 있고 선택/진척/의뢰 정산은 없음 |
| [길드 역할](../story/04_characters_and_factions.md#길드-관리자)·[사회적 위치](../story/03_player_and_society.md#수색꾼-길드) | 행정 NPC가 허가·의뢰·등록으로 목표를 구조화. 길드 자체는 깊게 등장하지 않아도 됨 | 메뉴형 거점에 최소 목표 기능을 둘 수 있음. 새 NPC 이름·조직명·허가 아이템·평판 계산이 필수라는 뜻은 아님 |
| [경제 규칙](economy_rules.md#정산과-순이익) | 판매액과 화폐 의뢰 보상을 구분하고 총 수입에 한 번 포함 | [SettlementResult](../../src/meta/settlement_result.gd)·[ExpeditionCosts](../../src/meta/expedition_costs.gd)는 현재 회수품 판매·보관품 판매만 수입으로 연결. 보상 표시만 추가해서는 지갑/손익/저장 관계가 맞지 않음 |
| [물품 보호](item_rules.md#판매폐기-보호) | 고유 유물·핵심 기록물·보호 의뢰품의 판매/빠른 버리기 방지 | 일반 물품의 회수 실적을 세는 안과 특정 물건의 납품/보호를 요구하는 안은 구분해야 함 |
| [실패·저장](repeat_exploration.md#귀환과-실패) | 미확보 회수품 손실, 기존 돈/거점/연구 유지, 탐험 중 자유 저장 없음 | [HubState](../../src/meta/hub_state.gd)의 출정 예약·시작·정산/복구 원자성에 목표 선택/완료를 함께 연결해야 함 |

선택 목표를 넣는 것과 G4 전체 완료는 별개다. 경제의 다른 미구현 범위, 사람 평가와 G5/G7 콘텐츠 책임은 [G4 검토](../project/g4_meta_review.md)에 남는다.

## 비교한 세 방향

| 방향 | 플레이어가 하는 일 | 장점과 부담 |
|---|---|---|
| 자유 수색+선택 의뢰 1개·추가 보상 — 채택 | 자유 출정하거나, 회수 조건/보상을 보고 한 의뢰 선택. 귀환 정산에서 달성 여부와 추가 보상 확인 | 길드 목표와 정산을 작게 검증할 수 있음. 보상 경제·중복 지급·출정별 저장 검사가 필요 |
| 보상 없는 개인 수색 목표 — 미채택 | 이번에 노릴 회수 목표만 선택하고 결과 확인 | 현금 경제를 늘리지 않음. 길드의 의뢰/보상 기능을 구현한 것으로 볼 수는 없음 |
| 목표 안내만 유지·의뢰 후속 — 미채택 | 현재 목적지와 안내만 확인하고 출정 | 현재 흐름 유지. DEV-0416의 최소 의뢰 공백이 해결된 것은 아니므로 보완 시점/범위를 별도 결정해야 함 |

어느 방향이든 목표 미달성만으로 생환을 실패로 바꾸거나 정상 판매·원본 등록을 막지 않는다. DEC-112의 직접 구매+무료 발견을 의뢰 선행 조건으로 바꾸지 않는다. 의뢰 보상에 허가/평판/새 하네스 해금을 함께 붙이는 안은 이번 최소 범위에서 제외한다.

## 채택한 방향의 첫 시험 제안

다음 값과 정책은 채택한 방향을 구체화하는 **구현 검토용 제안**이다. 아직 실행에 적용하지 않았으며 최종 밸런스나 세부 정책의 일괄 승인이 아니다. 후속 DEV-0418에서 confirmed 규칙·DEC-115와 대조하고 시험 적용 범위를 먼저 기록한다.

| 항목 | 제한된 제안 |
|---|---|
| 종류/동시 수락 | 기존 시험 구역의 회수 실적 의뢰 한 종류, 한 출정에 최대 하나. 선택하지 않고 출정 가능 |
| 조건 | 이번 출정에서 가져온, 분류가 확인된 일반 폐품 2개 이상을 안전 귀환 정산에 포함 |
| 대상 제외 | 미확인 물품·잔재·원본·보호 물품·하네스 발견·휴대 도구·과거 거점 보관품. 감정 전 실제 분류로 진척을 올리지 않음 |
| 추가 보상 | 시험 금액 10. 같은 출정에서 조건을 넘겨도 한 번만 지급. 판매액과 별도 항목으로 표시 |
| 물품 처리 | 납품/소비 의뢰가 아니라 회수 실적 확인이다. 대상 일반 폐품은 기존 규칙대로 정산 판매하고 보너스를 별도로 받음. 물품을 의뢰품으로 잠그거나 중복 생성하지 않음 |
| 비용/손실 | 수락 비용·보증금·미달성 벌금·평판 손실 없음. 목표 미달성의 안전 귀환은 기존 정산 유지. 실제 출정 실패/종료의 기존 손실은 유지 |
| 반복 | 매 출정 같은 시험 의뢰를 선택 가능. 완료/실패/시작 후 종료 뒤 선택과 진척을 초기화해 자유 수색으로 복귀. 자동 재수락·연속 보상·일일 갱신은 넣지 않음 |
| 등록/성장 | 원본 등록이나 영구 개선을 조건 또는 보상으로 쓰지 않음. 보상금은 다른 보유금과 같은 기존 구매에 쓸 수 있음 |

수량 2와 금액 10은 기존 [가벼운 폐품](../../src/data/prototype_light.tres)·[무거운 폐품](../../src/data/prototype_heavy.tres)의 두 물품을 함께 들고 돌아오는 경우를 비교하기 위한 값이다. 슬롯·무게의 최종 수치를 확정하지 않는다. 정식 의뢰 명칭/문구·종류·구역 조건·반복 보상 경제는 후속 검토이며 NPC의 새로운 지식이나 사건을 만들지 않는다.

이 안은 **특정 의뢰품을 납품하는 기능을 구현하지 않는다.** 향후 납품 의뢰를 추가한다면 보호 부여/해제·제출 소비·판매 제외·귀환/실패·중복 제출을 먼저 설계해야 한다. 일반 폐품 실적 보너스를 근거로 confirmed 의뢰품 보호 규칙을 완화하지 않는다.

## 선택·진척·결과 계약 제안

| 시점 | 처리 |
|---|---|
| 거점 준비 | 자유 수색 또는 의뢰를 선택. 조건/보상/미달성 처리 확인 후 후보 저장에 성공해야 선택 변경. 취소·저장 실패·중복 확인은 원래 선택 유지 |
| 출정 예약 | 선택한 의뢰와 조건/보상 버전을 출정 ID에 묶어 고정. 예약 뒤 거점 선택이나 데이터 가격 변경으로 같은 출정의 약속을 바꾸지 않음 |
| 시작 전 기술 복구 | 예약 취소·기존 유인물 반환과 같은 후보에 연결. 의뢰 선택은 출정 전 준비 상태로 유지하고 보상/완료는 만들지 않음 |
| 탐험 | 현재 가방의 자격 있는 일반 폐품 수를 진척으로 표시. 회수 2개 뒤 1개를 버리면 1개로 내려감. 버렸다 다시 줍기를 반복해 누적 횟수를 부풀리지 않음. 물품 이름/분류의 기존 공개 경계 유지 |
| 안전 귀환 결과 | 최종 가져온 물품으로 조건을 다시 검사. 정상 입구 귀환과 기존 회수품 유지 비상 귀환에 같은 기준 적용. 화면은 정산 예정 결과이며 아직 돈/완료를 저장하지 않음 |
| 미달성 안전 귀환 | 의뢰 추가 보상만 0. 가져온 판매품·미확인 보관품·원본/발견·손상·반환은 기존 정산 그대로. ‘의뢰 미달성’과 ‘탐험 실패’를 구분 |
| 실패 또는 시작 후 미정산 종료 | 의뢰 보상 0, 진행 이월 없음. 기존 실패 손실/중단 복구와 함께 선택을 정리. 결과 미리보기를 보았어도 정산 저장 전 종료하면 보상 미확정 |
| 정산 저장 | 판매 수입+추가 보상·내구/보관/원본/발견·도구 반환·비용 보고·목표 결과/선택 초기화·다음 기간을 한 후보로 저장. 성공 후에만 실제 상태를 교체 |
| 저장 실패/재시도 | 기존 파일·지갑·선택과 최근 결과 유지. 같은 결과를 재시도해도 성공한 한 번만 지급. 저장 직후 강제 종료→새 실행에서 이미 지급된 보상을 다시 지급하지 않음 |

전체 회수 수량은 현재 탐험 가방에서 계산하되 최종 판단은 불변 귀환 결과와 출정 예약 조건을 사용한다. UI가 직접 완료·보상이나 물품 자격을 결정하지 않는다. 제한된 목표 표시가 모든 구역/의뢰 종류를 지원하는 범용 퀘스트 체계를 뜻하지 않는다.

## 수입과 비용 표시 계약 제안

아래는 채택한 추가 보상 방향을 구현할 때 필요한 확장 제안이다. [현재 비용 시험](expedition_cost_reporting.md#dev-0415-비용-표시-시험-적용)의 계산은 아직 바뀌지 않았다.

```text
구간 수입 = 이번 회수품 판매 + 거점 보관품 판매 + 이번 의뢰 보상
소모 기준 손익 = 구간 수입 - 실제 감정/수리 지불 - 사용/소실 도구 취득 원가
현금 변화 = 구간 수입 - 실제 감정/수리 지불 - 새 도구 구매 - 영구 개선 구매
이번 정산의 지갑 반영액 = 이번 회수품 판매 + 이번 의뢰 보상
```

큰 손익을 다시 지갑에 더하지 않는다. 의뢰 보상은 운영 비용을 줄인 것처럼 표시하지 않고 독립 수입으로 기록한다. 총 수입과 판매액을 같은 필드로 부르지 않는다. 구형 원가가 미기록이면 의뢰 보상과 현금은 정확히 표시해도 큰 손익의 미기록 상태는 유지한다. 원가가 모두 알려진 경우 `손익 - 현금 변화 = 영구 개선 투자 + 기말 유료 재고 원가 - 기초 유료 재고 원가`의 기존 관계도 유지한다.

| 계산 예 | 판매 | 보상 | 소모 기준 손익 | 현금 변화 | 정산 지갑 반영 |
|---|---:|---:|---:|---:|---:|
| 자유 수색으로 폐품 둘 귀환, 다른 거래 없음 | 40 | 0 | +40 | +40 | +40 |
| 의뢰 선택 후 같은 둘 귀환 | 40 | 10 | +50 | +50 | +50 |
| 의뢰 선택·도구 2개를 10에 구입·유료 1개 사용·둘 귀환 | 40 | 10 | +45 | +40 | +50 |
| 의뢰 선택했으나 무거운 폐품 1개만 귀환 | 30 | 0 | +30 | +30 | +30 |
| 의뢰 선택·도구 구매 10 뒤 실패 | 0 | 0 | -10 | -10 | 0 |
| 의뢰 달성·수리 5·개선 구매 60·도구 구매 10·유료 1개 사용 | 40 | 10 | +40 | -25 | +50 |

보상 10은 이 제안의 숫자 예에만 사용한다. 거점 보관품 판매는 위 식의 구간 수입에 들어가지만 이번 의뢰의 회수 진척에는 들어가지 않는다. 과거 정산에 보상을 소급하거나 금액을 맞추기 위해 판매품 가격을 바꾸지 않는다.

## 저장과 책임 경계 제안

필요한 정보는 거점의 선택, 출정 ID에 묶인 조건/보상 약속, 마지막 정산의 선택/달성 결과와 실제 보상이다. 거점 선택을 기억하는 저장과 탐험 도중 자유 저장은 다르다. 탐험 중 임시 진척을 독립적인 보상 청구권으로 저장하지 않는다. 장기 의뢰 이력·누적 실적·새 재화·평판은 제외한다.

- `meta`는 자격/진척/완료·보상 계산과 거점 후보를 맡고 `data`는 제한된 정의/수치를 맡는다. `gameplay`는 현재 가방과 귀환 결과를 제공한다. `app`은 출정·정산·복구와 저장 후 상태 확정을 조정한다. `ui`는 조건/선택/진척/결과를 표시하고 명령만 보낸다.
- 저장 스키마 번호·키·실제 콘텐츠 ID는 구현 작업에서 명시한다. 현재 스키마 7·12필드를 이 문서로 바꾸지 않는다. 구형 1~7은 의뢰 없음/보상 없음으로 보완하고 과거 완료를 추측하지 않는다. 읽기만으로 원본 파일을 덮어쓰지 않는다.
- 알 수 없는 의뢰/규칙 버전·잘못된 필드/수량/금액/출정 ID·서로 맞지 않는 결과/보상은 임의 보상이나 조용한 초기화로 처리하지 않는다. 파일을 보존하고 지원하지 않는 기록임을 알린다. 유효한 구형 저장 보완과 손상 복구를 구분한다.
- 보상 포함 총액이 int64 범위를 넘으면 일부 지급·잘라내기·보상만 포기하기 없이 정산 후보 전체를 거절한다. 저장 직전/직후의 새 실행, 오래된 요청·두 번 클릭·다음 출정 뒤 이전 결과 재요청을 검사한다.

## DEV-0418 선택 의뢰 시험 적용

2026-10-09 사용자 다음 작업 지시를 받아 confirmed GDD/경제/아이템/반복 탐험, DEC-115와 Q-028을 대조하고 [MIG-CHG-050](../project/migration_changes.md#mig-chg-050-dev-0418-거점-선택-의뢰-연결)을 먼저 기록했다. DEV-0417 제안의 아래 범위를 실제 앱에 연결했다. 문서 `draft`와 Q-028 `provisional`을 유지한다.

- 거점 **목표·의뢰** 탭에서 자유 수색 또는 `폐품 회수 의뢰`를 고른다. 조건/보상/미달성 안내를 확인한 뒤 선택 적용을 눌러 저장한다. 다른 서비스·일시 정지·출정/복구 중 선택을 막고 오래된 준비 상태의 요청은 다시 확인한다. 실패하면 이전 선택과 돈을 보존하고 재시도할 수 있다.
- 시험 정의 [prototype_expedition_objective.tres](../../src/data/prototype_expedition_objective.tres)는 `prototype_scrap_recovery`, 버전 1, 필요 2개, 보상 10이다. 공식 세계관 명칭을 새로 정한 것이 아니다. 현재 가방의 확인된 비보호 일반 폐품만 세고 버리면 진척이 감소한다. 도구·미확인/잔재/원본/보호 물품·과거 거점 보관품을 실적으로 세지 않는다.
- 일반/기존 비상 안전 귀환의 실제 회수 결과로 달성을 다시 계산한다. 달성은 판매액 외 보상 10을 한 번 지급하며 미달성 생환은 보상만 0, 판매/보관/원본·개선 발견·손상·도구 반환은 기존 규칙대로다. 실패/시작 후 미정산 종료는 보상 0이다. 예약만 복구하면 선택을 유지하고 정산/시작 후 종료 복구가 저장되면 자유 수색으로 돌아간다. 매 출정 명시적으로 다시 고를 수 있고 자동 재수락은 없다.
- 스키마 **8·거점 13필드**는 `objective`를 추가한다. 선택은 `{}` 또는 `id/version/required/reward` 4필드, 마지막 비용 보고는 기존 7필드에 `objective:{offer,count}`를 더한다. count는 현재 가방 최대 3에 맞춘 0~3 정수이며 자유 수색·실패/중단은 0이다. 실제 보상은 검증한 약속·수량·귀환 상태에서 재계산한다. version/required/count는 JSON 숫자를 검증 후 정수로 정규화하고 금액은 int64 십진 문자열을 유지한다.
- 기존 출정 ID/phase가 선택 약속을 묶고 예약 후 수정을 막는다. 저장 형식에 실시간 가방 진척이나 독립 보상 청구권은 없다. 지원하지 않는 ID/버전/조건은 재가격 책정·초기화 없이 파일 보존/오류로 처리한다. 구형 1~7의 정상 기록에는 선택/과거 보상 없음을 보완하고 읽기만으로 파일을 쓰지 않는다.
- 판매 수입과 보상은 별도 항목으로 표시하며 위 숫자 예 6개의 결과를 유지한다. 모든 돈·선택 해제·최근 보고·내구/보관/등록 대상/발견·도구·다음 구간은 같은 저장 후보에서 확정한다. 저장 실패·중복 요청·종료 후 재실행에서 보상을 두 번 주지 않는다. 보상 때문에 지갑 또는 구간 수입이 int64를 넘으면 정산 전체를 거절한다. 원가 미기록은 계속 손익 계산 보류다.

## DEV-0420 회수세 문서 인계

## DEV-0422 현장 감정과 의뢰 인계

[횟수 제한 확정 감정](portable_appraisal.md#귀환실패정보-보존-제안)은 후속 구현에서 실제 가방의 미확인 일반 폐품을 의뢰 실적 대상으로 바꿀 수 있다. 기존의 확인된 비보호 일반 폐품 조건을 그대로 대조하고 버리면 실적에서 제외한다. 잔재·보호 원본·감정 도구는 실적이 아니며 감정 행동 자체로 보상을 지급하지 않는다. 보상은 안전 귀환 때 한 번 판정하고 기존 판매·판매 과세/보상 비과세를 유지한다. 이번 문서 작업은 의뢰 코드·수치·Q-028의 사람 평가를 변경하지 않는다.

## DEV-0423 현장 감정 진척 연결

실제 가방에서 확정된 비보호 일반 폐품은 진척에 들어가고 버리면 제외한다. 잔재·보호 원본·감정 도구는 실적이 아니다. 안전 귀환 정산의 보상10·폐품2개 시험 조건과 판매 과세/보상 전액 지급은 그대로다. 현재 [휴대용 감정 시험 적용](portable_appraisal.md#dev-0423-준비사용정산-시험-적용)과 [검사 기록](../project/project_context.md#dev-0423-휴대용-감정-연결-검사)을 따른다. 위 DEV-0422 인계는 당시 이력이며 최종 정책·사람 평가는 기존 질문 상태를 유지한다.
