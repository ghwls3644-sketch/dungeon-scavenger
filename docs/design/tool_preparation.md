# 휴대 도구 준비 규칙 검토안

## 상태와 범위

DEV-0412에서 작성한 **문서 검토안**에 DEV-0413 시험 적용을 덧붙였다. `draft`이며 단독 구현 기준이 아니다. DEC-113·GDD·confirmed Design과 `MIG-CHG-045`를 함께 따른다. 아래 DEV-0412의 현재 구현 대조/미적용 제안/계약은 작성 당시 이력이며, 현재 적용 범위는 다음 절이 소유한다.

첫 준비 대상은 이미 F로 사용하는 **소음 유인물** 하나다. 하네스 장착/공유 충전과 별도 횟수를 사용하며 새로운 도구 종류, 제작·재료·상인 NPC나 공식 상품명을 만들지 않는다. 전체 출정 비용 통합과 G4 완료 판정은 후속 작업이다.

## DEV-0413 준비·소비·복구 시험 적용

총 0~4개·기본 무료 최대 2개·추가 재고 최대 2개·부족분 개당 5·남은 도구 무게 0.25를 [규칙 데이터](../../src/data/prototype_lure_supply.tres)로 적용했다. 한 수량 선택에서 보유 추가분을 먼저 배정하고 부족분만 결제한다. 선택을 줄여도 구입 재고는 보존하며, 다음 출정의 부족분은 다시 확인하고 자동 구매하지 않는다. 기존 세 하네스 조합·영구 개선·내구·충전/건강을 변경하지 않는다.

유효 투척에서 무료분부터 소비하고 슬롯 없이 공통 적재 무게에 반영한다. 생환/비상 탈출 정산 시 미사용 유료분만 반환한다. 실패·시작 후 미정산 종료는 가져간 유료분만 잃으며 거점 잔여 재고를 보존한다. 결과에 무료/추가 사용·반환 또는 소실 수량을 표시한다. 구매비는 거점에서 이미 지불했으므로 정산에 다시 청구하지 않는다.

스키마 6의 `paid_lures`·`selected_lures`·`pending_departure`를 추가했다. 미완료 기록은 빈 사전 또는 `id`(십진 문자열)·`phase`(`reserved`/`started`)·`free`·`paid` 네 필드다. 배정량/선택·거점+휴대 상한·출정 ID/다음 ID를 함께 검증한다. 구형 1~5는 추가분 0·선택 2·빈 기록으로 읽고 정상 저장 때 전환한다.

출정은 비활성 장면 검증→예약 저장→전환/초기화→시작 표식 저장→조작/시간 활성화다. 시작 표식 저장 직후 조작이 열리기 전 종료도 시작된 출정으로 취급한다. 시작 전 기술 실패의 예약은 한 번만 복구 저장하며 실패하면 준비를 잠그고 재시도한다. 이어하기는 예약을 반환하거나 시작 기록을 반환 없이 정리 저장한 뒤 거점으로 들어간다. 정산 반환과 기존 결과 반영은 한 저장이다. 읽기만으로 복구/반환하거나 미확보 회수품을 저장하지 않는다.

검사 범위/실제 경로/준비한 경계와 재현은 [DEV-0413 검사 기록](../project/project_context.md#dev-0413-거점-소음-유인물-준비-검사)을 따른다. 이하 제안의 수치/보존 계약은 이 시험에서 적용되었지만 최종 한도·단가·무게·손실 체감은 Q-026에 남는다. 출정별 현금 지출/재고 소비 원가와 귀환 순이익 통합은 DEV-0414의 문서 범위다. 새로운 도구·세계관 보급 제도·G4 완료를 선언하지 않는다.

## 사용자가 선택한 준비 방식

2026-10-06 사용자가 **기본 2개 무료 + 필요하면 추가 구매**를 선택했다. [DEC-113](../project/decisions.md#dev-0412-휴대-도구-준비-방식-선택)과 [경제 규칙](economy_rules.md#휴대-도구의-기본분과-추가-구매)에 이 방향만 반영한다. 기존 무료 대응을 유지하면서 추가 수량에 비용을 쓰는 선택이다. 가격·최대 수량·남은 추가분의 보존·무게·저장 처리는 아래의 **미적용 제안**이며 답변만으로 최종 확정하지 않는다.

아래 표는 질문 당시 비교 이력이다. 선택한 첫 행을 바탕으로 후속 시험을 설계한다.

| 방향 | 플레이어가 하는 일 | 정리해야 할 부담 |
|---|---|---|
| 기본 2개 무료 + 추가 구매 | 기본 대응 수단을 유지하고 더 가져갈 만큼 비용을 확인 | 무료분의 비축/현금화 방지, 추가분의 미사용 잔량 처리 |
| 전량 구매 + 남은 수량 보관 | 보유량과 비용을 보고 필요한 만큼 구매/휴대 | 돈 0에서의 재출정과 기존 무료 기능 축소, 구매 재고의 출정/귀환 저장 |
| 무료 지급 + 휴대 수량 선택 | 돈을 쓰지 않고 이번 출정 수량만 선택 | 적재 선택의 실제 효과, 소모품 비용을 다룰 후속 범위 |

## DEV-0412 수량·비용·적재 제안 — 미적용

| 항목 | 첫 비교 값/처리 | 검토 근거와 제한 |
|---|---|---|
| 가져갈 총수량 | 0·1·2·3·4개 중 선택, 기본 2개 | 2개까지 기존 무료 대응 유지. 3/4개는 추가 대응과 비용/적재를 비교. 최종 한도는 아님 |
| 기본 무료분 | 선택 총수량과 2 중 작은 값 | 0개 선택도 가능. 출정마다 새로 부여하며 거점 재고로 쌓지 않음 |
| 추가 휴대분 | 총수량에서 무료분을 뺀 값, 최대 2개 | 이미 보유한 추가분을 먼저 배정, 부족한 개수만 새로 구매 |
| 추가분 가격 | 개당 5, 추가 구매 합계 0/5/10 | 현행 일반 회수품 판매 10·30, 수리 단가 5와 비교할 첫 조건. 2개 추가 가격 10은 회수 경로 수입 40의 1/4. 최종 부담 적절성은 사람 평가 |
| 거점 추가분 보유 한도 | 최대 2개 | 별도 대량 비축/상점 화면 없이 준비에 필요한 부족분만 사는 첫 범위. 준비 수량을 줄여도 이미 산 추가분을 삭제하거나 환불하지 않음 |
| 사용 순서 | 무료분부터 소비, 이후 추가분 | 실제 유효 투척 시작 때 1개. 쓰지 않은 구매분을 먼저 낭비하지 않음 |
| 슬롯/무게 | 회수품 슬롯 0, 남은 도구 개당 무게 0.25 | 별도 도구 개수로 관리. 기본 2개면 시작 무게 0.5, 4개면 1.0. 기존 구현은 도구 무게 0이며 이 제안은 아직 적용하지 않음 |

준비 화면은 총수량 하나를 선택하게 하고 무료분·보유 추가분 사용·새 구매분·비용·확정 후 잔액·시작 무게를 함께 보여준다. 별도 무료/유료 수량 조절이나 먼저 상점에서 사는 절차를 요구하지 않는다. 잔액이 부족하면 같은 화면에서 2개 이하로 줄여 무료 준비할 수 있다. 수리·충전·하네스 장착은 기존 서비스를 따른다.

이전 총수량 선택은 다음 준비의 희망값으로 기억한다. 사용/실패 뒤 추가분이 부족해졌다면 출정 버튼은 부족분과 비용을 다시 확인하는 준비 화면으로 연결하며 자동 재구매하지 않는다. 무료 2개로 줄이기와 추가 구매 후 이전 수량 유지를 같은 화면에서 선택할 수 있다. 실제 출정 배정 직전에 보유량을 다시 검사한다.

보유 추가분을 `S`, 총 휴대 선택을 `N`이라 하면 무료분 `F=min(N,2)`, 추가 배정 `P=max(N-2,0)`, 구매 부족분 `B=max(P-S,0)`, 결제액 `5×B`다. 수량/가격은 규칙 데이터로 관리하며 코드는 위 시험 숫자를 고정하지 않는다. 확정 뒤 거점 추가분은 `S+B`; 실제 출정 배정 뒤 `S+B-P`다. UI 견적과 도메인 계산은 같은 값을 사용한다.

| 선택 예 | 준비 확정 | 출정 배정 | 결과 |
|---|---|---|---|
| 돈 10·보유 추가분 0 → 총 4개 | 2개 구매, 돈 0·추가분 보유 2 | 무료 2+추가 2, 거점 잔고 0 | 1회 쓰고 생환하면 무료 1은 끝나고 추가 2는 반환 |
| 돈 5·보유 추가분 1 → 총 4개 | 부족한 1개만 구매, 돈 0·추가분 보유 2 | 무료 2+추가 2 | 총 3회 쓰고 생환하면 추가 1개 반환 |
| 보유 추가분 2 → 총 3개 | 새 결제 0 | 무료 2+추가 1, 거점 추가분 1 유지 | 실패 시 휴대한 추가분만 소실, 거점의 1개는 유지 |
| 돈 0·보유 추가분 0 → 총 2개 | 결제 0 | 무료 2 | 내구가 부족하면 기존 최소 복구를 거쳐 재출정 가능 |

무게 제안은 가져갈수록 회수 여유가 줄고 사용 후 가벼워지는 효과를 비교한다. 현재 부담 경계 2.5·과적 경계 4.0은 변경하지 않는다. 예를 들어 회수품 무게 2.0에 도구 2개가 남으면 2.5로 부담, 한 개를 쓰면 2.25로 정상이다. 도구가 0개가 되어도 회수품 무게를 없애지 않는다. 무게는 가방 총량·HUD·이동 감속·걸음 소음에 같은 입력으로 반영한다. 고유 물품 보호·G 빠른 버리기·미확인 가치에는 영향을 주지 않는다. 첫 제안에는 도구 버리기·판매를 추가하지 않으며 출정 전 0개 선택으로 적재를 줄일 수 있다.

## 귀환·실패·재출정 제안

| 시점/결과 | 무료분 | 구입한 추가분 | 비용/보유 처리 |
|---|---|---|---|
| 준비 선택/취소 | 출정 전 예상량만 표시 | 미확정 구매는 지급하지 않음 | 취소 시 돈·보유·기존 준비 유지 |
| 준비 확정 후 수량을 줄임 | 새 선택값에 맞게 미리 보기 변경 | 이미 구매한 추가분은 거점에 보관 | 환불·자동 판매 없음. 새 차감도 없음 |
| 정상/비상 탈출 성공 후 정산 저장 | 남은 무료분은 비축하지 않음 | 휴대했던 미사용 추가분만 거점 반환 | 재결제/현금 환급 없이 반환 수량 표시 |
| 위험 실패 | 남은 무료분 폐기 | 미사용분을 포함해 휴대한 추가분 소실 | 거점에 남긴 추가분·기존 돈/영구 장비/개선은 보존 |
| 시작이 확정된 탐험 도중 종료/강제 종료 | 다음 출정 때 새 무료분 | 출정 배정한 추가분은 반환하지 않음 | 이어하기는 거점. 사용 전 상태로 구매분을 복제하지 않음 |
| 결과 화면에서 저장하지 않고 종료 | 새 획득으로 저장하지 않음 | 반환 미확정이므로 거점에 추가하지 않음 | 저장 실패 중에는 안내 후 정산 재시도 가능 |
| 출정 시작 전 기술 실패 | 아직 지급/사용하지 않음 | 예약 배정만 한 수량은 저장된 복구 절차로 반환 | 게임 내 위험 실패와 구분, 같은 예약을 두 번 반환하지 않음 |

위 추가분 손실·종료 처리는 이번 비교안이며 영구 장비를 잃지 않는 DEC-105를 변경하지 않는다. 무료분을 판매/보관/반환으로 바꾸거나 무료 귀환 반복으로 추가분을 늘릴 수 없다. 돈 0·판매품 없음·내구 0·추가분 0에서도 기존 무료 최소 수리 후 기본 2개 또는 선택 0개로 실제 회수/귀환이 가능해야 한다.

총 투척 수를 `U`라 하면 사용한 추가분은 `min(P,max(U-F,0))`, 생환 반환은 `P-사용한 추가분`이다. 실패/시작 후 미완료 종료의 반환은 0이다. 반환이 최초 배정 `P`보다 크거나 다른 출정 번호와 연결되면 정산을 거절한다. 반환과 거점 진행/결과 반영은 한 저장에 포함한다.

## 저장·시작·복구 계약 제안

유료 재고를 넣으면서 현재의 “출정 직전 거점 기록으로 그대로 이어하기”를 유지하면 이미 던진 구매분을 다시 받게 된다. 따라서 구매 저장만 붙이고 출정 배정 저장을 빠뜨려서는 안 된다. 아래는 **후속 구현이 충족할 처리 계약**이고 이번에 저장 키/버전을 추가한 것이 아니다.

1. **준비 확정:** 현재 돈/추가분/선택/가격을 다시 확인한 후보에 부족분 결제·지급과 총수량 선택을 함께 저장한다. 저장 성공 뒤 실제 거점을 바꾼다. 결제 뒤 선택만 줄이면 구매분은 거점에 남는다.
2. **출정 예약:** 장면·내구·구성을 입력 불가 상태에서 먼저 검증한다. 새 출정 번호, 무료/추가 배정량과 원래 선택을 가진 예약 및 추가분 차감·다음 번호를 함께 저장한다. 보관 잔량과 예약 수량을 별도로 보존하며 입력을 아직 열지 않는다. 예약 저장 실패는 거점/재고/번호를 바꾸지 않는다.
3. **시작 확정:** 상태 전환과 초기화가 성공한 뒤, 예약을 시작된 출정으로 표시하는 저장에 성공해야 입력·위험 시간을 활성화한다. 이 지점부터 종료하면 추가분을 소모한 출정으로 취급한다. 탐험 중 자유 저장이나 위치/위험 상태 복원은 추가하지 않는다.
4. **시작 전 복구:** 초기화/전환/시작 저장 실패는 예약의 추가분만 돌려주는 복구 후보를 저장한다. 복구 저장도 실패하면 출정·거점 상태 변경을 막고 재시도를 안내한다. 재실행은 시작 전 예약을 같은 복구 절차로 처리하며, 복구 성공 전 상태를 무시하거나 재예약하지 않는다. 읽기 자체는 파일을 다시 쓰지 않는다. 이미 소비한 번호는 재사용하지 않는다.
5. **시작 후 재실행:** 시작된 기록은 추가분 반환 없이 거점 재개 대상으로 정리한다. 이 정리 저장이 실패하면 새 출정/거래를 열지 않는다. 장비 손상이나 소모품 외의 새 종료 벌금을 여기서 만들지 않는다. 시작 표식 저장 직후 입력 활성화 전 종료도 이 경계를 따름을 안내한다.
6. **정산:** 시작된 출정 번호·배정량과 종료 요약을 검증한다. 기존 정산 후보에 미사용 추가분 반환과 출정 기록 종료를 포함해 저장한 후 거점을 교체한다. 저장 실패 시 결과와 이전 파일을 유지하고, 성공 후 같은 결과/번호는 재반영하지 않는다.
7. **호환:** 현재 스키마 5와 구형 1~4는 추가분 0·선택 총수량 2·미완료 도구 출정 없음으로 읽는다. 실제 스키마 확장 때 기존 1~5의 등록·내구·장착·영구 개선 전환을 보존한다. 필드 누락·분수/음수/범위 초과·예약/시작 상태 불일치·미지원 버전은 원본을 덮어쓰지 않는다. 기술 복구가 필요한 기록과 손상된 기록을 구분한다.

도구를 실제로 사는 **준비 확정**과 거점의 구매 재고를 가져가는 **출정 배정**은 돈을 두 번 차감하는 두 거래가 아니다. 기존 `HubState.to_save_data()`는 활성 탐험에서 비어 있으므로 활성 런을 그대로 저장하려 하지 말고 검증 가능한 출정 예약 후보/복구 상태를 별도 공개 계약으로 만든다. 앱은 후보 저장과 입력 활성화 순서를 연결하고 파일 기술 처리는 저장 계층에 남긴다.

## 비용 표시와 후속 통합

준비 화면은 `이번 새 구매액`, `보유 추가분 사용`, `확정 후 보유금`을 구분한다. 이미 보유한 추가분을 가져갈 때 새 비용은 0이다. 결과 화면은 무료 사용·추가분 사용/소실·반환을 수량으로 표시하며, 구매가 끝난 도구를 사용/반환할 때 돈을 다시 빼거나 더하지 않는다.

구매액 10과 이번 사용 가치 5는 같은 지표가 아니다. 구매 시점의 현금 지출·기존 재고의 이번 소모 가치·이번 출정 순이익 귀속은 후속 G4 비용 통합에서 명시적으로 선택한다. 현재 귀환 `순이익`에 새 도구 비용이 통합되었다고 보고하지 않으며, 미지불 견적을 실제 비용으로 합치지 않는다. 가격이 나중에 달라졌을 때 기존 재고의 취득 원가까지 저장할지는 그 작업에서 판단한다.

## 공통 검증 계약

1. 거점 화면은 현재 보유금, 지급/보유/추가 구매 수량, 가져갈 수량, 실제 지불액과 예상 적재 영향을 구분한다. 확정 전 선택·취소는 재산을 바꾸지 않는다. 가격이나 선택을 UI 자체에서 계산하지 않는다.
2. 수량의 음수·소수·잘못된 타입·상한 초과·정수 곱셈/합산 초과, 부족한 돈/재고·오래된 견적·중복 확정을 거절한다. 동일 상태에서 동일한 견적이어야 한다.
3. 구매/준비 후보 저장 실패 시 실제 상태와 이전 파일을 유지하고 같은 확인을 다시 해도 중복 결제하지 않는다. 다른 거점 서비스·가방/장착 변경·출정과 동시에 확정할 수 없게 한다.
4. 출정 전 구성을 검증하고 시작 수량을 복사한다. 도구 0개로도 기본 회수·입구 귀환과 기존 수리 후 재출정이 가능해야 한다. 하네스 세 장착 조합·충전·건강·내구·영구 개선의 값이 도구 선택으로 바뀌지 않아야 한다.
5. 실제 이동/F 입력으로 정상 투척·벽 앞/범위·소진·중복 입력·메뉴/포커스·투척 중 귀환/실패를 검사한다. 선택한 수량·유효 사용 수·종료 잔량을 같은 출정 안에서 대조한다.
6. 생환·별도 비상 탈출 성공·실패·정산 저장 오류/재시도·종료/강제 종료·새 프로세스 이어하기를 구분한다. 영구 장비 유지 규칙을 소모품 전량 복구로 자동 확장하지 않는다.
7. 미사용/반환 수량이 있으면 출정 때 실제 배정한 수량을 초과해 반환할 수 없고 한 번만 반영한다. 무료 수량을 보관/판매/현금 환급으로 바꾸는 경로도 검사한다.
8. 새 저장 필드의 정상/손상/누락/미지원 값, 구형 1~5 읽기 원본 보존·다음 정상 저장 전환, 기존 돈/가방/보관/원본/내구/장착/개선 보존을 검사한다. 저장 키·버전·ID는 구현 착수 때 기록한다.
9. 실제 출정 흐름과 상태를 준비한 경계 검사를 구분하고 두 해상도·마우스/키보드·기존 전체 회귀를 확인한다. 자동 검사는 규칙 일치만 입증하며 비용 부담·휴대 선택·읽기 쉬움의 사람 평가를 대신하지 않는다.

선택한 비교안의 추가 경계는 총수량 0/1/2/3/4, 보유 추가분 0/1/2, 잔액 0/4/5/9/10, 같은 준비 재확정, 구매 후 수량 줄이기, 무료분 소진 전/후·투척 직후 종료, 반복 생환/실패, 예약 전/후·시작 표식 전/후·정산 전/후의 프로세스 재실행이다. 기본/추가분 혼동·무한 반환·보유 한도 초과를 검사하고, 무게 경계 2.5/4.0 바로 아래·같음·초과 및 도구 사용 직후 이동/소음 회복을 확인한다.

## 구현 인계의 제한

수량 준비가 확정되더라도 신규 조명·감정 도구·문 고정 아이템이나 도구 제작/판매/발견 획득을 함께 추가하지 않는다. 문 고정은 현재 하네스 비상 방전의 행동이고, 별도 E 비상 탈출과 소음 유인물은 다른 자원이다. 구체적인 순서는 개발 인계에서 한 작업씩 지정한다.

## DEV-0415 비용 표시 연결

위 DEV-0412의 비용 미통합 설명은 당시 이력이다. 현재는 [DEV-0415 시험 적용](expedition_cost_reporting.md#dev-0415-비용-표시-시험-적용)으로 구매 원가를 보존하고 무료분 우선·추가분 FIFO 사용/반환/소실을 손익과 현금 변화에 각각 연결한다. 수량·단가·무게·실패 안전망은 DEV-0413과 같고, 구형 유료 재고는 원가 미기록으로 취급한다. Q-026의 최종 도구 밸런스와 Q-027의 사람 이해도 검토는 유지한다.

## DEV-0422 휴대용 감정 준비 인계

[DEC-117](../project/decisions.md#dev-0422-휴대용-감정-방식-선택)은 휴대용 감정 도구를 유료 구매해 휴대 수량을 고르고 안전 귀환 미사용분을 보관하는 방향이다. 위 무료 기본분·추가 구매와 무료분 우선 사용은 소음 유인물에만 적용한다. [휴대용 감정 검토안](portable_appraisal.md#수량비용적재-제안)은 보유분 우선·부족분 구매 확인·자동 재구매 없음과 두 도구 잔량 무게의 합산을 후속 수용 기준으로 정리한다. 이번에는 코드·기존 재고·스키마 9를 변경하지 않으며 단가/한도/사용·복구 세부와 사람 평가는 Q-030에 남긴다.

## DEV-0423 두 도구 준비와 합산 무게

유인물의 무료2+추가 구매는 그대로이며 감정 도구는 기본0·전량 유료다. 두 재고/원가를 따로 예약·반환하고 잔량 무게를 합산한다. 도구 구매/선택 후보는 저장 성공 뒤 반영하며 부족분 자동 결제는 없다. 현재 [휴대용 감정 시험 적용](portable_appraisal.md#dev-0423-준비사용정산-시험-적용)과 [검사 기록](../project/project_context.md#dev-0423-휴대용-감정-연결-검사)을 따른다. 위 DEV-0422 인계는 당시 이력이며 최종 정책·사람 평가는 기존 질문 상태를 유지한다.
