# 하네스 엔지니어링

## 목적

수색꾼이 정면 전투 대신 도구로 위험에 대응하도록 하는 하네스의 준비·자원·성장 경계를 관리한다. DEV-0408의 요구·비교안, DEV-0409의 제한된 장착 시험 적용과 DEV-0410의 미적용 성장 제안을 구분한다.

**이 문서는 `draft`이며 단독 구현 기준이 아니다.** 기존 요구의 권한은 아래에 연결한 GDD·confirmed Design·기존 결정에 있다. 새 장착 한도·초기 구성·해금/성장 가격과 효과는 [Q-024·Q-025](../project/open_questions.md#하네스-준비성장-검토-경계)에서 추적한다. 미적용 제안은 게임 데이터나 사용자 승인 정책으로 읽지 않는다. 작업 순서와 완료 상태는 [DEV-0410 인계](../project/development_handoff.md#dev-0410--하네스-영구-성장-규칙-정리)가 소유한다. 아래 시험 적용은 최종 제품 수치·영구 성장의 승인이 아니다.

## 포함 범위

- 하네스의 핵심 동작과 모듈 경계
- 자원 소모와 회복 규칙
- 위험 대응 도구와 성장 축
- 하네스가 전투 장비로 변질되지 않도록 하는 금지선

## 제외 범위

- 던전과 잔존 에너지의 세계관상 원리
- 실제 코드 구조와 엔진 구현 세부
- 모듈별 최종 수치와 콘텐츠 목록

## 행동과 모듈 계열

GDD의 모듈 계열은 아래의 **역할 예시**다. 코드 상속 관계나 입력 키 하나가 곧 장착 모듈의 정체성이 되는 것은 아니다.

| GDD 계열 | 예시 역할 | 이번 검토에서 지킬 경계 |
|---|---|---|
| 감지 | 위험 예고·미확인 분류 추정·잔여 구역 반응 | 무료 기본 정보와 충전 정밀 분석을 분리한다. 물품 감정의 정보 제한을 우회하지 않는다. |
| 작업 | 문 우회·함정 정지·잔해 안정화 | 비용과 대상의 상태를 확인해 일시 대응한다. 모든 문·위험을 무조건 해결하지 않는다. |
| 운반 | 무게 한도·대형품 견인·짐 버리기 속도 | 기존 가방/무게와 실제 회수 선택에 연결한다. 대형품·견인은 아직 별도 후속이다. |
| 비상 | 방전·문 임시 고정·짧은 탈출 가속 | 짧은 무력화·퇴로 확보에 사용한다. 적을 계속 공격하는 수단으로 바꾸지 않는다. |

성장 축은 GDD의 관찰 숙련·현장 정비·회수 기술·비상 대응·운영 효율을 따른다. 이 이름만으로 구매 가능한 상품·능력 ID·수치 단계를 추가하지 않는다.

## 장기 진행·장착·런 상태의 구분

다음 표는 GDD의 해금/선택과 기존 보존 규칙을 후속 구현에서 함께 지키기 위한 계약이다. 저장 키·자료 구조·가격을 확정하는 표가 아니다.

| 상태 | 의미와 변경 경계 |
|---|---|
| 영구 해금/업그레이드 | 사용할 수 있게 된 선택지와 구매/획득한 개선. 획득 조건과 가격은 Q-025에서 정하며 실패로 소급 취소하지 않는다. |
| 거점 장착 선택 | 해금된 선택지 중 다음 출정에 사용할 구성. 해금했다고 자동 장착하거나 다른 장착을 몰래 밀어내지 않는다. |
| 출정 구성 복사 | 출정 시작 시 유효한 장착과 능력치를 복사한다. 탐험 중 거점 선택을 바꿔 충전이나 기능을 다시 받는 경로를 만들지 않는다. |
| 런 충전/임시 효과 | 정밀 분석·작업·비상 대응이 공유하는 현재 런 자원과 일시 대응 상태. 장착 변경이나 내구 수리로 런 소모를 되돌리지 않는다. |
| 영구 내구 | 기존 손상 정산·거점 선택 수리 규칙을 따른다. 모듈 교체로 새 하네스를 받은 것처럼 내구를 초기화하지 않는다. |
| 휴대 도구/소모품 | 별도 횟수·구매·적재 규칙이 필요한 준비 대상이다. 하네스 장착 슬롯이나 충전과 같다고 가정하지 않는다. |

무료 기본 정보, 사전 경고, 이동·기본 상호작용·회수·입구 귀환은 유료 모듈 구매 전에도 접근할 수 있어야 한다. 선택하지 않은 모듈의 능력을 사용할 수 없다는 사실과 실제 우회/회피 대안을 출정 전·현장에서 알린다. 모듈 부재를 숨긴 채 충전을 차감하지 않는다.

## 첫 장착 비교안 — 미적용 제안

다음은 **DEV-0408 당시의 제안 이력**이다. DEV-0409의 현재 적용 범위와 구형 전환은 [시험 적용](#dev-0409-장착-선택-시험-적용)을 따른다.

기존 동작의 차이를 비교하기 위해 **정밀 분석·안정화·비상 방전 세 행동 중 두 개를 고르는 구성**을 우선 후보로 둔다. 새 액션·공격력·충전 증가 없이 준비가 탐험 판단을 바꾸는지 확인하기 위한 제안이다. 이번 작업에서 실행·저장에 적용하지 않았으며 슬롯 수나 초기 소유 구성을 승인한 것으로 기록하지 않는다.

- 첫 비교 자료에는 세 행동을 모두 선택 가능한 상태로 제공하고 두 개를 장착한다. 이는 행동 제한을 비교할 시험 조건이며 제품의 초기 영구 해금이나 성장 보상을 대신하지 않는다.
- 비교 조합은 정밀 분석+안정화, 정밀 분석+비상 방전, 안정화+비상 방전이다. 선택되지 않은 정밀 기능과 별개로 무료 기본 정보·경고는 유지한다. 각 조합으로 회수·회피·입구 귀환이 가능하고 선택한 행동의 결과가 실제로 달라지는지 확인한다.
- 작업 분류 후보에서는 잔해·함정·잔여 구역 입구 안정화를 안정화 선택에, 골렘 방전과 문 임시 고정을 비상 대응 선택에 연결한다. 정밀 분석 대상은 기존 지원 대상만 사용한다. `StabilizableHazard` 계열 전체를 일괄 차단하면 문 고정까지 잘못 묶일 수 있으므로 대상별 대응표를 먼저 확정하고 검사한다. 안정화 미장착은 해당 선택 구역 개방을 제한할 수 있지만 기본 회수·입구 귀환까지 막는 배치는 피한다.
- 비상 탈출의 기존 E 준비·충전 1·회수품 유지와 소음 유인물 2회는 첫 장착 비교의 제한 대상에서 제외하는 안을 둔다. 이는 두 기능을 최종적으로 무료 기본 장비로 확정한다는 뜻이 아니다. 별도 도구 준비·Q-021 검토에서 바꿀 때 다시 기록한다.
- 첫 비교에서는 장착 변경 자체에 비용을 붙이지 않고 현재 공용 충전 3·사용 비용·가방·수리 값을 유지하는 안을 둔다. 화면을 열고 닫거나 저장을 재시도해 내구·충전·보유금이 늘면 안 된다.
- 초기/구형 파일에 어떤 조합을 보완할지는 Q-024에 남긴다. 지금 모든 행동을 쓰던 기록을 읽기만으로 덮어쓰거나 알려주지 않은 선택지 손실로 전환하지 않는다. 실제 구현 착수에서 보완 구성·안내·전환 시점을 기록한다.

장착 조합의 차이는 **준비 선택**의 근거다. 무료로 세 행동을 열어 놓은 비교만으로 돈을 써서 발전하는 영구 성장이나 G4 완료를 입증하지 않는다.

- 무료 기본 정보·상태 경고·이동·E 조사/회수·입구 귀환은 유지한다. 안정화 없이 잔여 구역 입구를 열 수는 없지만 위쪽 기본 회수 경로와 원래 입구 귀환은 가능하다. 소음 유인물의 별도 횟수 2와 별도 시험 공간의 E 비상 탈출(공유 충전 1)은 이번 모듈 제한에서 제외한다.

- 스키마 **4**의 거점 7필드는 기존 6필드와 `harness_modules` 배열이다. 두 개가 아닌 배열·중복·알 수 없는 ID·잘못된 타입을 거절한다. 구형 1~3은 안정화+비상 방전을 메모리에서 보완하고 이어하기 거점에 안내한다. 읽기는 원본 바이트를 유지하며 다음 성공한 거점 저장에서 전환한다. 구형 1/2의 내구 3, 1의 빈 등록 목록 보완도 유지한다.
- 후보 상태 저장 성공 후 실제 상태를 바꾼다. 저장 실패는 기존 구성을 유지하며 재확정 또는 취소할 수 있다. 오래된 선택·중복 확정·활성 탐험 중 변경·다른 서비스 동시 사용을 거절한다.

## DEV-0410 영구 성장 제안 — 미적용

2026-10-04 다음 작업 지시로 `MIG-CHG-042`에 먼저 기록했다. **이번 작업은 규칙 검토이며 실행 코드·가격 데이터·저장 형식은 변경하지 않는다.** 아래 두 설명은 비교용 효과명이며 Reference의 공식 상품명이나 새 모듈 ID가 아니다. 최종 제품 수치·문서의 `confirmed` 승격·G4 완료를 뜻하지 않는다.

### 획득 방식과 한도

획득 경로는 거점 직접 구매·원본 등록 후 유료 구매·탐험 발견을 사용자에게 질문했다. **현재 응답 대기이며 다음은 거점 직접 구매를 가정한 제안이다.** 이는 GDD 10장의 수입→개선 흐름에 맞추고 현재 연구 해설·원본 등록에 새 보상을 붙이지 않는 첫 비교 조건이다. 응답이 다른 방식을 선택하면 조건·검증 계약을 먼저 고친다. 응답 없이 승인된 정책이나 DEC 결정으로 옮기지 않는다.

- 기존 세 모듈의 사용 자격과 두 개 장착은 유지한다. 이미 무료로 쓰던 기능을 유료로 다시 사게 하거나 구형 이용자의 장착을 빼앗지 않는다. 첫 비교는 **기존 행동의 영구 개선 두 종류**, 각 한 단계다. 새 행동 모듈 해금은 구현 완료로 세지 않는다.
- 거점에서 개선 하나를 선택해 효과·가격·구매 후 잔액·필요 장착을 보고 확정한다. 시험 구매가는 **각 60**, 추가 재료·연구·발견 선행 조건은 없다. 가격은 데이터로 관리한다. 현재 판매가/수리비가 모든 난이도의 가격 근거가 되는 것은 아니다.
- 해당 개선을 아직 보유하지 않고, 잔액이 가격 이상이며, 거점 대기 상태일 때만 구매 가능하다. 두 개선은 어느 순서로든 하나씩 살 수 있으며 각각 한 번만 보유한다. 둘 다 사도 세 번째 모듈 슬롯이나 충전 증가를 받지 않는다. 반복 단계·되팔기·환불·분기 초기화는 첫 시험에 없다.
- 구매는 모듈을 자동 장착하지 않는다. 해당 모듈이 미장착이면 보유 개선도 비활성이라고 구매 전 안내한다. 다음 출정에 장착 모듈과 보유 개선을 함께 복사하고 그 런 동안 고정한다. 별도 개선 장착 슬롯을 만들지 않으며 두 관련 모듈을 장착했다면 두 보유 개선이 함께 적용된다.
- 최초/구형 진행의 보유 개선은 빈 목록이다. 현재 무료 장착을 구매 완료로 변환하지 않는다. 거점 장착을 바꾸거나 탐험에 실패해도 구매 기록을 지우지 않는다.

### 서로 다른 두 효과와 현재 기준

| 비교용 개선 | 미구매의 현재 동작 | 구매·해당 모듈 장착 뒤 제안 | 유지할 제한 |
|---|---|---|---|
| 관찰 정보 개선 | 잔해·골렘 정밀 분석은 즉시 상태별 설명을 보여 주며 남은 초를 공개하지 않는다. | 정밀 분석에 성공한 현재 대상/상태의 남은 시간을 추가로 표시한다. 잔해 붕괴 경고, 골렘의 경계·수색·무력화 타이머만 대상이다. | 정밀 분석 장착과 기존 충전 1이 필요하다. 무료 경고·기존 설명은 그대로이며 물품 분류/가격·미발견 구역·원본 정보를 공개하지 않는다. |
| 비상 대응 시간 개선 | 현재 앱의 골렘 무력화는 2초, 문 고정 규칙은 6초다. | 해당 출정의 골렘 방전은 기본 시간에 **1초 추가**(현재 앱 3초), 닫힌 문 고정은 **2초 추가**(현재 규칙 8초)한다. | 비상 방전 장착과 기존 충전 1이 필요하다. 공격/영구 처치·비상 탈출·안정화 대상·충전 최대 3은 바꾸지 않는다. |

현재 기준의 근거는 [정밀 분석 제어](../../src/harness/harness_controller.gd), [잔해 상태](../../src/gameplay/hazards/unstable_debris_hazard.gd), [골렘 상태](../../src/gameplay/hazards/broken_guard_golem.gd), [앱 골렘의 2초 설정](../../src/app/prototype_exploration.tscn), [문 고정 6초 데이터](../../src/data/prototype_door_hold.tres)다. 골렘 클래스 기본값은 1.5초이므로 모든 장면을 일괄 3초로 덮어쓰지 않는다. 개선은 각 대상의 기본 시간에 가산하며 과거 G1 비교 장면은 개선 미보유 기준을 유지한다. 두 종류의 이득은 **판단에 쓸 정보**와 **실제 행동 여유 시간**으로 구별한다.

관찰 개선의 세부 조건은 다음과 같다.

- 남은 시간은 해당 타이머가 실제로 진행 중일 때만 소수 첫째 자리까지 내림해 표시한다. 예: 실제 0.19초→표시 0.1초. 음수나 가상의 타이머는 만들지 않고 잔해 대기/안정화/붕괴 후, 골렘 순찰/추적에서는 남은 시간 줄을 표시하지 않는다. 숫자는 상태 설명을 대신하지 않으며 경계/수색 중 재탐지 등으로 행동이 달라질 수 있음을 기존 설명과 함께 알린다.
- 한 번 유료 분석한 **동일 대상·동일 상태의 유효한 분석 구간** 안에서만 숫자를 갱신한다. 초가 줄었다는 이유로 분석이 만료되거나 매 프레임 충전을 다시 쓰면 안 된다. 대상/상태 변경, 범위 이탈 뒤 재접근은 기존 분석 만료 규칙을 따른다. 같은 상태에서 타이머가 다시 시작되면 현재 남은 시간을 갱신하며 과거 값을 고정하지 않는다.
- 인벤토리/지도 일시정지 동안 타이머와 표시도 멈춘다. 정밀 분석 비용 예약 후 대상/상태가 바뀌어 결과를 얻지 못하면 비용을 보존한다. 표시를 위한 조회가 타이머를 새로 시작하거나 위험 상태를 바꾸면 안 된다.
- 정밀 분석 자체는 이미 즉시 끝나므로 속도 개선을 별도 이득으로 세지 않는다. 충전 1을 0으로 낮추거나 정밀 정보를 무료 기본 정보로 옮기지도 않는다.

비상 개선은 행동이 성공할 때 한 번만 가산한다. 이미 무력화한 골렘/고정 중인 문에 반복 입력해 효과를 연장하거나, 공유 규칙 자원을 바꿔 다음 출정에도 가산이 남게 해서는 안 된다. 효과 종료 후 실제 추적/문 해제가 기존 상태 규칙으로 이어져야 한다. 해제 예고·밀어서 여는 시간·피해·건강·내구·수리비는 그대로다.

### 가격 비교와 지출 표시

시험가 60의 첫 비교 근거는 현재 [경제 데이터](../../src/data/prototype_economy.tres)의 경량 폐품 10+중량 폐품 30과 정상 귀환 내구 1의 수리비 5다. 보유금 0에서 두 물품을 모두 회수·판매하고 매번 완전 수리하는 가정이면 회당 잔액 증가 35, 두 번 뒤 70으로 첫 개선을 살 수 있다. 네 번의 같은 귀환 뒤 총 140으로 두 개선 120을 살 수 있다. 이는 **다른 비용·실패·추가 수입이 없는 산술 예시**이며 실제 소요 런 수나 재미를 보장하지 않는다. 후속 출정별 비용 통합이나 가격 변경 때 다시 평가한다.

구매 화면은 보유/미보유, 현재 장착에 따른 활성 여부, 효과 전후, 한 단계 상한, 가격, 보유금과 구매 후 잔액을 표시한다. 잔액 부족이면 필요한 차액과 구매 불가 이유를 알린다. 성공 안내는 이번 실제 지불액만 표시한다. 취소·화면 열람·견적 재계산은 지출이 아니다.

개선 구매는 장기 장비 투자로 표시하는 제안이다. 성공한 구매에서 돈을 한 번 차감하며 과거 귀환 순이익을 다시 쓰거나 다음 정산에서 재청구하지 않는다. [경제 규칙의 정산식](economy_rules.md#정산과-순이익)을 이번 문서에서 바꾸지 않는다. 투자 지출과 출정 비용을 함께 보는 기록/표시 방식은 후속 G4 비용 통합에서 정하며 지금 미구현 원장이나 누계가 있는 것처럼 표시하지 않는다.

### 결제·저장·재출정 계약

1. 견적은 선택한 개선·보유 여부·가격/효과·현재 잔액과 관련 상태를 묶는다. 확정 직전에 같은 조건을 다시 검사한다. 가격 변경·이미 구매·잔액 부족·상한 초과·활성 탐험·다른 거점 서비스 중에는 비용 차감 없이 거절하고 새 견적을 보여 준다.
2. 돈 차감과 보유 개선 추가를 하나의 후보 상태로 저장하고 성공 뒤에만 실제 거점을 교체한다. 쓰기 실패·재시도·취소·중복 확정에서 돈만 사라지거나 무료 개선이 남으면 안 된다. 새 프로세스로 이어하기해 두 값이 함께 복원되는지 확인한다.
3. 후속 저장 확장에는 보유 개선 목록을 추가하되 정확한 키/ID·다음 스키마 번호는 구현 착수에서 기록한다. 구형 1~4는 빈 보유 개선으로 읽고 기존 장착 보완(1~3), 내구/등록 보완을 유지한다. 읽기는 원본 파일을 유지하고 다음 정상 저장 때 전환한다. 누락·중복·알 수 없는 ID·잘못된 타입·단계 상한 초과를 거절하며 부분 복원/조용한 초기화는 금지한다. 개선 보유와 관련 모듈 미장착의 조합은 정상이다.
4. 성공/실패 정산·감정·판매·등록·연구·수리·무료 장착 변경의 후보 복사에서도 보유 개선을 보존한다. 출정에는 독립 복사본을 전달하며 런 충전 소모·대상 타이머는 영구 저장 목록에 넣지 않는다.
5. 구매 뒤 보유금 0이어도 무료 기본 정보·회수/입구 귀환과 기존 최소 복구로 재출정할 수 있어야 한다. 구매로 내구·건강·충전을 회복시키거나 실패 회수품을 되돌리지 않는다. 내구 0·잔액 0~4는 기존 무료 최소 복구, 잔액 5 이상은 기존 선택 유료 수리 조건을 유지한다. 성장 구매를 출정 허가의 필수 조건으로 만들지 않는다.

### 다음 적용에서 필요한 증거

| 검사 묶음 | 실제로 확인할 조건 |
|---|---|
| 구매/한도 | 각 개선의 돈 59/60/61 경계, 보유 상태, 두 구매 순서, 취소·중복·오래된 견적/가격 변경·서비스 충돌, 각 한 단계 상한 |
| 분석 정보 | 미구매/미장착/보유+장착 차이, 잔해 경고와 골렘 경계/수색/무력화의 실제 타이머 표시, 대상/상태/범위 전환·같은 상태 타이머 재시작·일시정지·반복 조회, 최초 1회 충전과 실패 시 보존 |
| 비상 시간 | 앱의 골렘 2→3초·문 6→8초 전후 경계, 과거 기준 장면과 개선 미보유 출정, 효과 종료·반복 입력 거절·일시정지, 충전/내구·타 대상 불변 |
| 저장/보존 | 결제/보유 동시 저장, 쓰기 실패/재시도·구형 1~4 읽기 바이트 보존/정상 전환·잘못된 파일 거절, 새 프로세스, 다른 서비스/실패/수리 후 보유 유지 |
| 실제 순환 | 번 돈으로 첫 개선 구매→관련 모듈 선택→앱 출정의 정보/시간 변화→회수·귀환, 두 개선 보유와 두 모듈 장착 동시 적용, 실패 뒤 최소 복구→재출정 |
| 화면/평가 | 두 해상도·키보드/마우스/Esc·미장착 효과 안내·가격/잔액/상한, 같은 경로의 미구매/두 선택 비교와 사람의 선택 이유·체감 이득·가격 부담 기록 |

자동 검사는 위 시험 조건의 정확성을 판정한다. 관찰 숫자가 짧은 경고 시간 안에 읽히는지, 비상 시간 증가가 판단을 바꾸는지, 어느 것을 먼저 살지 고민되는지와 가격 60의 적절성은 사람 평가로 남긴다. 신규 행동 모듈 해금·휴대 도구 준비·출정별 비용 통합과 G4 전체 완료는 이 두 개선만으로 충족했다고 처리하지 않는다.

## 저장·확정과 표시의 검증 계약

1. 장착 검토 화면은 보유/미해금·선택/미선택·허용 한도와 실제 가능한 행동을 구분한다. 사용할 수 없는 행동은 안내뿐 아니라 실행 직전에도 거절하고 충전을 쓰지 않는다.
2. 거점 선택은 후보를 저장한 뒤 실제 상태를 교체한다. 취소·쓰기 실패·오래된 상태·중복 확정에서 돈·내구·장착·해금·보관/등록/연구를 유지한다. 수정 중 출정/다른 서비스를 동시에 실행하지 않는다.
3. 해금 구매가 생기면 조건·가격·현재 상태를 다시 검사해 결제와 해금을 함께 저장한다. 구매와 장착은 구분하며 예상 비용이나 단순 화면 열람을 지출로 기록하지 않는다. 비용 귀속은 [경제 규칙](economy_rules.md#정산과-순이익)과 후속 G4 비용 통합이 소유한다.
4. 저장 확장은 구형 지원 버전·기본 해금/장착·알 수 없는 ID/중복/미해금 장착/한도 초과 처리부터 정한다. 잘못된 파일을 부분 복원하거나 조용히 삭제하지 않는다. 읽기는 원본 파일을 유지하고 정상 저장 시 전환한다. DEV-0408 문서 작업은 스키마를 바꾸지 않았고, DEV-0409의 장착 확장은 위 시험 적용을 따른다.
5. 같은 출정 구성을 모든 관련 입력·HUD·위험 대상에 전달한다. 한 화면에서만 기능을 숨기거나 충전을 재설정해 장착 제한을 우회하지 않는다. 실제 동작 경계와 모듈 ID/계열은 구분한다.

| 후속 검사 | 필요한 증거 |
|---|---|
| 선택/저장 | 한도·미해금·중복/알 수 없는 ID, 취소·실패/재시도·새 프로세스와 구형 전환 |
| 실제 행동 | 각 조합에서 정밀 분석·잔해/함정·잔여 구역 입구·골렘·문 고정의 허용/거절과 공용 충전 소모, 대상/상태 변경·정지·반복 입력 |
| 기본 탐색 | 기본 정보·경고·회수·우회·입구 귀환, 미장착 행동에 의존하지 않는 경로 |
| 기존 기능 | 소음 유인·비상 탈출·가방·수리·감정·판매·등록·연구가 약속한 기존 범위를 유지 |
| 손상/실패 | 성공/실패 후 장착·영구 해금을 유지하고 내구 손상·선택 수리·돈 부족 최소 복구를 거쳐 실제 재출정 |
| 화면 | 마우스/키보드/Esc, 두 해상도, 선택 한도와 미장착 안내, 비용 발생 전후 구분 |
| 성장 평가 | 구매 전후 서로 다른 두 선택의 실제 플레이 변화, 체감 이득·반복 부담을 사람 평가와 분리해 기록 |

자동 검사는 선택한 시험 조건이 지켜지는지를 확인한다. 어느 모듈이 재미있거나 공정한지, 장착 제한이 적절한지, 구매가가 의미 있는지는 자동 통과만으로 확정하지 않는다.

## 이관 상태

기존 골격에 DEV-0408에서 GDD 4-2·7장·10장·20-3의 준비/자원/성장 요구와 현재 코드 대조를 추가했다. 신규 비교안은 먼저 `MIG-CHG-040`에 기록했다. DEV-0409 장착 시험은 `MIG-CHG-041` 뒤 적용했다. DEV-0410은 `MIG-CHG-042` 뒤 미적용 영구 성장 비교안과 검사 계약을 추가했다. Story의 원인·공식 명칭이나 문서의 `confirmed` 승격을 변경하지 않는다. 이후 성장 적용/도구 준비/비용 통합은 개발 인계가 관리한다.
