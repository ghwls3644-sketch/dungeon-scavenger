# 장비 내구·수리와 재출정 안전망 검토안

## 상태와 목적

`DEV-0405`의 **구현 전 검토안**이다. GDD와 confirmed 경제 규칙에 이미 있는 요구를 현재 코드와 대조하고, 구현에 필요한 미정 처리를 분리한다. 아래 제안과 비교용 수치는 아직 실행에 적용하지 않았으며 이 문서만으로 제품 규칙을 확정하지 않는다. 미정 항목은 [Q-022·Q-023](../project/open_questions.md#수리-규칙-검토-경계), 다음 작업과 완료 조건은 [개발 인계](../project/development_handoff.md#dev-0405--장비-내구수리와-재출정-안전망-규칙-정리)가 관리한다.

## 기존 요구와 책임

| 기준 | 이미 정해진 요구 | 이번 문서가 임의 확정하지 않는 것 |
|---|---|---|
| [GDD 4-4](../GDD.md#4-4-실패-손실-설계-결정), [경제 규칙](economy_rules.md#실패-손실과-재기-안전망) | 실패해도 기본 하네스·영구 장비를 잃지 않으며 손상과 수리 비용이 존재한다. 기본 장비와 최소 회복으로 재출정을 보장한다. | 손상량·출정 제한·무료 복구량·면제 조건 |

| [경제 규칙의 비용 항목](economy_rules.md#비용-항목) | 수리비는 손상도·장비 유형·정비 성장과 관련하며 수치는 데이터로 관리한다. | 수리비 공식·거래 시점·반올림·최종 가격 |

영구 장비의 내구가 0이 되더라도 장비 소유 자체를 삭제하는 뜻으로 쓰지 않는다. 세계관상 사고 책임, 길드 대여 가능성, 공방 역할은 수리 수치나 무료 복구의 제공자를 자동 결정하지 않는다. 새 보험·대출·구조자·수리 NPC의 고유명은 만들지 않는다.

## 현재 구현과의 차이

| 구현 지점 | 현재 동작 | 수리 구현에서 보완할 계약 |
|---|---|---|
| [`ExplorationOutcome`](../../src/gameplay/recovery/exploration_outcome.gd) | 안전 귀환/실패, 회수 결과, 손실 수, 원인과 귀환 방식만 전달한다. | 손상이 언제 확정되고 정상/비상 귀환·실패에 어떤 입력이 전달되는지 정한다. |
| [`HubState`](../../src/meta/hub_state.gd) | 돈·보관품·등록 원본·가방·출정 번호를 유지한다. 내구 상태는 없다. | 현재 내구와 후보 손상의 일회 반영, 수리 견적/확정과 출정 가능 여부를 소유한다. |
| `SettlementResult`·`EconomyRule` | 정산 비용은 0이고 실제 판매가·별도 감정료만 있다. | 실제 발생 비용과 미지불 수리 예상액을 분리하고 단가·안전망 조건을 데이터로 둔다. |
| [`GameEntry`](../../src/app/game_entry.gd) | 감정·판매·등록은 후보를 저장한 뒤 실제 거점을 교체한다. | 손상 정산·수리·무료 복구도 같은 방식으로 저장 성공 때만 반영한다. |
| [`ProgressStore`](../../src/infrastructure/progress_store.gd) | 스키마 2의 거점 5필드, 구형 1의 빈 등록 목록 보완을 지원한다. | 내구 저장을 추가할 때 별도 버전 전환·구형 기본값·손상 데이터 거절을 검사한다. 이번 문서에서 키/버전을 추가하지 않는다. |
| `ExpeditionLoadout`·거점 준비 | 가방과 하네스 충전의 기본 구성을 복사한다. | 수리 상태 확인이 기존 충전/가방 값을 몰래 변경하지 않도록 한다. |
| 결과 화면 | 현재 비용 0에 맞춘 `순이익 +값`과 기존 돈 보존 안내를 쓴다. | 유료 수리 도입 시 실제 비용 발생 시점에 맞는 문구·음수/0/양수 표시를 검증한다. |

이 표는 코드의 현재 상태와 후속 책임을 설명한다. 아직 없는 필드·서비스를 구현 완료로 읽지 않는다.

## 사용자가 선택한 수리 방식

2026-10-01 사용자가 **거점에서 비용을 확인하고 선택 수리**를 선택했다. [DEC-111](../project/decisions.md#dev-0405-수리-방식-선택)과 confirmed [경제 규칙](economy_rules.md#수리-거래-시점)에 이 거래 시점만 반영했다. 귀환 정산은 손상을 확정하고, 실제 수리비는 거점에서 비용을 확인해 수리를 확정할 때 발생한다. 기존 감정·판매와 확인/취소/저장 실패 재시도의 흐름을 맞춘다.

아래 손상량·단가·부분 수리·내구 0의 제한·무료 최소 복구 조건은 별도 제안이다. 수리 방식의 선택이나 이 문서의 커밋 승인을 모든 시험 값의 승인으로 처리하지 않는다.

### 손상 상태 제안

첫 비교에서는 기본 하네스 한 개의 내구만 다룬다. 슬롯별 장비 내구·교체 부품·영구 최대 내구 감소는 후속으로 남긴다. 피해가 여러 번 통지되거나 종료 요청이 경합해도 출정 결과 하나에 손상을 한 번만 확정하는 구조를 우선한다.

시험 후보는 최대 내구 3, 정상 귀환 마모 1, 실패 손상 2다. 0보다 작아지지 않으며 실제 귀환/실패 정산의 후보 상태에서 반영한다. 출정 취소·단순 메뉴 열기·이어하기에는 손상을 추가하지 않는다. 비상 탈출 성공은 첫 비교에서 정상 귀환과 같은 후보로 두되, 별도 추가 손실은 Q-021의 기존 사용자 선택을 변경하므로 임의로 붙이지 않는다.

이 후보는 장비 사용 시간·Q 사용 횟수·위험별 충격을 아직 측정하지 않는 단순 비교다. 빈 출정의 즉시 귀환에도 비용 압박을 줄지, 실제 사용량에 비례시킬지는 Q-022의 후속 판단이다. 현재 기본 지형이나 G1 비교 장면에는 적용하지 않았다.

### 선택 수리와 최소 복구 제안

사용자가 선택한 수리 방식을 구체화하기 위한 비교 후보이며 승인된 실행 규칙이 아니다.

- 내구가 남아 있으면 충전·이동·가방을 기존 조건으로 유지한다. 부족 내구만큼 수리할 수 있고, 최소 복구와 완전 수리의 비용을 각각 확인한다.
- 내구 0에서는 바로 출정시키는 대신 최소 복구 경로를 함께 안내한다. 출정 버튼만 막고 돈이나 판매할 물품이 없으면 해결할 수 없는 상태를 만들지 않는다.
- 시험 단가는 내구 1당 5, 출정 가능한 최소 내구는 1을 후보로 둔다. 돈이 최소 복구 비용보다 적을 때 최소 내구까지만 무료 복구하는 안을 비교한다. 전액 수리할 돈이 부족하다는 이유만으로 무료 완전 수리를 제공하지 않는다.
- 기본 장비와 기존 등록/연구 진행은 계속 보유한다. 무료 복구를 돈·판매 가능한 아이템·추가 충전 보상으로 바꾸지 않는다. 이미 최소 내구를 만족하면 반복 요청으로 내구·돈을 늘릴 수 없다.
- 실제 결제는 확인한 복구량에만 발생한다. 돈이 부족한 유료 견적은 전체 거절하고, 지원 적용은 비용 0인 별도 안내로 구분한다. 부채나 음수 보유금은 새로 만들지 않는다.

현재 문서가 요구하는 것은 재출정 보장이지, 모든 실패에 무료 완전 수리나 손실 환급을 제공한다는 뜻이 아니다. 무료 복구 자격·수량·입력 횟수와 반복 실패의 부담은 Q-023에서 검토한다. 건강/부상의 새 출정 초기화는 Q-019의 기존 시험 정책으로 남기며 수리와 묶어 변경하지 않는다.

## 정산과 저장의 구현 계약

귀환 정산의 손상 안내에 현재 내구·이번 손상·정산 뒤 내구를 표시하고 **예상 수리비**를 아직 지불한 비용과 구별한다. 거점에서 수리할 때 확인한 비용을 한 번 차감한다. 출정별 최종 순이익에 나중 수리비를 합산하려면 비용 귀속 기록이 필요하므로, 영수증/정산 이력 없이 과거 순이익을 덮어써서 재정산하지 않는다. 비용 귀속의 구현 범위는 수리 거래 착수 때 함께 정한다.

공통으로 확인할 사항은 다음과 같다.

1. 요청에 현재 거점 상태·대상 장비·복구량·단가·지원 자격을 묶고 확정 직전에 재검사한다. 다른 서비스나 출정으로 상태가 바뀐 오래된 요청은 거절한다.
2. 후보 돈·내구·정산 완료 상태를 한 번 저장한 뒤 실제 상태를 교체한다. 저장 실패는 원본 파일·돈·내구·등록/연구 상태를 유지하며 재시도/취소를 제공한다.
3. 반복된 종료·정산·수리·무료 복구 요청은 손상이나 결제를 중복 반영하지 않는다. 수리 중 출정/가방 변경/다른 서비스 진입을 막는다.
4. 새 내구를 저장할 때 구형 파일은 읽기만으로 덮어쓰지 않는다. 구형 기본 내구는 과거 파일에 없는 손상을 소급 부과하지 않는 방향으로 검토하되 구현 작업에 값을 기록한다. 잘못된 범위·타입·누락 필드·미지원 버전은 부분 복원하거나 자동 덮어쓰지 않는다.
5. 수리 수치·조건은 데이터와 규칙 계층, 비용 표시·확인/취소는 UI, 저장 성공 후 상태 교체는 앱이 담당한다. UI가 직접 돈·내구를 고치지 않는다.

## 후속 구현 검증 계약

| 범위 | 완료 전에 확인할 사례 |
|---|---|
| 손상 | 정상/빈 귀환·실패·비상 탈출, 최소/최대/0 경계, 종료 경합·재시도와 정산 일회 반영 |
| 수리 | 정상/부분/완전 수리, 대상 없음·과도한 복구량·정수 초과·부족 잔액·취소·오래된 견적·중복 확정 |
| 안전망 | 돈 0·판매품 없음·내구 0으로 실제 재출정, 최소 비용 직전/같음/이후, 반복 무료 복구에서 지급 증가 없음 |
| 자원 분리 | 수리가 건강·부상·충전을 치료/충전하지 않음, 기본 장비 소유와 기존 가방·등록/연구 상태 보존 |
| 순환 | 실제 탐험 손상→결과→거점→수리/최소 복구→다음 탐험에서 출정 가능 상태 확인 |
| 저장 | 손상 정산·유료 수리·무료 복구 각각의 쓰기 실패/재시도, 새 프로세스 이어하기, 구형 정상 읽기/전환과 손상·미지원 파일 보존 |
| 표시 | 예상 비용과 결제 비용·감면 구분, 부호 있는 순이익, 마우스/키보드·Esc·두 해상도·낮은 잔액의 재기 안내 |

자동 검사는 선택한 시제품 규칙의 일관성을 입증한다. 수리가 의미 있는 준비 선택인지, 단순 반복 부담인지, 손상량·가격·무료 복구가 공정한지는 사람 평가와 후속 밸런스 범위다. 이 문서로 G4 전체 완료나 수리 기능 구현 완료를 선언하지 않는다.
