# 장비 내구·수리와 재출정 안전망 검토안

## 상태와 목적

`DEV-0405`에서 시작한 **수리 검토안**이다. GDD와 confirmed 경제 규칙의 기존 요구, DEV-0406의 손상 및 DEV-0407의 선택 수리/최소 복구 시험 적용과 최종 미정을 구분한다. 이 문서만으로 제품 규칙을 확정하지 않는다. 미정 항목은 [Q-022·Q-023](../project/open_questions.md#수리-규칙-검토-경계), 다음 작업과 완료 조건은 [개발 인계](../project/development_handoff.md#dev-0407--거점-선택-수리와-최소-복구)가 관리한다.

## 기존 요구와 책임

| 기준 | 이미 정해진 요구 | 이번 문서가 임의 확정하지 않는 것 |
|---|---|---|
| [GDD 4-4](../GDD.md#4-4-실패-손실-설계-결정), [경제 규칙](economy_rules.md#실패-손실과-재기-안전망) | 실패해도 기본 하네스·영구 장비를 잃지 않으며 손상과 수리 비용이 존재한다. 기본 장비와 최소 회복으로 재출정을 보장한다. | 손상량·출정 제한·무료 복구량·면제 조건 |
| [GDD 7-4](../GDD.md#7-4-자원-규칙-설계-결정) | 내구는 거점 수리 비용, 충전은 런 중 선택을 담당한다. | 내구를 충전 잔량으로 대체하거나 수리를 충전 판매로 처리하는 규칙 |
| [경제 규칙의 비용 항목](economy_rules.md#비용-항목) | 수리비는 손상도·장비 유형·정비 성장과 관련하며 수치는 데이터로 관리한다. | 수리비 공식·거래 시점·반올림·최종 가격 |
| [경제 규칙의 정산](economy_rules.md#정산과-순이익) | 실제 화폐 수입과 비용을 구분하고 같은 비용을 중복 차감하지 않는다. | 미확정 예상 수리비를 이미 지불한 비용으로 계산하는 처리 |

영구 장비의 내구가 0이 되더라도 장비 소유 자체를 삭제하는 뜻으로 쓰지 않는다. 세계관상 사고 책임, 길드 대여 가능성, 공방 역할은 수리 수치나 무료 복구의 제공자를 자동 결정하지 않는다. 새 보험·대출·구조자·수리 NPC의 고유명은 만들지 않는다.

## 사용자가 선택한 수리 방식

2026-10-01 사용자가 **거점에서 비용을 확인하고 선택 수리**를 선택했다. [DEC-111](../project/decisions.md#dev-0405-수리-방식-선택)과 confirmed [경제 규칙](economy_rules.md#수리-거래-시점)에 이 거래 시점만 반영했다. 귀환 정산은 손상을 확정하고, 실제 수리비는 거점에서 비용을 확인해 수리를 확정할 때 발생한다. 기존 감정·판매와 확인/취소/저장 실패 재시도의 흐름을 맞춘다.

아래 DEV-0405의 손상량·단가·부분 수리·내구 0의 제한·무료 최소 복구 조건은 별도 제안이며, DEV-0406에서 시험 적용한 손상 범위는 별도 절에서 구분한다. 선택 수리·최소 복구 후보의 DEV-0407 시험 적용도 별도 절에 기록한다. 수리 방식의 선택이나 이 문서의 커밋 승인을 모든 시험 값의 승인으로 처리하지 않는다.

### 손상 상태 제안

첫 비교에서는 기본 하네스 한 개의 내구만 다룬다. 슬롯별 장비 내구·교체 부품·영구 최대 내구 감소는 후속으로 남긴다. 피해가 여러 번 통지되거나 종료 요청이 경합해도 출정 결과 하나에 손상을 한 번만 확정하는 구조를 우선한다.

시험 후보는 최대 내구 3, 정상 귀환 마모 1, 실패 손상 2다. 0보다 작아지지 않으며 실제 귀환/실패 정산의 후보 상태에서 반영한다. 출정 취소·단순 메뉴 열기·이어하기에는 손상을 추가하지 않는다. 비상 탈출 성공은 첫 비교에서 정상 귀환과 같은 후보로 두되, 별도 추가 손실은 Q-021의 기존 사용자 선택을 변경하므로 임의로 붙이지 않는다.

이 후보는 장비 사용 시간·Q 사용 횟수·위험별 충격을 아직 측정하지 않는 단순 비교다. 빈 출정의 즉시 귀환에도 비용 압박을 줄지, 실제 사용량에 비례시킬지는 Q-022의 후속 판단이다. DEV-0405 당시에는 실행에 적용하지 않았으며 DEV-0406의 적용 범위는 아래와 같다.

### DEV-0406 손상 상태 시험 적용

GDD·confirmed Economy Rules·DEC-105·DEC-111과 개발 인계를 함께 대조하고 `MIG-CHG-038`에 먼저 기록한 제한된 구현이다. 위 손상 후보의 최대 3·정상/빈 귀환 및 비상 탈출 성공 1·실패 2를 [`prototype_equipment_wear.tres`](../../src/data/prototype_equipment_wear.tres)에 시험 적용했다. 영구 기본 하네스 한 개만 다루며 실제 손상은 남은 내구 이하로 제한한다. 최종 수치·행동별 마모는 Q-022의 후속 판단이다.

- `HubState`가 현재 내구를 소유하고 `SettlementResult`가 정산 전/후 내구·이번 실제 손상을 복사본으로 제공한다. 미리보기·중복 종료·취소는 내구를 바꾸지 않는다. 후보 정산을 파일에 저장한 뒤 실제 거점에 한 번 반영한다.
- 결과 화면은 이번 손상과 저장 후 내구, 수리비 미차감을 표시하고 거점은 저장된 내구와 현재 출정 가능 상태를 표시한다. DEV-0406 당시에는 가격을 정하지 않아 예상 수리비를 만들지 않았으며 DEV-0407에서 별도로 표시한다.
- 스키마 3의 거점 6필드에 `harness_durability`를 추가한다. 0~3 정수만 읽으며 누락·잘못된 타입/범위·추가 필드·미지원 버전은 거절한다. 스키마 1·2에는 내구 3을 보완하고 1에는 빈 등록 목록도 보완한다. 읽기만으로 파일을 바꾸지 않고 다음 정상 저장 때 전환한다.
- 저장 실패·재시도에서 원본 파일과 돈·내구·가방·보관/등록 원본·연구를 보존한다. 내구 0도 장비 소유를 잃거나 충전·건강·이동 성능을 바꾸지 않는다. DEV-0406 당시 수리/안전망이 없는 단계에서는 돈 0·판매품 없음에도 바로 출정했다. DEV-0407에서는 아래의 무료 최소 복구와 함께 출정 제한을 적용한다.
- 일반 앱 출정과 별도 비상 탈출 검토 공간의 결과에 적용하며 G1 비교 장면의 플레이 데이터는 바꾸지 않는다. 후속 DEV-0407에서 수리·최소 복구·결제·출정 제한을 아래와 같이 연결했다.

이 시험 적용으로 검토안의 `draft` 상태나 수리/안전망 제안을 확정하지 않는다. 검사 근거와 후속 범위는 [DEV-0406 인계](../project/development_handoff.md#dev-0406--장비-손상-상태와-저장)를 따른다.

### 선택 수리와 최소 복구 제안

DEV-0405 당시 사용자가 선택한 수리 방식을 구체화한 비교 후보이며, DEV-0407의 제한된 시험 적용과 최종 제품 승인을 구분한다.

- 내구가 남아 있으면 충전·이동·가방을 기존 조건으로 유지한다. 부족 내구만큼 수리할 수 있고, 최소 복구와 완전 수리의 비용을 각각 확인한다.
- 내구 0에서는 바로 출정시키는 대신 최소 복구 경로를 함께 안내한다. 출정 버튼만 막고 돈이나 판매할 물품이 없으면 해결할 수 없는 상태를 만들지 않는다.
- 시험 단가는 내구 1당 5, 출정 가능한 최소 내구는 1을 후보로 둔다. 돈이 최소 복구 비용보다 적을 때 최소 내구까지만 무료 복구하는 안을 비교한다. 전액 수리할 돈이 부족하다는 이유만으로 무료 완전 수리를 제공하지 않는다.
- 기본 장비와 기존 등록/연구 진행은 계속 보유한다. 무료 복구를 돈·판매 가능한 아이템·추가 충전 보상으로 바꾸지 않는다. 이미 최소 내구를 만족하면 반복 요청으로 내구·돈을 늘릴 수 없다.
- 실제 결제는 확인한 복구량에만 발생한다. 돈이 부족한 유료 견적은 전체 거절하고, 지원 적용은 비용 0인 별도 안내로 구분한다. 부채나 음수 보유금은 새로 만들지 않는다.

현재 문서가 요구하는 것은 재출정 보장이지, 모든 실패에 무료 완전 수리나 손실 환급을 제공한다는 뜻이 아니다. 무료 복구 자격·수량·입력 횟수와 반복 실패의 부담은 Q-023에서 검토한다. 건강/부상의 새 출정 초기화는 Q-019의 기존 시험 정책으로 남기며 수리와 묶어 변경하지 않는다.

### DEV-0407 선택 수리와 최소 복구 시험 적용

GDD·confirmed Economy Rules·DEC-111의 요구와 DEV-0406 인계를 대조하고 `MIG-CHG-039`에 먼저 기록한 시제품이다. [`prototype_economy.tres`](../../src/data/prototype_economy.tres)의 내구 1당 비용 5·출정 최소 내구 1을 적용한다. 최종 단가·반올림/할인·장비별 공식과 지원 자격의 확정은 아니다.

- 현재 부족한 내구 범위에서 부분/완전 수리를 선택한다. 견적에 현재/복구 후 내구·예상 비용·복구 후 잔액 또는 부족액을 표시하고, 확정 시 현재 거점·단가·최소 내구·지원 조건을 다시 검사한다. 잔액 부족이나 오래된 견적은 전체 거절하며 취소는 돈과 내구를 바꾸지 않는다.
- 현재 내구가 출정 최소치보다 낮고 보유금이 그 최소치까지의 유료 수리비보다 적을 때만 **최소 복구 지원**을 제공한다. 현행 값에서는 내구 0·보유금 0~4이면 내구 1까지 비용 0, 보유금 5 이상이면 유료 수리다. 최대 내구까지의 비용이 부족하다는 이유만으로 무료 완전 수리하지 않는다.
- 내구 0에서 출정을 누르면 수리 화면으로 안내한다. 돈을 자동 차감하지 않으며 유료/무료 복구 확정 후 거점으로 돌아가 출정한다. 기본 하네스·충전·건강·가방·등록 원본/연구·보관품은 보존한다. 내구 1 이후 지원을 반복해 더 복구하거나 돈/물품을 받을 수 없다. 다시 탐험해 내구를 잃고 지원 조건을 만족하면 새 최소 복구를 선택할 수 있다.
- `HubState`/`RepairQuote`가 견적·검증·후보 적용, `HubRepairPanel`이 표시/확인/취소, `GameEntry`가 후보 저장 후 실제 상태 교체를 맡는다. 유료/무료 저장 실패에서도 원본 파일과 메모리를 보존하고 재시도·취소를 제공한다. 스키마 3의 거점 6필드를 유지한다.
- 결과의 **귀환 순이익**은 해당 귀환 정산의 실제 판매액·비용만 보여 준다. 완전 수리 예상액은 별도 미지불 견적이다. 수리 화면은 **예상 비용**과 완료된 **이번 지불액**·보유금을 구분하며 다음 귀환에서 이미 낸 비용을 다시 차감하지 않는다. 출정별 비용 귀속/영수증 이력은 후속 G4 범위다.

실제 손상→부분/완전/무료 복구→재출정, 저장 실패/중복/재시도와 새 실행을 검증했다. [DEV-0407 인계](../project/development_handoff.md#dev-0407--거점-선택-수리와-최소-복구)·[검사 기록](../project/project_context.md#dev-0407-거점-선택-수리와-최소-복구-검사)을 따른다. `draft`·Q-022·Q-023은 유지하며 사람 평가와 최종 밸런스는 후속이다.

## 정산과 저장의 구현 계약

귀환 정산의 손상 안내에 현재 내구·이번 손상·정산 뒤 내구를 표시하고 **예상 수리비**를 아직 지불한 비용과 구별한다. 거점에서 수리할 때 확인한 비용을 한 번 차감한다. 출정별 최종 순이익에 나중 수리비를 합산하려면 비용 귀속 기록이 필요하므로, 영수증/정산 이력 없이 과거 순이익을 덮어써서 재정산하지 않는다. DEV-0407은 서비스 완료의 실제 지불액까지만 표시하며 출정별 비용 귀속 이력은 후속으로 남긴다.

공통으로 확인할 사항은 다음과 같다.

1. 요청에 현재 거점 상태·대상 장비·복구량·단가·지원 자격을 묶고 확정 직전에 재검사한다. 다른 서비스나 출정으로 상태가 바뀐 오래된 요청은 거절한다.
2. 후보 돈·내구·정산 완료 상태를 한 번 저장한 뒤 실제 상태를 교체한다. 저장 실패는 원본 파일·돈·내구·등록/연구 상태를 유지하며 재시도/취소를 제공한다.
3. 반복된 종료·정산·수리·무료 복구 요청은 손상이나 결제를 중복 반영하지 않는다. 수리 중 출정/가방 변경/다른 서비스 진입을 막는다.
4. 새 내구를 저장할 때 구형 파일은 읽기만으로 덮어쓰지 않는다. 구형 기본 내구는 과거 파일에 없는 손상을 소급 부과하지 않는 방향으로 검토하되 구현 작업에 값을 기록한다. 잘못된 범위·타입·누락 필드·미지원 버전은 부분 복원하거나 자동 덮어쓰지 않는다.
5. 수리 수치·조건은 데이터와 규칙 계층, 비용 표시·확인/취소는 UI, 저장 성공 후 상태 교체는 앱이 담당한다. UI가 직접 돈·내구를 고치지 않는다.

## DEV-0430 반복 수리 검토와 미적용 제안

DEV-0429에서 사용자는 돈0의 최소 복구는 찾기 쉬웠지만 수입 뒤에는 수리를 해야 출정할 수 있었다고 답했다. MIG-CHG-062 뒤 [실제 근거와 대안 비교](../project/repair_choice_review.md)를 기록했다. 현행 최소 복구1·안전 귀환 마모1의 조합이 매회 수리를 만들며, 승인된 DEC-111의 명시적 거래 확정과 현행 손상/출정 시험값을 구별한다.

후속 최소 시험으로 **안전 귀환의 고정 마모를0으로, 실패 손상은2로 유지**하는 안을 권고했고, 2026-10-15 사용자가 “실패 때만 손상되는 안 시험 (권장)”을 선택했다([DEC-118](../project/decisions.md#dev-0430-수리-반복-보완-시험-방향-선택)). 제한된 시험 방향의 선택이며 최종 수치 확정은 아니다. 현재 제품 데이터는 그대로이며 후속 구현은 다음 경계를 따른다.

- 정상/빈손/비상 탈출 성공을 함께0으로 취급한다. 실패는 남은 내구 이하에서2를 잃는다. 최대3·출정 최소1·내구1당 비용5는 현행 시험값을 유지한다.
- 기존 내구0에는 출정 전 수리가 여전히 필요하다. 과거 손상·결제를 소급 취소하거나 무료 복구하지 않는다. 비용 확인·부분/완전 수리·취소·후보 저장 뒤 일회 결제, 돈 부족 시 최소 복구를 유지한다.
- 현행 지원 자격은 내구0·현금0~4다. 다른 구매를 먼저 해 현금이 줄면 지원 자격이 생기는 순서 유인은 별도 한계다. 이 후보는 자격을 고치거나 지원 정책 전체를 확정하지 않는다. 반복 지원으로 돈/물품·최소치를 넘는 내구를 만들지 않는 계약은 유지한다.
- 내구 차이로 새로운 런 중 성능/충전/건강 차이를 만들지 않는다. 가방·장비 소유·등록/연구와 스키마10을 유지한다.
- 안전 귀환을 계속하면 수리비가 발생하지 않아 수입 축적 속도가 달라질 수 있다. 완전 수리는 실패 후에도 내구가 남는 여유로 비교한다. 반복 실패의 부담·순수입·준비 선택·지원 공정성은 사람 평가와 Q-022/Q-023에 남긴다.

이 제안으로 `draft`나 질문 상태를 승격하지 않는다. 새 동작의 실제 앱·저장·회귀 검사는 DEV-0430 승인 커밋 뒤 후속 DEV-0431에서 수행한다. 이번 메모리 비교는 새 제품 동작의 구현 완료나 재미 검증이 아니다.

## DEV-0431 안전 귀환 마모 제외 시험 적용

2026-10-20 MIG-CHG-063 뒤 DEC-118·DEC-111, GDD 7-4와 confirmed 경제 규칙의 실패 부담/재출정 안전망을 함께 대조해 위 제안의 제한된 시험을 적용했다. [`prototype_equipment_wear.tres`](../../src/data/prototype_equipment_wear.tres)의 **안전 귀환 고정 마모만1→0**으로 바꿨다. 위 DEV-0430의 미적용 표기는 당시 검토 이력이다.

- 정상 귀환·빈손 귀환·비상 탈출 성공은 현재 내구를 유지한다. 사용한 하네스 충전이나 받은 건강 피해로 추가 내구 손상을 계산하지 않는다. 실패는 기존처럼 남은 내구 이하에서2를 잃는다.
- 최대 내구3·출정 최소1·내구1당 수리비5와 비용 확인/부분·완전 수리/취소를 유지한다. 내구1로 안전 귀환하면 수리 없이 다시 출정할 수 있다. 내구3에서 실패하면1, 내구1에서 실패하면0이다.
- 과거 저장의 내구0은0으로 읽고 미지불/지불 수리비 이력도 그대로 유지한다. 소급 복구·환급·재정산을 하지 않으며 스키마10·거점15필드와 구형 저장 전환은 바꾸지 않는다. 결과의 이번 손상0과 기존 손상에 대한 미지불 완전 수리 견적은 서로 다른 값이다.
- 내구0·현금0~4의 무료 최소 복구, 현금5 이상에서 유료 복구하는 시험 조건은 유지한다. 현금9에서 다른 구매를 먼저 해4가 되면 지원받을 수 있는 순서 유인도 이번 변경으로 해결하지 않는다. 지원 반복으로 돈/물품이나 최소치를 넘는 내구를 만들지는 않는다.
- 충전·건강·장비 소유·가방·등록/연구를 보존한다. 실제 결제/손상은 후보 저장 성공 뒤 한 번 반영하며 취소·저장 실패·중복 확정은 기존 상태를 보존한다.

[구현 검사와 실제 앱 근거](../project/project_context.md#dev-0431-안전-귀환-마모-제외-검사)는 메모리 비교와 구별해 기록한다. 안전 귀환 뒤 반복 수리는 줄지만 성공만 이어질 때의 소득 축적 속도, 완전 수리의 가치·실패 부담·지원 공정성과 최종 수치는 Q-022/Q-023 및 후속 사람/장기 경제 판단으로 남긴다. 이 시험은 `draft` 승격·G4 전체 완료·G5 착수 승인이 아니다.

## DEV-0432 내구0 출정과 주의 안내 방향

MIG-CHG-064 뒤 사용자는 수리 부담 자체보다 수리 없이는 출정이 막히는 조건을 문제로 짚었다. 이어 **내구0에서도 출정할 수 있지만 실수를 막을 주의 피드백이 있으면 좋겠다**고 답했다. 승인 방향은 [DEC-119](../project/decisions.md#dev-0432-내구0-출정과-주의-안내-선택)·GDD·confirmed 경제 규칙을 따른다. 현재 제품은 위 DEV-0431 상태이며 아래 변경은 후속 DEV-0433에서 구현한다.

- 내구0을 출정 거절 사유로 삼지 않는다. 손상 상태를 출정 전에 명시하고 선택권을 보장한다. `하네스 내구가 0입니다. 수리하지 않고 출정할까요?`와 `돌아가기 / 그대로 출정`의 확인 화면을 구현 방안으로 삼고, 기본 포커스와 Esc는 돌아가기에 둔다. 구체적 문구/배치는 구현 검토 대상이다.
- 안내를 열거나 닫는 것만으로 수리·결제·내구 복구·도구 예약/소비·출정 번호 증가를 수행하지 않는다. 명시적 계속 선택 뒤에도 다른 준비·저장 조건을 검사한다. 오래된/중복 확정, 경쟁 서비스·일시정지·다른 상태에서의 요청을 거절하고 각 출정에서 현재 내구를 다시 확인한다.
- 출정 허용 기준을 기존 무료 최소 복구 목표1과 분리한다. 현행 `minimum_departure_durability`는 출정 검사와 지원 복구량 양쪽에 쓰이고0을 무효값으로 취급하므로, 값만0으로 바꾸어 지원이나 경제 규칙을 무효화하지 않는다. 지원의 현금 경계0~4·목표 내구1과 유료 수리 단가5는 이번 구현에서 보존한다.
- 안전 귀환 마모0·실패 손상2/0 하한·최대 내구3, 거점 선택 수리·무료 최소 복구의 기존 시험을 유지한다. 내구0의 주의 문구에 구현되지 않은 능력 중지·추가 손실을 쓰지 않는다. 새 성능 불이익·자동 수리·지원 자격 재설계는 이 요구에 포함하지 않는다.
- 기존 내구0 저장을 소급 복구하거나 환급하지 않는다. 확인 전에는 저장을 바꾸지 않고, 확인 후에는 기존 출정 예약/시작·실패 복구/재시도와 정산을 연결한다. 스키마 변경을 전제로 삼지 않는다.
- 내구0·돈0/4/5/9의 주의/취소/계속, 내구1~3의 정상 출정, 실제 내구0 탐험/귀환/실패/재출정, 수리 후 안내 해제와 새 실행·구형 저장, 마우스/키보드·두 해상도 및 기존 회귀를 검증한다.

이 방향은 내구0의 강제 수리를 해제하지만 수리의 가치와 장기 실패 부담까지 해결하지는 않는다. Q-022/Q-023의 최종 밸런스·지원 공정성과 기존 사람 미평가는 남긴다. 이번 문서 검토는 구현 완료나 `draft` 승격이 아니다.

## DEV-0433 내구0 출정과 주의 안내 적용

MIG-CHG-065와 DEC-119에 따라 내구0 출정 제한을 해제했다. 위 DEV-0431의 출정 최소1과 DEV-0432의 미적용 표기는 당시 이력이다. 내구0에서 출정을 누르면 “수리하지 않고 출정할까요?”와 “하네스 내구가 0입니다.”를 표시하고 돌아가기/그대로 출정을 고르게 한다. 기본 포커스·Enter와 Esc는 돌아가기, Tab/방향키로 명시적으로 그대로 출정을 선택할 수 있다. 내구1~3은 기존처럼 바로 출정한다.

- 열기/취소는 돈·내구·도구·출정 번호·저장을 바꾸지 않는다. 상태 전환 시 안내를 해제하며 요청 번호와 준비 스냅샷이 일치하는 확인만 받는다. 안내 중 다른 거점 서비스·가방/목표 변경·중복 출정을 막는다.
- 계속 선택 뒤 도구 수량과 출정 준비/예약/시작 저장을 다시 검사한다. 실패한 예약은 소비 없이 거점으로 돌아오고, 시작/예약 복구 실패는 기존 복구 요청 흐름을 유지한다. 재출정마다 현재 내구0을 다시 확인한다.
- 경제 데이터의 `minimum_departure_durability`를 `minimum_recovery_durability`로 바꿔 무료 지원 목표1만 소유하게 했다. 내구0~3은 출정 가능한 유효 상태다. 현금0~4·내구0의 무료 복구와 단가5 유료 수리·오래된 견적 거절은 유지한다. 새 필드는 저장 스키마의 필드가 아니며 스키마10과 기존 내구/수리 지출을 보존한다.
- 안전 귀환 마모0·실패 손상2/0 하한·최대3·충전/건강·장비 소유는 그대로다. 구현되지 않은 능력 중지나 추가 손실을 경고하지 않는다. 수리 화면에도 수리 없이 출정 가능함을 명시했다.

[검사 기록](../project/project_context.md#dev-0433-내구0-출정-검사)은 자동 앱/저장 검사와 그래픽 확인을 구분한다. 사용자 체감, 수리의 가치·장기 실패 부담과 최종 수치는 Q-022/Q-023의 후속이며 `draft` 승격·G4 전체 완료를 뜻하지 않는다.
