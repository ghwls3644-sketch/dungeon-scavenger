**DEV-0426 — 정산 화면 가독성 개선 구현·검증 및 재검토 의견 기록 완료, 사용자 로컬 커밋 승인.** 손익·이번 입금·현금 변화/정산 후 보유금을 분리하고 비용·도구 상세와 회수품 보기를 열어 읽도록 바꿨다. 계산·가격·세율·스키마10은 유지한다. 전체 **106/106 실행·62개 스모크 장면**, 10사례×두 해상도 화면/조작 검사와 최종31장 캡처를 통과했다. 사용자는 뜻을 이해했다고 답했고 어려운 용어와 몰입감을 후속 검토 의견으로 남겼다. **G4 전체 완료와 G5 착수는 보류**한다. 기준 `7aa117c`, 승인된 로컬2커밋 앞섬·뒤처짐0에서 착수했다. 2026-10-11 사용자가 검토된 DEV-0426 결과의 로컬 커밋을 승인했으며 push하지 않았다. 다음은 **DEV-0427 — 골렘 대응 수단 안내·활용성 검토**다. **정합성 검사: 아직 아님 — G5 완료 후.**

2026-10-11, 기준 DEV-0424 `13db00e`. 착수 fetch에서 main은 승인된 로컬 1커밋 앞섬·뒤처짐 0이고 작업 트리는 깨끗했다. MIG-CHG-057을 먼저 기록했다. GDD 20-3과 [DEV-0424의 여섯 조건·관찰 항목](g4_meta_review.md#dev-0424-보완-완료-조건-검토)을 기준으로 삼는다. 이 문서는 실행 방법과 사람 평가의 근거를 관리하며 가격·세율·성장 규칙을 확정하지 않는다.

## 저장과 실행 방법

[검토 장면](../../tests/fixtures/g4_review_entry.tscn)은 실제 [앱 진입 장면](../../src/app/main.tscn)을 사용한다. 테스트용 래퍼가 앱 준비 전에 진행·설정 저장소를 `.godot/g4-playtests/<세션 ID>/`로 지정한다. 제품의 `src/`·`project.godot`·저장 스키마 10은 변경하지 않는다.

- `initial_progress.json`: 시작 때 준비한 상태. 직접 번 돈·회수한 물품·구매한 성장과 구별하는 근거다.
- `progress.json`, `settings.cfg`: 해당 세션의 실제 진행과 설정. `natural`은 새 게임 전에는 진행 파일을 만들지 않는다.
- `session.json`: DEV 번호·사례·세션 ID·준비 여부·생성 시각. `human_evaluation: pending`은 생성 당시 표식이며 통과 판정은 아래 사람 기록으로 관리한다.
- 같은 ID와 사례로 재실행하면 기존 진행을 보존한다. 사례 불일치·손상·불완전한 기존 디렉터리는 덮어쓰지 않고 거절한다. 거절되면 기존 파일을 보존하고 새 ID를 사용한다.
- 세션 ID는 영문 소문자·숫자·밑줄·하이픈 1~80자이며 경로 이동과 Windows 예약 이름을 거절한다. 한 세션은 한 게임 창에서만 사용한다.

저장소 루트의 PowerShell에서 `GODOT_BIN`을 Godot 4.7.1 실행 파일로 지정한 뒤 실행한다. 아래 ID를 바꾸면 독립 사례를 만들고, 같은 ID를 쓰면 이어서 검토한다.

```powershell
& $env:GODOT_BIN --path . --rendering-method gl_compatibility --log-file .godot/g4-human-economy-01.log res://tests/fixtures/g4_review_entry.tscn -- --g4-case=economy --g4-session=human-20261011-economy-01
```

준비 사례는 타이틀의 **이어하기**를 누른다. 새 게임을 누르면 실제 제품의 초기 상태로 시작하므로 준비 사례 평가와 구분해 기록한다. `natural`은 **새 게임**으로 시작한다. 이동 WASD·조사/회수/귀환 E·가방 Tab·하네스 Q·소음 유인물 F를 안내했다. 구체적인 정산 정답이나 선택의 우열은 먼저 알려주지 않는다.

`.godot/`는 Git 제외 경로다. 다른 환경에서는 새 세션을 만들거나 필요한 검토 저장본을 별도로 보존해야 하며, 저장소 문서만으로 이 로컬 진행이 복원되지는 않는다. 동일 세션을 재실행할 때 로그는 별도 파일명으로 보존한다.

## 준비한 사례와 해석 범위

| 사례 | 시작 상태 | 확인할 경험과 한계 |
|---|---|---|
| `natural` | 제품의 기본 새 게임: 돈0·가방2칸·내구3 | 직접 회수해서 번 돈으로 다음 준비를 바꾸는 순환. 준비 잔액 사례를 자연 수익 경험으로 대신하지 않음 |
| `economy` | 돈100·가방3칸, 다른 상태는 기본값 | 도구/의뢰를 선택하고 일부 사용·반환·정산을 이해하는지 확인. 돈100과 가방 개선은 시험 준비값 |
| `services` | 돈30·가방3칸·미확인 시험 잔류물/고유 유물/핵심 기록물 각1 | 감정·일반품 판매·보호 원본 등록·연구 해설/재열람의 목적. 직접 회수한 물품으로 세지 않음 |
| `growth_before` | 돈0·가방3칸·성장 없음 | 같은 위험에서 장착 선택과 대응 이유를 관찰 |
| `growth_after` | 위와 같은 상태에 관찰 정보 개선·비상 대응 개선 보유 | 같은 상황의 판단/행동 변화 비교. 개선을 번 돈으로 구매했다는 근거는 아님 |
| `recovery` | 돈0·가방3칸·내구0 | 최소 복구와 재출정 접근성. 직접 실패했을 때의 감정·의욕은 별도 확인 |

모든 사례는 기존 시험 데이터와 도메인 검증을 사용한다. 조사·회수·판매·실패를 자동으로 진행시키지 않는다. 비교 전에 정답 행동을 시키지 않고 선택 이유부터 듣는다. 직접 실패·의뢰 미달성·귀환·성장 구매가 발생하지 않으면 해당 경험은 미평가로 남긴다.

## 사람 관찰 기록

### 2026-10-11 첫 경제 사례

- 사용자 발언: “지금 직접 플레이할 수 있어요”. 이는 참여 가능 응답이며 게임 이해도나 완료 승인으로 해석하지 않는다.
- 실행: `human-20261011-economy-01`, `economy`. Godot 4.7.1·OpenGL Compatibility·NVIDIA RTX 4060. 세션 생성 기록은 UTC `2026-10-11T06:21:17`이다.
- 실행 로그: 첫 탐험 실패→Results→Hub, 두 번째 탐험 안전 귀환→Results→Hub→종료가 기록됐다. 화면을 직접 관찰한 기록은 없으며 선택 이유·정산 이해·실패의 원인은 로그만으로 판단하지 않는다.
- 첫 정산의 저장 근거: 실패, 판매 수입0, 선택 의뢰 없음, 유료 도구 구매/감정 사용/유인물 사용 기록0. 준비 잔액100을 유지했다. 이는 복합 비용·세금·의뢰/감정 선택의 이해를 평가하기에 충분하지 않다. 두 번째 출정 성공은 기록상 확인되지만 재출정의 쉬움·의욕은 답변 대기다.
- 제공한 도움: 이어하기 선택, 도구/의뢰를 원하는 대로 고른 뒤 탐험하고 귀환 정산 확인, 기본 조작 안내. 정산 금액의 정답은 알려주지 않았다.
- 질문: 선택한 도구·의뢰와 이유, 정산의 손익·현금 변화·입금에 대한 본인의 설명, 막히거나 헷갈린 화면/조작.
- 두 번째 정산의 저장 근거: `id=2`, `outcome=safe`, 판매80·회수세8, 무료 유인물1개 사용, 유료 도구 구매/감정 사용/의뢰 없음. 돈100→172, 내구0, 보호 원본 `test_g4_artifact`·`test_g4_record` 보관, 미완료 출정 기록 없음. 실제 번 돈72를 확인했지만 이후 준비 개선/수리는 하지 않았으며 준비 잔액100을 자연 수익으로 세지 않는다.
- 사용자 답변: “도구와 의뢰는 기본 베이스에서 딱히 건드리지 않았어”, “정산 부분은 너무 가독성이 떨어져서 눈에 안들어오네”, “골렘이 너무 빨라서 장애물 없는 공간에서 한번 들키면 벗어날 수가 없네 스테미나가 있어서 잠시동안 전력질주 한다거나 다른 대비책은 없으려나?”, “가방칸도 너무 적은 것 같은데 이부분은 아직 테스트 단계니까 넘어갈 수 있을 것 같아”.
- 판정: 정산 가독성은 **보완 필요**. 정산 수치를 본인 말로 설명하는 증거가 없어 계산 이해 자체는 미평가다. 열린 공간의 추적 대응에는 체감 문제가 제보됐다. 가방은 사용자 요청으로 이번 보완 우선순위에서 보류하며 최종 칸 수를 승인하지 않는다.
- 추가 질문과 답변: 추적 중 Q 비상 방전/F 유인물 사용 여부를 물었다. 사용자는 “비상 방전은 무슨 효과 인지 모르겠고 소음 유인물은 벽뒤에서 사용하니까 그 잠깐 동안 어그로를 끌 수 있었지만 다시 원래 장소로 돌아가 버리니 사용하기 까다롭겠다고 생각했어”라고 답했다. 비상 방전의 **효과 전달 부족**, 벽 뒤 유인 성공 뒤의 **활용 여유 부족**을 보완 대상으로 기록한다. Q를 실제 눌렀는지·발동했는지는 아직 확인되지 않았으며 유인 시간을 측정한 것은 아니다.

### 현재 코드와의 대조

아래는 사람 답변 뒤 소스를 읽어 확인한 현황이며 추가 플레이 실험이나 문제 원인의 확정이 아니다.

- [정산 화면](../../src/ui/expedition_results_screen.tscn)은 오른쪽 좁은 열에 손익·현금 변화·손상·긴 내역·저장 안내·버튼을 배치한다. [표시 문자열](../../src/ui/cost_report_text.gd)은 도구 사용/반환/소실, 구매/투자, 회수세와 설명을 한 긴 목록으로 만든다. 이 정보 밀도는 가독성 문제의 보완 대상으로 판단한다. 특정 해상도에서의 잘림을 직접 관찰했다고 주장하지 않는다.
- 실제 [탐험 장면](../../src/app/prototype_exploration.tscn)의 골렘 추적 속도는210, [플레이어](../../src/gameplay/player/player.tscn)는240이다. [짐 감속](../../src/data/prototype_load_movement.tres)을 적용하면 부담192·과적132가 되고 부상 중에는 추가0.9배다. 빈손의 기본 속도만 비교해 사용자의 어려움을 부정하지 않으며 당시 무게/부상을 이 기록으로 특정하지 않는다.
- 기본 장착에는 비상 방전이 있다. [하네스](../../src/harness/harness_controller.gd)의 대상이 골렘이고 충전이 있으면 Q로 충전1을 사용해 기본2초 정지시킨다. 이는 즉시 탈출이나 영구 처치가 아니다. [골렘](../../src/gameplay/hazards/broken_guard_golem.gd)은 벽/닫힌 문으로 시야를 잃으면 마지막 위치를 수색하지만, 플레이어를 직접 보는 동안 F 유인물로 추적을 지울 수 없다.
- 가방에서 선택한 일반품을 [빠른 버리기](../../src/gameplay/inventory/quick_drop_controller.gd)로 버려 적재를 줄일 수 있다. 보호 원본은 대상이 아니며 짐 감소가 모든 지형의 탈출을 보장하지 않는다. [이동 코드](../../src/gameplay/player/player_controller.gd)·입력에는 스태미나/전력질주가 없다.
- 후속 추적 검토에서는 대응 키·대상·범위·충전·발동/정지/복귀가 충분히 드러나는지, 열린 공간에서도 잠깐 멈춤과 거리 이탈의 여유가 있는지 재현한다. 유인 후 관심 유지·수색·원래 순찰 경로 복귀까지 실제 이용 가능한 시간도 확인한다. 스태미나/짧은 전력질주는 사용자 제안으로 남긴다. 새 자원·속도·소음·적재와의 관계를 이번 결과만으로 확정하지 않는다.

## 보완 인계와 다음 진행

다음은 **DEV-0426 — 정산 화면 가독성 개선**이다. 사용자가 정산을 읽기 어렵다고 한 문제를 먼저 해소한다. 손익을 크게 유지하면서 이번 입금·현금 변화·정산 뒤 보유금의 뜻을 짧게 분리하고, 수입/비용 요약과 도구별/물품별 상세를 나눠 처음부터 긴 설명 전체를 읽을 필요를 줄인다. 기존 소모 원가 기준·회수세·의뢰 보상·저장 처리는 바꾸지 않는다. 구체적 범위·검사 조건은 [다음 작업 인계](development_handoff.md#다음-할-일-dev-0426--정산-화면-가독성-개선)를 따른다.

추적 대응은 별도 후속 후보로 보존한다. 비상 방전의 효과·발동 가능 상태·정지/재가동을 알아볼 수 있게 하는 안내와, 벽 뒤 유인 후 우회·회수할 시간이 있는지부터 대조한다. 열린 공간의 경고/대응 시간·적재·시야·충전을 통제해 재현한다. 스태미나 도입은 미승인 제안이며 가방 칸은 이번 우선 보완에서 보류한다. 한 정산 UI 작업에 속도·전력질주·가방 변경을 섞지 않는다.

가독성 보완 후 금액 정답을 미리 알려주지 않은 사람 재평가, 이후 자연 수익으로 준비 개선·서비스 비교·두 성장/장착 비교·최소 복구의 미평가를 이어간다. 추가 사례를 수행하지 않았다는 이유로 보완이 확인된 결과를 전체 합격으로 바꾸지 않는다. **G4 전체 완료와 G5 착수는 보류**하며 Q-004·Q-005·Q-019~Q-030 상태·최종 수치와 G1/G3/G5/G7의 잔여 범위를 유지한다.

## DEV-0426 정산 화면 재평가

DEV-0425의 실제 발언·두 탐험·미평가 판정은 위에 보존한다. DEV-0426은 표시를 개선한 후 유료 도구 일부 사용/반환 사례의 새 화면을 대화에 제시했다. 손익·입금·현금 변화가 무엇이라고 이해되는지, 이전보다 읽기 편한지와 헷갈리는 부분을 질문했다. 화면 자체의 설명 외에 기대 답을 먼저 제공하지 않았다.

사용자는 “뭘 뜻하는지는 이해하겠는데 단어가 너무 어렵지 않나 생각되네, 게임상의 배경도 그렇고 주인공 상태를 짐작해봤을 때 너무 어려운 말을 쓰면 몰입이 아쉽지 않을까? 그냥 내 생각이니까 참고만 해줘”라고 답했다. **의미 이해는 자기보고로 확인했고, 어려운 용어와 몰입감은 후속 문구 검토 의견**으로 기록한다. 금액별 관계를 직접 설명한 답변은 없어 해당 검증을 통과로 세지 않는다. 참고 의견에 따라 이번에 공식 용어나 새 화자 표현을 임의로 확정하지 않는다. 준비한 예시의 돈/물품을 실제 사람이 획득한 것으로 세지 않으며 자동 키보드/마우스 조작과 렌더링31장을 사람 플레이로 세지 않는다. 이 작업의 기술 검증과 사용자 자기보고·후속 문구 의견을 분리한다. 새로 실제 탐험을 실행한 횟수는 0이다.

화면만 다시 열 때는 아래 테스트 장면을 사용한다. 개인 진행/설정 저장소를 읽거나 쓰지 않으며 정산/종료 버튼은 예시 화면만 닫는다. 가능한 사례 이름은 [검토 장면](../../tests/fixtures/results_readability_review.gd)의 CASES를 따른다.

```powershell

```
