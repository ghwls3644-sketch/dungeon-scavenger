## 상태 정의

- `source-frozen`: Git과 해시로 원본 기준이 고정됨
- `copied-active`: 원본과 일치하는 사본이 활성 기준으로 사용됨
- `copied-archive`: 원본과 일치하는 사본이 보관 전용으로 사용됨
- `active-overview`: 동결 원본에서 분리되어 현재 제품·시스템 연결을 관리하는 활성 개요
- `pending-split`: 세부 문서로의 책임별 이관을 기다림
- `verified`: 대상 사본이 원본과 바이트·SHA-256이 일치하거나, 사본이 없는 원본 참고 문서는 현재 파일의 SHA-256이 기록과 일치함

Godot 4.7.1 자동 검사에서 버린 물품과 슬롯 한도로 거절된 물품이 결과에 포함되지 않고, 들고 나온 물품만 개수와 합계에 반영되는지 확인했다. 실제 판매액, 세금·감정료·수리비, 순이익, 저장과 귀환·실패 판정은 구현하지 않았다.

`DEV-0105`에서 불안정한 잔해가 플레이어 진입 뒤 먼지·진동 징후를 먼저 표시하고, 경고 시간 뒤 붕괴·포착 이벤트를 내도록 했다. 플레이어의 하네스 감지기와 컨트롤러는 경고 중인 대상을 선택해 `Q` 안정화에 시험 충전을 사용하며 성공 뒤 붕괴를 막는다. Godot 4.7.1 자동 검사에서 징후가 판정보다 먼저 노출되고, 대응 시 안정화와 충전 갱신, 미대응 시 붕괴와 포착이 각각 발생하는지 확인했다. GDD의 안정화 범위만 사용했으며 `draft` Harness Engineering의 세부 모듈·수치, 실제 피해·부상·실패 판정은 확정하지 않았다.

`DEV-0106`에서 입구 상호작용으로 생환하고 위험 포착으로 실패하는 두 종료 분기를 추가했다. `ExplorationRun`은 활성 상태에서 첫 종료만 받아들이며, 생환한 인벤토리 물품은 기존 `RecoveryResult`로 넘기고 실패한 탐험의 물품은 비워 정산 대상에서 제외한다. 결과 화면은 생환의 회수 목록과 실패의 손실 개수를 구분한다. Godot 4.7.1 자동 검사에서 입구 감지·상호작용, 생환 물품 인계, 위험 징후 뒤 포착·실패, 물품 손실, 실패 회수 결과 부재와 종료 상태 덮어쓰기 방지를 확인했다. 피해·부상, 퇴로 상실 시간, 영구 장비 손상·수리비, 저장과 거점 반영은 구현하지 않았다.
