# 개발 문서 인계 안내

## 목적

동결된 [`게임 개발 단계별 제안서 v0.1`](<../../게임 기획 파일/게임 개발 단계별 제안서 v0.1.md>)의 단계·티켓 구조를 새 공식 Story·Design·Reference 문서와 연결한다. 원본 제안서는 수정하지 않으며, 개발 작업을 시작할 때는 이 안내에서 현재 기준 문서로 이동한다.

## 개발 작업 읽기 순서

1. 저장소 작업 규칙인 [`../../AGENTS.md`](../../AGENTS.md)를 읽는다.
2. 전체 문서 입구인 [`../README.md`](../README.md)에서 현재 단계와 정합성 검사 시점을 확인한다.
3. 엔진·언어·실행 명령은 [`project_context.md`](project_context.md)에서 확인한다.
4. 코드 파일을 추가할 때는 [`module_boundaries.md`](module_boundaries.md)에서 소유 폴더와 의존 방향을 확인한다.
5. 제품과 시스템 연결은 [`../GDD.md`](../GDD.md)에서 확인한다.
6. 작업 규칙은 [`../design/README.md`](../design/README.md)에서 관련 `confirmed` Design 문서를 선택한다.
7. 세계관 이유와 표시 명칭이 필요하면 [`../story/README.md`](../story/README.md), [`../reference/README.md`](../reference/README.md)를 함께 읽는다.
8. 확정·미정 여부는 [`decisions.md`](decisions.md), [`open_questions.md`](open_questions.md)에서 확인한다.
9. 개발 단계와 기존 티켓 ID가 필요할 때만 동결 개발 제안서를 참고한다.

상세 내용이 다르면 최신 사용자 결정, 결정 기록, 해당 책임의 `confirmed` 문서, GDD 개요, 동결 제안서 순서로 판단한다. `provisional` 문서는 문서에 적힌 제한 범위에서만 사용하고 `draft` 문서는 단독 구현 기준으로 사용하지 않는다.

## 사용 제한

- 동결 제안서의 `스토리 정리 v1.5` 직접 참조는 현재 세부 기준으로 사용하지 않는다.
- `게임 기획 파일/`과 `docs/archive/`는 수정하지 않는다.
- Harness Engineering의 장착/성장 비교안을 확정된 규칙으로 취급하지 않는다. 구현 착수 때 GDD·기존 결정·Q-024·Q-025를 함께 읽고 시험 범위를 기록한다.
- `open_questions.md`의 항목을 구현 편의를 이유로 임의 확정하지 않는다.
- 새 기능, 수치, 이름, 코드 ID 또는 저장 키는 해당 개발 티켓 범위와 승인 없이 추가하지 않는다.

## 현재 상태

`DOC-0603`에서 동결 개발 제안서의 단계·티켓 구조를 새 공식 문서 체계에 연결했다. 이 문서는 개발 작업의 탐색과 인계를 돕는 Project 문서이며, 게임 규칙의 상세 기준은 각 `confirmed` Story·Design·Reference 문서가 소유한다.

G-M6는 2026-07-29 정합성 검사에서 통과했다. `DEV-0001`은 Godot 4.7.1, GDScript, Compatibility 렌더러와 Windows PC 우선 기준을 [`project_context.md`](project_context.md)에 기록하고 최소 프로젝트 설정의 headless 초기화를 검증했다.

`DEV-0002`는 실제 모듈 경계 9개와 책임·의존 방향을 [`module_boundaries.md`](module_boundaries.md)에 고정했다. 게임 코드와 장면은 추가하지 않았다.

`DEV-0003`은 `GameState` Autoload와 개발용 메인 장면에서 `Boot`, `Title`, `Hub`, `Exploration`, `Results` 흐름을 연결했다. 중복·현재 상태·허용되지 않은 전환은 중앙 관리자가 거절하며 UI는 상태를 직접 변경하지 않는다.

`DEV-0004`는 GDD 12장의 행동을 `InputMap`에 등록하고 `res://src/infrastructure/input_actions.gd`에 행동 이름과 조회 API를 모았다. 키보드·마우스 기본 입력은 프로젝트 설정 한곳에서만 물리 키를 사용하며 컨트롤러 입력은 `Q-006` 결정 전까지 추가하지 않는다.

`DEV-0005`는 `res://src/core/stable_id.gd`에 공용 안정적 ID 검증을, `res://src/data/content_definition.gd`와 `item_definition.gd`에 표시 이름과 분리된 ID 및 아이템 기본 필드를 추가했다. 아이템 분류는 확정된 네 분류만 사용하고 실제 콘텐츠·밸런스 값과 저장 형식은 추가하지 않았다.

`DEV-0006`은 `res://tests/smoke/game_state_flow_smoke.tscn`에서 기본 상태 흐름을 자동 검증하고, `GameLog`가 상태 전환 로그를 공통 형식으로 남기도록 했다. 메인 개발 장면은 `--dev-state` 인수로 현재 구현된 상태까지 중앙 전환 규칙을 따라 진입한다.

`DEV-0006` 완료 뒤 프로젝트 기반, 모듈 경계, 입력·데이터 기반, 테스트·로그와 다음 개발 순서를 대조했다. 이상이 없음을 확인하고 2026-08-01 사용자의 진행 지시에 따라 G0를 통과했다.

`DEV-0101`은 `res://src/gameplay/player/`에 `CharacterBody2D` 이동과 자식 `Camera2D`를 추가했다. 이동은 `InputActions`를 사용하며 시제품 속도는 플레이어 장면에서 조정한다. `res://tests/fixtures/movement_test_space.tscn`은 이동과 일시정지를 직접 확인하고, `res://tests/smoke/player_movement_smoke.tscn`은 실제 플레이어 장면의 이동 속도 정규화, 카메라 추적과 일시정지 중 정지를 자동 검증한다.

`DEV-0102`는 `res://src/gameplay/interaction/`에 공통 `Interactable`, 감지기와 입력 실행기를 추가하고 `res://src/ui/interaction_prompt.tscn`에 안내 표시를 분리했다. 플레이어 장면은 감지기와 실행기를 조립한다. 시험용 회수품과 문은 같은 인터페이스를 사용하며 자동 검사에서 감지, 안내, 회수와 문 열림·닫힘을 확인한다.

`DEV-0103`은 `res://src/gameplay/inventory/player_inventory.gd`에 획득, 슬롯 한도, 무게 합계·단계, 선택과 일반 버리기 규칙을 추가했다. `res://src/ui/inventory_panel.tscn`은 같은 상태를 표시하고 열려 있는 동안 시간을 멈추며, 일반 버리기 전에 확인을 요청한다. 실제 콘텐츠와 제품 밸런스 값은 추가하지 않았고, `Q-005`가 열려 있으므로 이동 감속과 빠른 버리기도 구현하지 않았다. 시험용 한도·무게 값은 테스트 자료 안에서만 사용한다.

`DEV-0104`는 `res://src/gameplay/recovery/recovery_result.gd`가 현재 인벤토리 물품을 회수 결과로 고정하고 화폐 가치 범위를 합산하도록 했다. `res://src/ui/inventory_panel.tscn`과 `recovery_result_panel.tscn`은 개별 예상 가치와 결과 합계를 표시한다. 고유 유물·핵심 기록물은 화폐 합계에서 제외하고 등록·정보 보상으로 구분한다. 버린 물품과 슬롯 한도로 획득이 거절된 물품이 결과에서 빠지는지는 자동 검사로 확인한다. 판매·비용·순이익, 저장과 귀환·실패 판정은 추가하지 않았다.

`DEV-0105`는 `res://src/gameplay/hazards/`에 먼지·진동 징후 뒤 붕괴하는 불안정한 잔해와 하네스 대상 감지를 추가하고, `res://src/harness/harness_controller.gd`가 `use_harness` 입력과 시험 충전을 사용해 경고 중인 위험을 안정화하도록 했다. 이 범위는 GDD 5장·7장과 티켓 완료 조건을 따르며 `draft`인 Harness Engineering의 빈 상세 규칙을 채우지 않는다. 충전량·비용·경고 시간은 조정 가능한 시제품 값이고, 포착 이벤트를 피해·부상·실패로 바꾸는 처리는 추가하지 않았다.

`DEV-0106`은 `res://src/gameplay/recovery/`에 입구 상호작용, 한 번만 확정되는 탐험 종료 상태와 생환·실패 결과를 추가했다. 생환은 현재 인벤토리를 기존 `RecoveryResult`로 넘기고, 실패는 현재 탐험 물품을 비운 뒤 회수 결과 없이 손실 개수만 남긴다. 시험 공간에서는 불안정한 잔해의 공개 포착 이벤트를 실패 명령에 연결한다. `res://src/ui/exploration_outcome_panel.tscn`은 확정된 결과만 표시하며 종료나 손실을 계산하지 않는다. 피해·부상, 퇴로 상실 시간, 장비 손상·수리비, 저장과 거점 정산은 후속 범위로 남겼다.

`DEV-0107`은 `res://tests/fixtures/core_loop_playtest_space.tscn`에서 기존 이동·상호작용·인벤토리·위험·하네스·귀환·실패 모듈을 안전 경로와 위험 보상 경로로 조립했다. 시험 슬롯이 찬 뒤 고가 잔재를 위해 기존 물품을 버리는 적재 선택, 하네스 충전을 써서 붕괴를 안정화할지 돌아갈지의 위험 선택, 같은 입구 생환과 미대응 실패를 한 장면에서 재현한다. 자동 검사는 안전 생환, 위험 대응 생환과 미대응 실패를 모두 확인한다. 시험 값은 제품 밸런스로 확정하지 않으며 출시 코드는 이 장면을 참조하지 않는다.

`DEV-0107` 완료 뒤 2026-08-31 G1 정합성 검사에서 Godot 4.7.1 프로젝트 초기화, 메인 장면과 기존 스모크 검사 8개가 모두 통과했다. 단계 1의 기존 개발 작업에는 회귀가 없지만 GDD 15-2의 별도 조사·미확인 물품·고장 난 경비 골렘·하네스 분석과 비상 방전은 아직 구현되지 않았고, GDD 20-1의 주관적 재미·안도감과 `Q-004`·`Q-005`는 사람 플레이테스트가 필요하다. 사용자는 `DEV-0201 — Boot와 임시 타이틀`보다 G1 누락 범위를 먼저 보완하도록 지시했다.

## G1 보완 개발 작업

GDD 15-2의 누락 범위와 사람 검토 항목은 다음 순서로 한 작업씩 진행한다. 기존 단계 1 코드를 임의로 확장하지 않고 각 작업의 제외 범위와 자동 검사 자료를 분리한다.

## DEV-0110 — 하네스 분석과 비상 방전

## DEV-0203 — 귀환 정산과 거점 반영

2026-09-09 사용자 작업 재개 지시에 따라 임시 정산을 구현한다. GDD 4-3·4-4·10-3·10-4·15-3, [경제 규칙](../design/economy_rules.md)의 수입·비용·순이익 분리와 실패 후 재출정, [아이템 규칙](../design/item_rules.md)의 감정·판매 보호·안전 귀환 상태를 기준으로 삼는다. 완료 조건은 회수품의 임시 판매 결과가 거점 보유금에 한 번만 반영되고 같은 실행에서 다시 출정할 수 있는 것이다.

실제 판매가는 `EconomyRule` 리소스의 안정적 ID별 시험 값으로 분리한다. 현재 시험 맵의 확인된 폐품 세 종류에 기존 예상 범위 하한과 같은 10·30·80을 명시하며, 예상 범위를 자동 판매가로 변환하지 않는다. 값이 없는 물품, 미확인 물품과 판매 보호 물품은 판매하지 않고 감정·보호 상태와 공개된 위험 정보를 보존해 거점에 보관한다. 등록·연구 보상으로 돈을 추가하지 않는다.

이번 단계에 유료 서비스·소모품 구매·장비 마모가 없으므로 비용은 발생하지 않는다. 세율·감정 비용·수리비·거래처 보정·통화 명칭과 제품 수치를 확정하지 않는다. 현재 시험 가격과 비용 없음은 임시 정산 연결에만 사용하며 G4 경제 작업에서 실제 비용과 서비스를 연결한다. 감정 UI 문구에 관한 `Q-017`도 미결정으로 유지한다. 거점에는 보유금과 미판매 회수품을 표시하되 감정·등록·꺼내기·저장 기능은 추가하지 않는다.

정산 전에는 기존 거점 상태를 바꾸지 않고, 확인 후 해당 출정 번호의 정산을 한 번만 반영한다. 이전 출정 결과나 중복 클릭은 돈·보관품을 중복 지급하지 못하게 한다. 실패하면 현재 물품 손실만 유지하며 기존 보유금·보관품·가방 선택은 유지한다. 다음 출정은 기존 시제품의 빈 가방·시작 충전·시험 배치를 사용한다. 이는 최종 충전 복구·장비 안전망·방문 상태 규칙을 확정한 것이 아니다.

구현·검증을 완료했다. `SettlementResult`는 고정한 회수 결과와 가격 리소스에서 판매액·비용·순이익과 보관품을 만든다. `HubState`는 출정 번호로 미리보기·확정·취소를 관리하고, 확인 전에는 보유금·보관품을 바꾸지 않으며 이전 출정·중복 반영을 거절한다. `GameEntry`는 결과 화면의 요청을 연결하고 `Results → Hub` 전환 뒤 이전 탐험 결과를 정리한다. 거점에 보유금과 미판매 물품의 공개 정보가 표시된다.

Godot 4.7.1에서 스모크 장면 15개와 출정·타이틀의 추가 분기 네 개, 프로젝트 초기화·기본 실행·개발 진입 5종이 통과했다. 독립 정산 검사는 예상가와 실제 판매가 분리, 보호·미확인·미설정 가격, 복사본 변경, 과거 출정 재처리·취소, 실패·빈손 귀환과 보관품 유지·새 게임 초기화를 확인한다. 실제 입력의 출정 검사는 각 조건에서 세 번 출정하며 돈·보관품 반영, 중복 클릭, 재출정 가방·충전 초기화와 실패 후 기존 재산 유지를 검사한다. 1152×648 정산·거점·실패 화면을 렌더링했다. 실행 명령은 [프로젝트 컨텍스트](project_context.md#귀환-정산-자동-검사)에 있다.

## DEV-0205 진행 저장과 이어하기

GDD 4-3~4-5·14-5와 [아이템 규칙](../design/item_rules.md)의 안정적 ID·감정·확보 상태, [경제 규칙](../design/economy_rules.md)의 실패 후 기존 재산 유지에 따라 현재 시제품의 거점 상태를 저장한다. 돈, 보관품의 ID·감정 여부·알려진 위험 안내, 가방 선택과 다음 출정 번호를 복원한다. 현재 하네스 구성·시작 충전은 변경할 수 없는 기존 기본 조건으로 복원하며 새 장비·성장·등록·방문별 영구 상태는 만들지 않는다.

설정과 분리한 `user://progress.json`의 버전 1·콘텐츠 버전 `g2_prototype_1`에 거점 복원 상태를 기록한다. 돈·출정 번호는 큰 정수도 손실되지 않도록 십진 문자열로 저장한다. 물품 정의는 기존 시제품의 값·이름을 그대로 독립 리소스로 옮겨 맵과 저장 복원이 같은 ID 목록을 사용하게 한다. 알 수 없는 ID·잘못된 타입·범위·버전의 기록은 부분 복원하지 않고 이어하기를 막으며 원본을 보존한다.

새 게임의 거점 진입, 준비 변경과 정산 확정 때 후보 상태를 먼저 저장한 뒤 실행 상태에 반영한다. 쓰기 실패는 기존 상태·파일을 유지하고 다시 시도할 방법을 안내한다. 기존 기록을 새 게임으로 바꾸는 경우에는 게임 내 확인 창을 거친다. 탐험·정산 대기 상태는 저장하지 않으며 재실행 시 마지막 저장된 거점에서 시작한다. 새 게임은 설정 파일을 바꾸지 않는다. 백업·마이그레이션·중단용 저장과 타이틀 복귀 흐름은 이번 범위에 추가하지 않는다.

완료 조건은 실제 정산·준비 상태 저장 후 별도 프로세스의 이어하기 복원, 이어서 출정 가능한 상태, 미확인 정보 보호, 실패·빈손 귀환과 중복 정산 방지, 기록 없음·손상·다른 버전·쓰기 실패·새 게임 취소 및 교체 확인이다.

구현·검증을 완료했다. 새 게임·준비 변경·정산은 후보 상태의 파일 저장 성공 후 반영하고, 실패는 기존 상태를 보존하며 같은 동작으로 재시도할 수 있다. 실제 입력의 세 번 출정을 저장한 뒤 별도 프로세스에서 돈 40·미확인 보관품 1개·가방 3칸·위험 안내를 복원하고 다시 출정·실패 정산해 기존 재산이 유지됨을 확인했다. 큰 정수의 정확성, ID와 표시 이름 분리, 보호·감정 상태, 손상·버전·알 수 없는 ID·기록 소실, 새 게임 취소·Esc·교체와 설정 파일 보존도 검사했다.

## DEV-0301 — 탐험 지도 기본 표시

지도 정보의 방문 간 저장과 실패 시 보존 여부는 아직 정하지 않는다. 이번 시제품의 방문 표시는 현재 탐험 동안만 유지하며 새 출정은 새 관찰 상태를 만든다. 기존 진행 파일, G1 자료와 최종 밸런스는 변경하지 않는다. 검사는 독립 지도 상태·실제 이동·키보드/마우스·가방 확인 창 전환·종료/재출정·화면 배치와 기존 기능을 포함한다. **정합성 검사: 아직 아님** — 다음 정기 검사는 G5 완료 후다.

## DEV-0302 — 열린 길·막힌 길의 지도 표시

`DEV-0301`은 사용자 승인으로 `61df626`에 커밋했다. 2026-09-12 다음 작업 진행 지시에 따라 GDD 5-5·12-4와 [반복 탐험 규칙](../design/repeat_exploration.md)의 지도 정의·현재 방문 상태를 기준으로 통로 관찰을 추가한다.

이번 범위는 기존 시험 구역의 위쪽 연결·가운데 연결·우회 연결 세 짧은 직선 구간이다. 가운데 연결은 공식 경로와 실제 중앙벽의 어긋남을 보여 주는 시제품 가정이며 지형·보상·위험 배치를 바꾸지 않는다. 통로 ID·양 끝점·이동 여유 반경은 고정 정의에 두고, 실제 통행 여부와 마지막 관찰 결과는 분리한다.

플레이어가 양 끝점 중 하나에 시험 거리 96 px 이내로 접근하고 관찰 시야를 벽이 가리지 않으면 실제 충돌 형상으로 열린 길·막힌 길을 확인한다. 폭 없는 선만 검사하지 않고 기존 플레이어 반경 14 px의 이동 여유도 확인한다. 한 번 본 상태는 현장을 떠나면 유지하고 가까이서 다시 확인할 때 갱신한다. 지도를 여는 동작으로 멀리 있는 실제 상태를 읽지 않는다. 열림은 해당 짧은 구간의 물리 통행 표시이며 위험이 없다는 보장이 아니다.

지도에는 미확인 점선, 열림 실선·원, 막힘 X와 문자 표기를 함께 사용한다. 확인한 통로 수·열림·막힘 개수를 표시하고 기존 방문·출구·현재 위치와 메뉴 일시정지를 유지한다. 출정 전·정지 중·탐험 종료 후에는 관찰을 중지하며 새 탐험은 새 관찰 상태로 시작한다. 동적으로 벽을 넣거나 없애는 상황은 검사 장면에서만 재현한다.

완료 검사는 실제 이동·물리 통행과 지도 일치, 먼 상태 비공개·시야 차단·재관찰·좁은 통로·일시정지·종료/새 출정과 화면 확인을 포함한다. 개인 표식, 잔여 구역 단서·개방, 방문 간 저장과 실패 시 정보 보존 여부는 후속 범위다. **정합성 검사: 아직 아님** — 다음 정기 검사는 G5 완료 후다.

`DEV-0302`에서 가까이서 시야가 확보된 통로의 실제 충돌과 플레이어가 지날 폭을 확인해 미확인·열림·막힘을 지도에 표시했다. 멀리서 바뀐 상태는 공개하지 않고 재접근하면 갱신하며, 출정 전·지도 정지 중·탐험 종료 후에는 관찰하지 않는다. 기존 지형과 진행 저장은 유지했다. 새 통로 검사를 포함한 스모크 장면 19개와 추가 분기·기본 실행·저장 순환을 합쳐 42개 실행이 통과했다. 1152×648 실제 화면에서 글자 겹침을 보완하고 미확인·관찰 후 표시를 확인했다. 구현·검증 결과 검토 후 사용자가 로컬 커밋을 승인했다.

## DEV-0303 — 지도 개인 표식

`DEV-0302`는 사용자 승인으로 `9eba0c1`에 커밋했다. 2026-09-12 사용자 진행 지시에 따라 GDD 5-5·12-4와 [반복 탐험 규칙](../design/repeat_exploration.md)의 지도 상태 구분을 기준으로 개인 표식을 구현한다. 변경 범위는 `MIG-CHG-012`에 먼저 기록했다.

지도에서 표식 편집을 켜고 빈 곳을 클릭하면 번호가 붙은 마름모 메모를 추가하며, 표식 근처를 다시 클릭하면 해당 표식을 삭제한다. 지도 바깥 여백은 입력 대상에서 제외한다. 메모는 미방문 위치에도 놓을 수 있으나 방문 여부·통로 관찰·잔여 구역 발견을 바꾸지 않는다. 번호는 이번 탐험 안의 표식 식별용이며 콘텐츠 ID나 저장 키가 아니다.

표식의 위치·추가·삭제·복사본 조회는 현재 탐험의 지도 상태가 소유한다. 화면은 지도 좌표 변환·표식 선택·공개 명령 전달을 맡는다. 지도를 닫았다 열거나 가방과 전환해도 표식은 유지되고 편집 모드는 꺼진다. 편집 중에도 시간이 멈추며 출정 전·탐험 종료 후에는 입력을 받지 않는다. 새 출정에는 빈 표식 상태를 만든다.

검사는 실제 클릭·경계와 잘못된 좌표·추가/삭제·관찰 상태 분리·재열기·가방 전환·화면 크기 변경·시간 정지·종료/새 출정·표시를 포함한다. 기존 지형·통로 관찰·진행 파일·G1 자료는 유지한다. 방문 간 지도 저장, 실패 시 정보 보존, 발견 단서·개방과 최종 UI·수치는 이번 범위에서 확정하지 않는다. **정합성 검사: 아직 아님** — 다음 정기 검사는 G5 완료 후다.

**DEV-0303 — 지도 개인 표식 구현·검증 완료.** 지도 편집을 켜고 클릭하면 번호가 붙은 마름모 표식을 추가·삭제한다. 표식은 이번 탐험의 개인 메모로서 재열기·가방 전환 동안 유지되고, 방문·통로 관찰·발견 상태를 바꾸지 않는다. 새 출정은 빈 표식으로 시작한다. 실제 클릭·화면 크기 변경·입력 차단·일시정지·종료/재출정과 상태 분리를 확인했으며, 스모크 장면 20개와 추가 분기·기본 실행·저장 순환을 포함한 전체 43개 실행 및 실제 화면 3장이 통과했다. 구현·검증 결과 검토 후 사용자가 로컬 커밋을 승인했다.

## DEV-0307 — 무게 단계의 이동 영향

**DEV-0307 — 무게 단계의 이동 영향 구현·검증 완료.** 기존 인벤토리의 정상·부담·과적 단계를 실제 이동과 HUD에 연결했다. 정상 100%·부담 80%·과적 55%는 조정 가능한 시험 값이며 과적에서도 이동한다. 무게 경계값의 실제 속도·이동 거리, 대각선 속도 제한, 일반·빠른 버리기 후 회복, 슬롯 거절·메뉴 정지·벽 충돌·귀환/실패·새 출정을 검사했다. ## DEV-0308 — 적재 이동 소음과 골렘 반응

## DEV-0309 — 소음 유인 도구

`DEV-0308 — 적재 이동 소음과 골렘 반응`은 `0fd1ec2`에 로컬 커밋했다. 사용자 진행 지시에 따라 GDD 2-2·6-1·9-2~9-4·12-1~12-4, `DEC-009`·`DEC-103`·`DEC-104`·`DEC-108`, [현재 방문 상태](../design/repeat_exploration.md)와 [아이템 데이터 경계](../design/item_rules.md)를 대조했다. `MIG-CHG-018`에 이번 범위와 시험 값을 먼저 기록했다.

현재 출정 장면에 소음 유인 도구 한 종류를 연결한다. 마우스 위치를 향해 F 한 번으로 투척하며, 최대 거리나 벽에 의해 실제 착지 위치가 제한된다. 목표·비행·착지를 간단한 표식으로 보여 주고, 유효한 투척 시작에만 한 개를 소비한다. 시험 지급 2회·거리 24~300 px·벽 여유 8 px·비행 0.3초·청취 320 px·착지 표식 1초는 별도 데이터의 조정 값이다.

골렘은 착지 순간 위치만 소리로 전달받는다. 플레이어 직접 탐지·방전·이미 시작한 경보 경고는 유인으로 덮어쓰지 않는다. 그 밖의 순찰·의심·수색과 시야 대상 없는 위치 추적은 유인 위치를 확인하고 수색 후 순찰로 돌아간다. 유인 자체는 이동 소음 누적을 늘리거나 비우지 않는다. 시제품의 직선 거리 수신과 기존 이동을 유지하며 벽 차음·길찾기를 확장하지 않는다.

메뉴가 열리면 비행과 표식 시간이 멈추고 새 투척 입력은 차단한다. 키 반복·누른 상태의 재개·중복 사용·잘못된 목표·소진·출정 전·종료 후를 검사한다. 귀환/실패는 비행을 취소하고 새 출정은 시험 지급 수량으로 시작한다. 수량은 현재 장면에만 존재하며 도구 구매·준비 선택·인벤토리 적재·하네스 충전·진행 파일과 기존 G1 비교 조건을 바꾸지 않는다. HUD에는 사용법·남은 수량·투척/골렘 반응을 표시한다.

완료 검사는 실제 F 입력·마우스 조준·거리 제한·벽·착지 후 반응·직접 탐지와 경보 우선순위·메뉴·수량 소진·중복 방지·귀환/실패·새 출정과 실제 화면을 포함한다. 검사 명령과 결과는 [프로젝트 컨텍스트](project_context.md#dev-0309-소음-유인-도구-검사)에 기록한다.

**DEV-0309 — 소음 유인 도구 구현·검증 완료.** 마우스로 목표를 지정하고 F로 유인물을 던지며, 실제 벽·닫힌 입구와 투척 거리로 착지를 제한한다. 유효한 투척 시작에만 한 개를 소비하고 수량·투척·착지·골렘 반응을 표시한다. 골렘의 직접 탐지·방전·경보 경고를 보존하면서 소리 위치만 추적하던 상태는 유인 위치 확인으로 바꾼다. 반복 입력·동시 사용·메뉴 정지·포커스·소진·귀환/실패·새 출정과 자원 분리를 검증했다. Godot 4.7.1 스모크 장면 26개와 추가 분기·기본 실행·저장 순환을 합친 전체 49/49 실행, 실제 화면 3장과 문서·원본 해시·공백 검사가 통과했다. 출정당 2회와 거리·시간은 시험 값이며 도구 구매·준비 선택·벽 차음·길찾기·최종 밸런스는 후속 범위다. 구현·검증 결과 검토 후 사용자가 로컬 커밋을 승인했다.

## DEV-0310 — 골렘 시야 차단과 재탐지

`DEV-0309 — 소음 유인 도구`는 `c178ae7`로 원격에 반영했다. 2026-09-21 사용자 진행 지시에 따라 GDD 2-2·9-1~9-5·12-4, `DEC-103`·`DEC-104`·`DEC-108`과 [현재 방문 상태](../design/repeat_exploration.md#상태-계층)를 대조하고 `MIG-CHG-019`에 범위를 먼저 기록했다. G3의 시야·비전투 대응을 다루며 정렬·필터는 GDD의 MVP 이후 범위로 유지한다.

현재 출정의 골렘은 기존 탐지 반경 안에서도 실제 벽·닫힌 문에 시야가 가리면 플레이어를 직접 탐지하지 않는다. 같은 반경 안의 개폐·이동을 계속 확인하고, 시야를 잃으면 마지막으로 본 위치를 수색한다. 가려진 뒤의 위치를 몰래 갱신하지 않으며 재노출은 경고부터 시작한다. 방전 복귀도 시야를 재검사한다. 기존 소음·유인물과 경보는 순간 위치 정보로 동작하며 시야 차단을 소리 차단으로 해석하지 않는다.

G1 비교 자료를 보존하기 위해 시야 차단은 현재 출정 장면에서만 사용한다. 새로운 시야각·길찾기·벽 차음·문 배치·도구·건강/피해 규칙·저장 형식·최종 수치는 이번 범위가 아니다. 기본 분석과 시야 상실 안내로 지형을 이용한 대응을 설명한다.

완료 검사는 실제 이동과 벽·문 개폐, 반경 안에서의 가림·재탐지, 마지막 위치 보존, 경고 시간·반복 통지, 방전 뒤 숨기/재노출, 소음·유인·경보 우선순위, 지도·가방 정지, 출정 전·귀환/실패·새 출정과 화면 및 기존 전체 검사를 포함한다. **정합성 검사: 아직 아님** — 다음 정기 검사는 G5 완료 후다.

## DEV-0404 — 등록 조건에 따른 연구 해설 해금

### 완료 결과

- `ResearchDefinition`·`ResearchCatalog`에 안정적 ID, 필요한 등록 원본 ID 조합과 해설을 둔다. 빈 조건·중복 ID·없는 원본·일반 판매품 참조를 거절한다. 시험 항목은 기존 기록물 하나의 등록과 기존 원본 두 개의 등록으로 구분한다.
- `ResearchProgress`는 실제 등록 목록만 읽어 해설을 공개한다. 회수 중·거점 보관·감정 완료만으로는 열리지 않는다. 잠긴 항목은 공통 제목/안내만 UI에 전달하며 숨은 제목·본문·조건 ID를 전달하지 않는다.

- 손상 주기·출정 제한·지원 조건·반복 확인 입력 중 실제 관찰을 설명하는 요인을 비교해 최소 보완안을 제시한다. 수리 폐지/자동 결제/무료화나 새 자원·아이템·최종 가격을 선행 적용하지 않는다. 기존 결정 변경이 필요하면 구체적 대안과 영향까지 정리해 사용자 판단을 받는다.
- 완료 조건: 현재 규칙과 체감의 관계, 유지/보완 권고, 검증 사례와 구현 범위를 명확히 인계한다. 저장 일회 처리·무료 복구 악용 방지·돈0 재출정·부분 수리/취소·다른 자원 분리를 유지할 기준도 포함한다.

Q 안내·안정화의 사용자 보류, 정산/거점의 그래픽 이후 다듬기, 정밀 분석/성장/금액·서비스 역할의 미평가와 G1/G3/G5/G7 잔여를 유지한다. 이 인계는 G4 통과·G5 착수 승인이 아니다.

## DEV-0430 — 내구·수리와 재출정 선택 검토

**DEV-0430 — 내구·수리와 재출정 선택 검토·시험 방향 선택 기록 완료, 사용자 로컬 커밋 승인.** 최소 복구1과 안전 귀환 손상1의 조합이 매회 수리를 만드는 원인임을 확인했다. 별도 메모리 비교56사례를 통과했고, 사용자가 안전 귀환 마모0·실패 손상2 유지의 제한된 시험을 선택했다(DEC-118). 비용 확인/수리 확정과 돈 부족 시 최소 복구는 유지하며, 현금 기준 지원의 구매 순서 유인은 별도 한계로 남긴다. 제품에는 아직 미적용이다. 다음은 **DEV-0431 — 안전 귀환 마모 제외 시험 적용**으로, DEV-0430 승인 커밋 뒤 착수한다. G4 전체 완료·G5 착수와 기존 사람 미평가/보류는 유지한다. **정합성 검사: 아직 아님 — G5 완료 후.**

MIG-CHG-062 뒤 [검토 결과](repair_choice_review.md)와 [Design의 미적용 제안](../design/repair_rules.md#dev-0430-반복-수리-검토와-미적용-제안)을 정리했다. 사용자 발언은 필수 수리 경험이며 무료화/폐지 요구로 확대하지 않는다. DEC-111의 비용 확인/확정과 현행 손상·지원 시험값을 분리했다. 경계8·완전 수리2·손상32·반복12·구매 순서2의56사례는 도메인 비교이며 새 사람 플레이/실제 앱 구현 검증이 아니다. 제품 소스558개와 이전108/108 근거는 유지한다.

### 다음 할 일: DEV-0431 — 안전 귀환 마모 제외 시험 적용

2026-10-15 사용자가 “실패 때만 손상되는 안 시험 (권장)”을 선택했다. [DEC-118](decisions.md#dev-0430-수리-반복-보완-시험-방향-선택)에 제한된 시험 방향을 기록했다. 검토된 DEV-0430의 로컬 커밋 승인 뒤 한 작업으로 착수한다. 방향 선택은 커밋 승인이나 최종 수치 확정으로 확대하지 않는다.

- 안전 귀환의 고정 마모만1→0으로 바꾼다. 정상/빈손/비상 성공을 같게 처리하고 실패2·최대3·출정 최소1·단가5·현금 부족 시 최소 복구는 현재 시험값을 유지한다. 새 능력 제한·자동 결제·전면 무료화·지원 자격 재설계를 추가하지 않는다.
- 과거 내구0에는 수리가 여전히 필요하다. 저장 스키마10·과거 결제/손상을 보존하고 소급 복구·환급·재정산하지 않는다. 표시와 기존 검사에서 안전 귀환 손상1에 의존하는 기대값을 확인한다.
- 실제 출정→안전 귀환→수리 없이 다음 출정과 실패→수리/지원→재출정, 정상/빈손/비상·내구0~3·돈0/4/5/9를 검사한다. 부분/완전/취소·부족액·오래된 견적·중복 확정·저장 실패/재시도·새 실행과 자원 분리를 보존한다.
- 현금9에서 유인물 구매 후 현금4가 되어 지원을 받는 현행 순서 차이를 기록한다. 지원 반복으로 추가 내구/돈/물품을 만들지 않는 계약과 구매 순서 유인의 미해결을 구별한다. Q-023의 자격 설계를 묶어 확정하지 않는다.
- 완료 조건은 구현·필요 회귀와 이전 동작 대비 수리 반복 감소의 실제 앱 근거다. 경제 체감·완전 수리의 가치·최종 수치의 사람 판단은 별도다. Q 안내/안정화 보류·정산/거점의 그래픽 이후 다듬기·다른 미평가를 반복 질문하거나 G4 통과로 올리지 않는다.
