# G2 제품 순환 검사 기록

## 현재 결과

**2026-09-09, 승인된 G2 시제품 순환 범위의 기술 검사 통과.** `DEV-0201`~`DEV-0206`의 6개 작업을 완료했다. 같은 체크리스트를 두 번 실행해 총 78개 프로세스가 모두 통과했다. 엔진 오류·경고·스크립트 오류는 없었으며 인증서 오류 예외 옵션도 사용하지 않았다. 결과 검토 후 사용자가 커밋을 승인했다.

다음 개발 단계는 **G3 탐험 확장**이다. 다음 작업을 시작할 때 기존 위험·하네스·인벤토리 구현과 지도·잔여 구역의 미구현 범위를 대조해 첫 작업을 작게 정한다. 이번 결과만으로 G3 구현을 시작하지 않는다. 정기 단계 검사는 다음 기록 지점인 G5 반복성 완료 후 진행한다. 그동안에는 각 변경에 필요한 기능 검사를 수행한다.

G2 통과는 현재 승인한 시제품의 실행·저장 순환에 대한 판단이다. GDD 15-3의 정산·판매·수리 중 실제 수리·비용·장비 손상은 `DEV-0203`에서 확정한 임시 비용 없음과 후속 G4 범위를 유지한다. 감정·등록·연구·장비 성장, 방문별 영구 변화, 타이틀 복귀, 고급 옵션·저장 복구도 해당 후속 범위에 남아 있다. G1 사람 평가와 `Q-004`·`Q-005`가 통과하거나 결정되었다는 뜻은 아니다.

## 반복 가능한 실행 방법

저장소 루트의 PowerShell 7 이상에서 실행한다. `GODOT_BIN`은 기존 [엔진 준비 방법](project_context.md#godot-준비)에 따라 Godot 4.7.1 console 실행 파일을 가리켜야 한다.

```powershell
& ./tests/run_g2_checks.ps1 -GodotBin $env:GODOT_BIN
```

기본값은 두 번 반복·프로세스당 30초 제한이다. 모든 실행은 새 프로세스를 사용하고, 설정·진행을 조작하는 검사는 임시 저장 경로를 주입한다. 기본 실행 검사는 실제 메인 장면을 부팅하므로 기존 사용자 설정·진행을 읽을 수 있으나 타이틀에서 조작 없이 종료해 저장하지 않는다. 로그와 `results.json`은 출력된 임시 폴더에 남는다. 다른 보관 위치는 `-OutputRoot`로 지정하며 그 아래에 매번 새로운 하위 폴더를 만든다. 기존 기록을 삭제하거나 덮어쓰지 않는다.

`-Repetitions 1`은 개별 변경 후 빠른 확인에 사용할 수 있지만 이 관문의 반복 통과 근거는 기본 두 번이다. `-AllowCertificateStoreWarning`은 제한된 실행 환경에서 정확히 `Failed to read the root certificate store` 한 종류만 예외로 기록하는 선택 사항이다. 기본은 모든 엔진 오류·경고를 실패로 처리하며 이번 공식 결과는 예외 없이 통과했다.

종료 코드 0과 마지막 `PASS G2`를 함께 확인한다. 각 프로세스는 종료 코드 0·예상 통과 표시·오류 없음·시간 제한 충족을 모두 만족해야 한다. 중간에 실패하면 뒤의 검사를 멈추고 종료 코드 1과 부분 결과를 남긴다. 결과 JSON의 `passed`, `completed_repetitions`, `checks`, `flows`에서 실패 지점을 확인할 수 있다. 실행 중 `src`·`tests`·`project.godot` 파일이 바뀌어도 실패한다.

## 체크리스트와 결과

| 확인 항목 | 근거 | 결과 |
|---|---|---|
| Godot 4.7.1과 프로젝트 초기화 | 버전 실행·headless editor 초기화 각 1회 | 통과 |
| 기존 탐험·하네스·물품·상태·정산·설정·진행 검사 | 스모크 장면 17개 × 2회 | 통과 |
| 이어하기·종료와 출정 조건 | 기존 추가 분기 4개 × 2회 | 통과 |
| 잘못된 설정·다른 설정 버전 | 추가 조건 2개 × 2회 | 통과 |
| 진행 교체·손상·다른 버전·알 수 없는 ID·파일 소실 | 추가 조건 5개 × 2회 | 통과 |
| 기본 실행과 개발 상태 5종 | 6개 실행 × 2회 | 통과 |
| 같은 파일을 사용하는 설정·탐험·이어하기 순환 | 아래 4개 프로세스 × 2회 | 통과 |
| 합계 | 공통 2개 + 반복당 38개 × 2회 | **78/78 통과** |

각 반복의 통합 순서는 다음과 같다.

1. 타이틀 옵션에서 전체 화면·창 크기 1600×900 선택·음량 37을 저장하고 프로세스를 종료한다.
2. 같은 설정을 읽은 새 게임에서 실제 이동·회수 입력으로 생환 정산→재출정 실패→빈손 생환을 진행한다. 돈 40·미확인 보관품 1개·가방 3칸·다음 출정 번호 4를 저장한다.
3. 새 프로세스의 이어하기로 같은 거점과 위험 안내를 복원한다. 설정 파일을 준비용 값으로 덮어쓰지 않으며 음량 적용도 확인한다. 재출정·실패 정산 후 기존 돈·물품과 다음 번호 5를 확인한다.
4. 다시 실행해 옵션의 전체 화면·창 크기·음량과 유효한 이어하기 상태를 확인한다. 설정 파일의 해시는 1번 이후 같고, 진행 파일의 해시는 옵션 확인 전후에 같아야 한다.

두 반복 모두 최종 상태가 돈 40, 가방 3칸, `test_g1_unknown` 1개·미확인, 위험 안내 `희미한 진동이 느껴집니다.`, 다음 출정 번호 5로 같았다. 설정과 진행 파일의 최종 해시도 반복 간 일치했다. UI 확인용 입력은 자동 입력이며 사람 플레이 평가로 집계하지 않는다.

## 검사 실행기의 실패 판정

실제 Godot 프로세스를 사용하는 임시 보조 검사로 다음 여섯 조건을 확인했다. 통과하지 못한 실행이 성공처럼 기록되는 것을 막기 위한 검사다.

| 조건 | 기대한 판정 | 결과 |
|---|---|---|
| 통과 표시·종료 0·오류 없음 | 성공 | 일치 |
| 통과 표시 없이 종료 0 | 실패 | 일치 |
| 오류를 출력한 뒤 통과 표시·종료 0 | 실패 | 일치 |
| 경고를 출력한 뒤 통과 표시·종료 0 | 실패 | 일치 |
| 통과 표시 뒤 종료 7 | 실패 | 일치 |
| 종료하지 않고 제한 시간 초과 | 실행기가 시작한 프로세스만 종료하고 실패 | 일치 |

보조 검사는 임시 GDScript와 별도 로그를 사용했고 제품 코드나 기존 사용자 Godot 실행에는 영향을 주지 않았다. 제한된 환경의 보조 검사에서는 인증서 오류 한 종류만 예외로 기록했으며, 위 78개 제품 검사 결과에는 적용하지 않았다.

## 근거와 범위 대조

[자동 실행 원본 JSON](g2_automated_results.json)에 실행별 인수·통과 표시·종료 코드·시간·오류, 반복별 최종 상태와 파일 해시를 보존했다. 실행 시 기준 HEAD는 `6387914`이며 이 작업의 검사 코드 변경이 포함된 작업 폴더였다. `source_tree_sha256`는 실행 전후 소스 파일 바이트가 같았는지 확인하는 값으로, 문서 수정은 포함하지 않는다. 새 환경의 줄바꿈 차이까지 동일한 커밋임을 보증하는 값으로 사용하지 않는다. 원본 JSON의 절대 임시 경로는 당시 로그 위치이며 새 실행은 별도 폴더를 만든다.

| 기준·책임 | 대조 결과 |
|---|---|
| GDD 4-1·4-3~4-5 | 시제품의 실행·거점·탐험·정산·저장 순환, 실패 후 기존 재산 유지와 거점 복원에 일치 |
| Item Rules의 ID·감정·보호 경계 | 안정적 ID로 복원하고 미확인 정보·보관품 상태를 유지 |
| Economy Rules와 승인된 DEV-0203 범위 | 실제 판매가와 예상가를 분리하며 비용 없음·보관 처리는 기존 시제품 범위 유지 |
| GDD 14-2·14-5와 모듈 경계 | 제품 코드는 변경하지 않고 검사 실행기·검사 경로 연결만 추가 |
| GDD 16-3 | 초기화·기존 검사·수용 기준·오류·저장 영향·재현 절차 확인 |
| 후속 범위 | G3 탐험 확장, G4 실제 경제·수리·성장, G5 영구 반복 상태, G6 복구·제품 기능과 G1 사람 평가 유지 |

별도의 광범위 재검사를 다시 완료 조건으로 추가하지 않는다. 새로운 변경이나 실패가 없으면 이 기록을 G2 기술 완료 근거로 사용한다. **정합성 검사: 지금 — 이번 작업에서 G2 결과를 확인했고 통과했다.**
