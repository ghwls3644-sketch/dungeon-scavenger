# 내구·수리와 재출정 선택 검토

## 결론과 범위

현재 제품은 [DEV-0431 시험 적용](#dev-0431-시험-적용-후-현재-상태)을 완료했다. 아래 DEV-0430의 “현행/미적용”은 당시 비교 기준이며, 현재 동작은 안전 귀환 마모0·실패 손상2다. DEV-0432에서 확인한 [사용자 의도](#dev-0432-사용자-의도-정정과-출정-방향)를 [DEV-0433에서 구현](#dev-0433-출정-선택-적용)했으며 다음은 DEV-0434 — 내구0 출정 안내 사람 검토다.

**DEV-0430 — 내구·수리와 재출정 선택 검토·시험 방향 선택 기록 완료, 사용자 로컬 커밋 승인.** 현재 손상과 수리 조건은 기록된 시험 규칙대로 작동한다. 내구1의 최소 복구와 안전 귀환마다 손상1이 합쳐져 매번 수리하는 흐름을 만든다. **안전 귀환의 고정 마모를 0으로 바꾸고 실패 손상2·명시적 수리 확정·돈 부족 시 최소 복구는 유지하는 제한된 시험**을 권고했고 사용자가 이 시험 방향을 선택했다([DEC-118](decisions.md#dev-0430-수리-반복-보완-시험-방향-선택)). 제품에는 아직 적용하지 않았으며 후속 구현이 필요하다.

기준 커밋은 DEV-0429 `ebf3bd2`, 착수 fetch 뒤 로컬6커밋 앞섬·뒤처짐0이다. 이번 작업은 기존 사람 자료와 코드 대조, 별도 메모리 비교56사례 및 문서 검토다. 새 사람 플레이·GUI 실행은0회다. 기존 사람 답변을 다시 질문하지 않는다. **정합성 검사: 아직 아님 — G5 완료 후.**

[당시 자료](dev0429_playtest_results.json)의 마지막 비용 기록은 현금9에서 수리5, 판매40·세금4를 거쳐 현금40·내구0이다. 이 자료는 실제 유료 수리를 입증하지만 앞선 탐험의 모든 수입/지출 이력을 복원하지는 않는다. 이 DEV-0429 답변만으로 수리 폐지·전면 무료화나 대체 규칙을 선택했다고 해석하지 않는다. 이후 DEV-0430의 비교안을 보고 사용자가 별도로 제한된 시험 방향을 선택했다.

### 준비 순서에 따른 지원 자격

현금9·내구0에서 수리부터 하면 현금4·내구1·유료 유인물0이다. 반대로 기존 무료2개에 유료1개를 추가 구매하면 현금4가 되어 최소 복구 지원을 받을 수 있고, 결과는 현금4·내구1·유료 유인물1이다. 두 순서를 실제 도메인에서 대조했다. 사용자가 이 순서를 사용했다는 관찰은 없으며 UI에서 자연스럽게 찾는지도 평가하지 않았다.

이는 지원 조건이 현재 현금만 보기 때문에 생기는 **구매 순서 유인**이다. 지원 버튼을 반복해 무한히 돈/물품을 받는 오류와 구별한다. 현금0이어도 재출정을 보장하려면 단순히 보유 물품까지 재산으로 합산해 지원을 막는 수정도 신중해야 한다. 안전 귀환 마모0은 이 자격 차이를 없애지 않는다. 후속 구현에서 현행 차이를 숨기거나 확정된 악용 방지 정책으로 표현하지 않으며, 지원 자격의 재설계는 Q-023의 별도 판단으로 남긴다.

## 후속 범위와 검증

다음은 **DEV-0431 — 안전 귀환 마모 제외 시험 적용**이다. 2026-10-15 사용자가 “실패 때만 손상되는 안 시험 (권장)”을 선택했다. DEC-118의 승인 범위는 이 제한된 시험 방향이며, 2026-10-15 사용자가 “커밋”으로 검토된 DEV-0430의 로컬 커밋을 별도로 승인했다. push하지 않는다. 승인 커밋 뒤 한 작업으로 구현한다. 가격·최대 내구·지원 자격과 최종 밸런스를 함께 확정하지 않는다.

- 정상/빈손/비상 성공의 마모를 함께0으로, 실패2·남은 내구 제한은 유지한다. 저장 스키마10·과거 손상/비용 이력은 그대로 읽고 재계산/환급하지 않는다.
- 현재 안전 귀환 손상1에 의존하는 검사 예상값과 검사 자료를 점검한다. 출정→귀환→다음 출정의 실제 앱 흐름에서 최소 수리의 반복이 줄었는지 확인한다. 이번 메모리 계산을 그 구현 검증으로 대체하지 않는다.
- 기존 내구0·돈0/4/5/9, 최소/완전/취소/부족액·오래된 견적·중복 확정, 정상/빈손/비상/실패와 새 실행을 확인한다. 저장 실패/재시도에서도 결제·손상은 한 번만 반영한다.
- 무료 지원 반복으로 추가 내구·돈·물품을 만들지 않음, 구매 순서에 따른 현행 자격 차이, 건강/충전/장비 소유·가방/등록/연구 보존을 확인한다. 자격을 바꾸는 설계를 함께 끼워 넣지 않는다.
- 소득별 순수입·다음 준비의 여지와 실패 부담은 후속 사람/밸런스 판단으로 남긴다. 새 권고안의 재미·공정성은 미평가다.

Q 안내·안정화는 사용자 보류, 정산/거점 다듬기는 그래픽 뒤 재검토를 유지한다. 정밀 분석·성장 차이·금액/서비스 역할의 본인 설명과 G1/G3/G5/G7 잔여도 유지한다. 이 검토 완료는 G4 전체 통과 또는 G5 착수 승인이 아니다.

## 검증 근거

[비교 기록](dev0430_review_results.json)은 경계8·완전 수리 대조2·손상32·반복12·구매 순서2의56사례를 담는다. 성공한 새 Godot 프로세스는1회이며, 최초 실행의 검사 스크립트 파싱 실패는 성공으로 세지 않는다. 복제한 규칙의 `return_damage`만0으로 계산했고 파일과 공유 원본 규칙은 유지했다. 재현용 스크립트 원문·명령·로그 해시를 결과에 보존한다.

제품 소스558개는 DEV-0428 전체108/108 검사 때와 동일하다. 기존 저장 실패/재시도·새 프로세스·UI 취소 검증을 재사용하며 전체108건을 이번 실행에 더하지 않는다. [문서 검사](dev0430_document_results.json)는 활성 링크·동결 원본·이전 결과·질문 상태·검사표·제품 소스 보존과 공백을 검사한다.

## DEV-0431 시험 적용 후 현재 상태

2026-10-20 DEC-118의 선택을 실제 제품 데이터에 적용했다. 위 DEV-0430 표의 현행/미적용 후보는 비교 당시 이력이다. 현재는 정상/빈손/비상 성공의 마모0·실패 손상2이며 [제한된 적용 규칙](../design/repair_rules.md#dev-0431-안전-귀환-마모-제외-시험-적용)을 따른다.

[전체108/108 및 실제 앱 근거](project_context.md#dev-0431-안전-귀환-마모-제외-검사)에서 한 번 최소 수리 뒤 안전 귀환3회, 무료 최소 복구 뒤 안전 귀환3회의 직접 재출정과 내구/잔액 보존을 확인했다. 이전 도메인 계산을 앱 실행으로 바꾸어 센 것이 아니라 새 실행이다. 과거 내구0·수리 지출을 소급 수정하지 않고 비용 확정·실패 복구/저장을 유지한다.

구매 순서 유인은 해결하지 않았으며 수입 축적·완전 수리의 가치·최종 수치는 여전히 검토 대상이다. 다음 DEV-0432에서 바뀐 수리 반복과 다음 준비의 사람 경험만 확인한다. Q/안정화·그래픽 이후 다듬기 보류와 G4 전체 완료 보류를 유지한다. DEV-0431은 구현·검증 완료, 사용자 로컬 커밋 승인이며 정합성 검사: 아직 아님 — G5 완료 후.

## DEV-0432 사용자 의도 정정과 출정 방향

사용자는 수리 부담이 원래도 크지는 않았고 수리하지 않으면 출정이 막히는 점이 문제였다고 정정했다. 이후 내구0에서도 출정할 수 있게 하되 실수로 나가지 않도록 주의 피드백이 있기를 원한다고 답했다. 이전 DEV-0430의 반복 수리 감소 권고는 당시의 대안 비교이며 사용자 문제를 모두 해결했다고 보지 않는다.

[DEC-119](decisions.md#dev-0432-내구0-출정과-주의-안내-선택)는 내구0 출정 허용과 사전 주의 안내다. 표에서 내구0 출정을 당시 권고하지 않았던 판단은 이력으로 보존하고, 후속 DEV-0433에서 [새 요구의 수용 기준](../design/repair_rules.md#dev-0432-내구0-출정과-주의-안내-방향)을 구현한다. 현재 제품은 안전 귀환 마모0·내구0 출정 제한 상태다.

실제 사람 기록은 안전 귀환1회와 이후 수리10 지출·최종 돈26/내구3을 보여 준다. 귀환 당시에는 내구1이라 수리 없이 출정할 수 있었지만, 수리 선택 이유와 두 번째 출정·실패 경험은 미평가다. 이 차이로 사용자의 정책 선호를 부정하거나 UI 오해로 단정하지 않는다. 수리의 가치·실패 부담·최종 경제는 Q-022/Q-023에 남기고 새 능력 불이익을 임의 추가하지 않는다.

## DEV-0433 출정 선택 적용

DEC-119에 따른 [내구0 안내 후 선택 출정](../design/repair_rules.md#dev-0433-내구0-출정과-주의-안내-적용)을 구현했다. 이전 출정 최소1/필수 수리는 이력이며 현재 동작은 안내에서 그대로 출정을 선택하면 내구0으로도 출정하는 것이다. 무료 복구 목표1과 기존 가격·지원 조건은 분리해 보존한다. 안내의 사람 확인은 DEV-0434이며 수리의 가치·장기 경제/지원 공정성은 Q-022/Q-023에 남긴다.
