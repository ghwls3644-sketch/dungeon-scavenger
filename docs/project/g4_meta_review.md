# G4 거점·경제·성장 완료 조건 검토

## 현재 판단

**DEV-0420 — 회수세 최소 규칙 정리 문서 작성·검증 완료, 사용자 로컬 커밋 승인. G4 전체 완료 보류.** 판매 과세·의뢰 보상 전액 지급의 방향은 DEC-116이며 [검토안](../design/recovery_tax.md)에 미적용 계산·저장 제안과 Q-029를 정리했다. 다음은 **DEV-0421 — 회수세 정산·보고 연결**이다. 2026-10-10 사용자가 검토 결과의 로컬 커밋을 승인했으며 push하지 않았다. 코드에 세금은 아직 없으며 휴대용 감정·사람 평가도 남는다. 정합성 검사는 아직 아니며 G5 완료 후다.

DEV-0419의 98/98 결과와 여섯 완료 조건 판정은 현재 코드에 대한 기존 근거다. DEV-0420에서 새로운 게임 실행이나 기능/사람 평가 통과를 추가하지 않았다. 아래 DEV-0419 및 DEV-0416~0418의 “다음 작업”은 당시 인계다. 현재 후속 범위는 [DEV-0420 인계](development_handoff.md#dev-0420--회수세-최소-규칙-정리)를 따른다.

## DEV-0419 보완 완료 조건 검토

2026-10-10, 기준 DEV-0418 93d2b5a. 시작 fetch에서 main과 origin/main이 같고 작업 트리가 깨끗함을 확인했다. MIG-CHG-051을 먼저 기록했다. 이번 검토는 기능·가격·저장 형식을 바꾸지 않으며 기존 승인 DEC-111~115와 Q-022~Q-028의 시험 한계를 유지한다.

### 선택 의뢰로 보완된 범위

[선택 의뢰 계산](../../src/meta/expedition_objective.gd)·[거점 상태](../../src/meta/hub_state.gd)·[앱 연결](../../src/app/game_entry.gd)을 [DEC-115](decisions.md#dev-0417-거점-목표의뢰-방식-선택), GDD 4-2, confirmed 아이템·경제·반복 탐험 규칙과 대조했다.

- 자유 수색 또는 의뢰 하나를 고르고, 현재 가방의 확인된 비보호 일반 폐품만 진척에 포함한다. 버리면 진척이 줄며 미확인/잔재/원본/도구/과거 보관품은 실적으로 세지 않는다.
- 일반·기존 비상 안전 귀환의 실제 회수 결과로 다시 판정한다. 시험 조건 2개·보상 10은 판매 대금과 별도이며, 미달성도 기존 판매·보관·발견 처리를 유지한다. 실패/시작 후 미정산 종료의 보상은 0이다.
- 선택·예약·시작·정산·복구는 후보를 저장한 뒤 확정한다. 정산은 보상·지갑·선택 초기화·최근 보고·도구 반환·내구·다음 기간을 함께 반영한다. 구형 1~7은 보상 없는 스키마 8 읽기로 보완하며 읽기만으로 원본 파일을 쓰지 않는다.
- 최소 목표/의뢰의 기술 공백은 보완됐다. 정식 납품 의뢰, 평판·허가, 장기 의뢰 이력, 최종 반복 보상 경제까지 구현한 것은 아니다. 구체적 시험 계약은 [DEV-0418 적용 범위](../design/expedition_objectives.md#dev-0418-선택-의뢰-시험-적용)를 따른다.

| 시드·구역별 풀·원본 회수 뒤 방 변화 | 원본 ID 제외는 있으나 현재 PrototypeExploration에는 시드/구역 풀로 방문 상태를 만드는 구조가 없음 | GDD 16-1의 G5와 confirmed 반복 탐험 책임. G4 기술 검증으로 대체하지 않으며 G5는 이번에 시작하지 않음 |
| 정식 의뢰·연구/NPC 문장·분량 | 현재 의뢰와 연구 데이터는 기능 검사용이며 정식 이야기/지도 완성이 아님 | G7 콘텐츠 책임. 기존 Story·Reference·Q-018의 허가 경계를 유지하고 새 이름·서사를 만들지 않음 |

회수세를 먼저 다루는 이유는 판매·보상·순이익·보관품 판매·구형 최근 보고의 돈 흐름에 직접 영향을 주기 때문이다. 휴대용 감정은 확정 요구로 남기되 같은 작업에 섞지 않는다. 이러한 후속 분류는 새 제품 정책의 승인이나 현재 기능의 삭제가 아니다.

### 사람 평가와 자동 근거의 경계

GDD 20-3의 다섯 관점을 그대로 유지한다. 아래 항목은 **미평가**이며 기술 검사 통과를 합격으로 바꾸지 않는다.

| 관점 | 비교할 상황·기록할 결과 |
|---|---|
| 총액·비용·순이익 이해 | 의뢰 달성/미달성, 추가 도구 구매 후 일부 소비/반환에서 판매·보상·손익·현금 변화를 본인 말로 설명하는지 |
| 노련함과 성장 선택 | 같은 위험에서 관찰 정보 개선/비상 대응 개선을 각각 사용하고 선택 이유와 판단 차이를 설명하는지 |
| 실패 뒤 재출정 | 돈 부족·내구 손상 뒤 최소 복구/도구 기본분으로 재출정할 수 있고 재기가 막힌다고 느끼지 않는지 |
| 감정·연구·판매 역할 | 미확인 물품의 정보 확인, 돈 획득, 원본 등록/해설을 구분하는지 |
| 장착 선택의 실제 영향 | 두 모듈 조합과 개선 효과가 단순 수치 차이를 넘어 다른 대응을 만드는지 |

의뢰 없는 출정의 자유, 매번 선택하는 번거로움, 미달성 부분 성공의 납득도 함께 확인한다. 관찰 자료가 없으므로 사람 플레이 수·선호·최종 수치·15~25분 분량을 새로 기록하지 않는다. 기존 G1/G3 및 Q-004·Q-005·Q-019~Q-028의 잔여를 유지한다.

**DEV-0419 검토 완료, G4 전체 완료 보류.** 최소 의뢰 공백은 해소됐지만 회수세·휴대용 감정 기능과 사람 판단이 남는다. 후속 한 작업은 **DEV-0420 — 회수세 최소 규칙 정리**이며 [인계](development_handoff.md#다음-할-일-dev-0420--회수세-최소-규칙-정리)를 따른다. 코드·세율·저장 형식은 이번에 바꾸지 않았다. 2026-10-10 사용자 로컬 커밋 승인, push하지 않음. **정합성 검사: 아직 아님 — G5 완료 후.** G4 완료 조건 검토와 정기 검사 시점은 구분한다.

## DEV-0416~0418 검토 이력

아래의 의뢰 없음·스키마 7·다음 DEV-0417/0418/0419는 당시 이력이며 최신 상태는 위 DEV-0419다. 이전 판단과 검사 기록을 보존한다.

### DEV-0416 당시 판단

**DEV-0416 — G4 완료 조건 검토 완료. G4 전체 완료는 보류한다.** 감정·판매·등록/연구·선택 수리·장착/영구 개선·소음 유인물 준비·비용 표시가 거점 준비→출정→귀환/실패→다음 준비·저장/이어하기에 연결되어 있다. 현재 소스로 전체 자동 검사를 다시 실행해 **95/95건** 통과했다. 다만 출정 목표·최소 길드/의뢰의 범위가 구현과 인계에 빠져 있고, GDD 20-3의 이해도·성장 선택·재기 체감은 사람 평가가 남아 있다.

다음 작업은 **DEV-0417 — 거점 목표·의뢰 최소 범위 정리**다. 현재의 고정 목적지 안내로 충족하는 부분과 추가로 필요한 목표/의뢰 흐름을 먼저 문서로 정한다. 이번 검토에서 의뢰 보상·세금·허가 아이템이나 기능을 새로 만들지 않으며 G5 착수를 선언하지 않는다. 기술 검증이 끝난 기존 기능을 반복 개발할 필요도 없다.

기준 커밋은 DEV-0415 `27c0684`다. 착수 fetch 뒤 로컬 15커밋 앞섬·뒤처짐 0·깨끗한 작업 트리를 확인했고 `MIG-CHG-048`을 먼저 기록했다. 2026-10-09 사용자가 이번 검토 결과의 **로컬 커밋을 승인**했으며 push하지 않았다. **정합성 검사: 아직 아님 — 다음 정기 검사는 G5 완료 후.** G4의 완료 조건 검토와 기록된 정기 검사 시점은 구분한다.

## 자동 근거의 범위

- `hub_upgrade_smoke`에는 실제 회수 두 번으로 구매 자금을 얻고, 새 발견의 실패/생환과 보유 저장을 확인하는 경로가 있다. 효과 비교에서는 위치·장착을 준비하고 골렘의 자동 이동/접촉을 멈추거나 상태/타이머를 직접 구성한다. 관찰 정보 표시, 골렘 대응 2→3초, 문 고정 6→8초의 차이를 검증하지만 자연 플레이의 선호나 난도를 증명하지 않는다. 잔액 60/120을 직접 구성하는 구매 경계도 별도로 존재한다.
- `cost_flow_smoke`는 실제 앱의 준비·구매·F 사용·회수·입구 귀환·정산을 두 차례 실행한다. 손익/현금/잔액은 +25/+20/120 → +25/+30/150이다. 앱 재생성 검사는 같은 프로세스에서 테스트 전역 상태를 초기화하는 방식이며 운영체제의 새 프로세스 검사와 구분한다.
- `cost_boundary_smoke`의 이번 실행은 10종 거래마다 후보 저장을 두 번 실패시킨 후 성공하는 검사다. 외부에서 저장 전후에 강제 종료한 20개 경계는 아래 DEV-0415의 기존 근거이며 이번에 재실행한 것으로 세지 않는다.
- G3의 완전 퇴로 상실/비상 탈출은 별도 고정 공간을 실제 앱에 연결한 검사다. 일반 출정의 모든 지형이나 정식 지도에 해당 사건이 배치되었다는 뜻이 아니다.
- 자동 조작 시간·준비된 경계·대표 화면 확인을 사람 플레이 수, 재미, 최종 가격 또는 15~25분 런 길이의 승인으로 바꾸지 않는다.

## 다음 작업의 제한

**DEV-0417 — 거점 목표·의뢰 최소 범위 정리**에서는 GDD 4-2·10-2와 관련 Story/Design/Reference·DEC/Q를 따라 목표 확인, 진행/완료, 귀환/실패/이어하기에 필요한 최소 계약을 정리한다. 목표 선택을 강제 과제로 만들지, 의뢰 수입을 추가할지 등 새로운 제품 판단이 필요하면 비교 가능한 안을 먼저 마련하고 사용자 판단을 받는다. 과거의 직접 구매+무료 발견 선택을 연구/의뢰 선행 조건으로 바꾸지 않는다.
