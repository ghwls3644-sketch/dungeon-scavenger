# 골렘 대응 수단 안내와 활용성 검토

## 결론과 범위

DEV-0427은 DEV-0425의 실제 사람 의견을 현재 코드·통제된 재현과 대조하는 작업이다. **방전 효과/가능 조건을 행동 전에 알기 어렵고, 유인 지점까지의 이동이 수색 시간을 소모하는 문제가 확인됐다.** 다음 구현은 **DEV-0428 — 골렘 대응 안내·유인 조사 흐름 보완**으로 인계한다. 이번에는 제품 코드·속도·시간·장착/충전·가격·스키마10을 변경하지 않는다.

기준은 DEV-0426 `5a3fa05`다. 2026-10-12 fetch 후 main은 승인된 로컬3커밋 앞섬·뒤처짐0·깨끗한 작업 트리였고 MIG-CHG-059 뒤 재현 검사를 추가했다. 정기 정합성 검사는 G5 완료 후다. G4 전체 완료·G5 착수와 최종 밸런스는 보류한다.

## 기준과 사용자 관찰

- [GDD 2-2](../GDD.md#2-2-약하지만-무력하지-않은-수색꾼), [7장](../GDD.md#7-1-정의-설계-결정), [9-2~9-5](../GDD.md#9-2-전투-규칙-설계-결정)는 정면 공격 대신 방전·유인·문·우회·짐 버리기로 대응하도록 한다. 정보 부족으로 억울하게 실패하게 하지 않고, 하네스는 잠시 지연하는 생존·회수 장비로 유지한다.
- [장착·개선 시험](../design/harness_engineering.md#dev-0411-구매발견-혼합-시험-적용)은 기본 안정화+비상 방전, 충전 공유, 비상 개선의 정지 시간 가산과 관찰 개선의 정밀 분석 잔여 시간 표시를 구분한다. 이 draft를 새 동작의 단독 권한으로 사용하지 않는다.
- [아이템 규칙](../design/item_rules.md)·[반복 탐험](../design/repeat_exploration.md), [공식 하네스 명칭](../reference/glossary.md#하네스-엔지니어링)과 [문체](../story/07_tone_and_writing_guide.md)를 보존한다. 기본 효과 설명을 숨은 정보/정밀 분석의 보상과 혼동하지 않는다.
- [DEV-0425 관찰](g4_playtest_review.md#사람-관찰-기록): 사용자는 열린 공간에서 추적 이탈이 어렵다고 했고, 방전 효과를 모르며 벽 뒤 유인 후 복귀가 빨라 활용이 까다롭다고 했다. 당시 실제 무게·부상·Q 발동 여부·유인 거리를 특정할 자료는 없다.
- [DEV-0426 의견](g4_playtest_review.md#dev-0426-정산-화면-재평가): 뜻은 이해하지만 어려운 말이 배경/주인공의 몰입에 어울리지 않을 수 있다는 참고 의견이다. 이번 안내 제안은 효과·다음 행동을 쉬운 말로 먼저 전달하며 새 화자 설정이나 공식 명칭 변경을 확정하지 않는다.

## 재현 방법과 한계

[전용 검사](../../tests/smoke/golem_response_review_smoke.gd)는 현재 출정 장면과 HubState의 기본 준비를 사용한다. 위치·짐·추적 시작 상태를 준비한 뒤 실제 물리 이동과 Q/G 입력을 실행한다. 방전은 장착/충전/거리·벽·재가동·개선 상태를, 유인은 현재 출정의 골렘 설정을 복사한 별도 직선 통로에서 골렘의 유인 API를 호출해 이동/수색을 측정한다. 직접 시야/벽 뒤 반응은 실제 GolemHearing 경로를 사용한다. 유인물의 F 투척·비행·벽 앞 착지·잔량은 기존 noise_lure_smoke와 전체 회귀에서 검사한다.

15개 준비 사례이며 자연 플레이·새 사람 평가가 아니다. 열린 직선 도주 검사는 이동 소음을 분리해 끄고 시작 간격을 준비했다. 이를 실제 던전의 모든 지형·소음·부상 조합에서 탈출이 보장된다는 뜻으로 읽지 않는다. 부상은 기존 이동 배수0.9의 코드/기존 회귀 근거이며 이번 세 도주 사례는 부상 없는 상태다. 사람 반응 시간이나 초심자 조작 성공률은 측정하지 않았다.

실제 렌더링은1152×648에서 기존 안내를 관찰하는 캡처14장이다. 화면 개선 후 두 해상도 수용 검사를 통과했다는 뜻이 아니다. 수치/근거는 [재현 결과](dev0427_response_results.json), 전체 회귀와 보존 검사는 [실행 기록](project_context.md#dev-0427-골렘-대응-검토-검사)을 따른다.

현재 골렘 시야 감지는 반경160과 플레이어 몸체 겹침을, 하네스 감지는 반경88과 골렘 몸체 겹침을 사용한다. 반경88을 중심 거리88의 딱 잘린 사거리로 표시하면 부정확하다. 이번 준비 사례에서70px 부근은 Q 대상이 잡혔고140px 부근은 시야에 보여도 Q 대상이 없었다. 골렘 접촉은 거리34·시야 추적 중1초 경고 뒤 실패이며 방전/이탈 시 경고가 해제된다.

기본 장착의 무료 안내는 `경비 골렘 비상 방전 · 충전 1`과 벽/문·소음 설명이다. 사용 전에 잠깐 정지시키는 효과와 바로 움직여야 한다는 설명은 정밀 분석에 치우쳐 있다. 기본 장착에는 정밀 분석이 없다. 충전0에서도 같은 Q 문구가 표시되고, 눌렀을 때 부족 안내가 나온다. 미장착은 거점 변경 안내가 있고 범위 밖에는 Q 안내가 없다. 성공 후 정지 상태는 표시되지만 출정의 ChoiceStatus에는 방전 성공 전용 안내가 연결돼 있지 않다.

G는 가방에서 직접 선택한 일반품만0.6초 길게 눌러 버린다. 이번 사례에서 미선택은 버리지 않았고 선택 뒤에는 과적132→정상240으로 회복했다. 보호 원본 금지·선택 취소·일시정지 경계는 기존 quick_drop_smoke를 따른다. 가방 칸 확대는 보류다.

## 유인 지점 도착과 복귀

현재 유인 성공은 즉시 의심0.7초를 시작하고 다음 수색2.5초를 시작한다. **수색 타이머는 도착 여부와 독립적이다.** 의심 이동75·수색 이동65로 목표를 향해 직선 이동하며, 벽을 돌아가는 길찾기는 없다. 약3.22초 뒤에는 도착했든 아니든 원래 순찰로 복귀한다. 아래 값은60Hz 물리 프레임 관찰이며 렌더러/프레임 순서에 따라 한 프레임 정도 달라질 수 있다.

| 골렘→착지 거리/장애물 | 도착 | 도착 뒤 복귀까지 | 복귀 시점의 남은 거리 |
|---|---:|---:|---:|
| 40px, 열린 통로 | 약0.50초 | 약2.72초 | 도착 판정 범위 안 |
| 160px, 열린 통로 | 약2.32초 | 약0.90초 | 도착 판정 범위 안 |
| 300px, 열린 통로 | 도착하지 않음 | 0초 | 약84px |
| 160px, 중간 벽 | 도착하지 않음 | 0초 | 약130px |

0.7×75+2.5×65=215px는 멈춤/충돌 없는 이상적 이동 상한의 근사값이다. 이 때문에 반응 반경320 안에 있는 유인물도 도착 전에 수색이 끝날 수 있다. 플레이어 기준 최대 투척300과 골렘 기준 청취320은 서로 다른 거리다. 착지 표식1초도 골렘의 실제 관심 유지 시간과 다른 값이다.

직접 보이는 플레이어는 유인물보다 우선하며 이번 청취 검사에서도 유인이 거절됐다. 벽으로 시야를 끊은 뒤에는 유인이 받아들여졌다. 이동 소음 경보가 이미 누적된 경계 상태, 방전 중·범위 밖·일시정지/종료의 우선순위는 기존 검사를 유지한다. 기존 UI의 거절 시 안내는 `소음 유인물이 떨어졌습니다.`라서 알아차리지 못함·직접 시야·다른 이유를 구별하기 어렵다. 실제 반응을 모르는 상태에서 확실히 유인했다고 단정하는 안내는 피해야 한다.

## 후속 보완의 최소 범위

다음 DEV-0428에서 구현할 방향이며 이번 코드에 적용되지 않았다. 설계 수치가 필요한 항목은 착수 때 MIG-CHG에 시험 조건을 먼저 기록하고 최종 밸런스와 구별한다.

1. **행동 전에 효과·가능 조건 안내.** Q의 기본 설명에 잠깐 멈춤·그동안 거리 벌리기를 무료로 알린다. 충전 부족/미장착/범위 밖을 현재 대상 기준으로 구별한다. 가까운 위험 대상 선택과 중복 입력·충전 예약/환불·문 고정의 기존 계약을 유지한다.
2. **성공과 다시 움직임의 짧은 안내.** 예시 후보는 `골렘을 잠깐 멈춥니다. 그동안 멀어지세요.`, `잠깐 멈췄습니다. 지금 거리를 벌리세요.`다. 정식 문구는 화면 길이와 다른 위험 안내의 우선순위를 대조해 결정한다. 무료 설명에 정확한 남은 초를 상시 공개해 관찰 개선의 정밀 정보 보상을 없애지 않는다.
3. **유인 이동과 도착 후 확인 분리.** 도달 가능한 가까운/먼 착지점에서 도착 후 확인할 시간이 남도록 한다. 벽에 막혀 못 가는 경우에는 이동/정체의 유한한 제한으로 순찰에 돌아가도록 하며 무한 정체·무한 유인을 만들지 않는다. 구현은 유인으로 시작한 조사에 한정하고 일반 시야 상실 수색·발소리/경보·방전 재가동을 함께 늘리지 않는다. 새 길찾기는 이 최소 범위에 포함하지 않는다.
4. **유인 중·반응 없음·복귀 전달.** 직접 보이는 동안은 유인이 추적을 없애지 않는다는 행동 설명과, 실제 골렘이 착지 위치를 확인하는지의 상태를 구별한다. `소리가 난 곳을 살피는 중`, `다시 순찰을 돕니다` 같은 쉬운 말 후보를 사용한다. 시야 밖의 정확한 위치/남은 초를 전지적으로 공개하지 않는다.

속도 전체 하향, 기본 정지 시간 증가, 감지/접촉 규칙 변경, 스태미나·전력질주 추가는 이번 최소안에 포함하지 않는다. GDD7-3에 짧은 탈출 가속 역할 예시는 있지만 MVP7-5의 세 행동 제한·새 입력/자원·적재/소음/건강 관계 검토가 필요하다. 기존 수단의 설명과 유인 조사 보완 후에도 열린 공간의 대응 실패가 남는지 사람에게 다시 확인한 뒤 비교한다.
