# G1 통합 플레이테스트와 검토 기록

## 현재 결과

`DEV-0111`의 통합 장면·자동 검사·검토 자료를 준비했다. **커밋 후 추가 검사에서 발견한 가방 열기 입력 오류 1건을 사용자 지시에 따라 보완했고, 재현 검사를 포함한 스모크 장면 12개가 통과했다. 사람 플레이테스트와 G1 최종 판단은 아직 끝나지 않았다.** 이 문서는 게임 규칙이나 제품 수치를 새로 확정하지 않는다.

2026-09-06 Godot 4.7.1에서 스모크 장면 12개가 모두 통과했다. 새 통합 검사는 좌표를 순간 이동시키지 않고 실제 이동 입력으로 벽·갈림길·위험 통로·우회로를 통과한다. 미확인 정보 보존, 충전 배분, 생환·실패와 종료 후 기록 고정도 함께 확인했다.

`정합성 검사: 지금`이다. 완료한 G1 기능과 GDD 15-2의 구조는 일치하며 아래 입력 오류 보완도 자동 검증을 마쳤다. GDD 20-1의 사람 판단 및 `Q-004`·`Q-005`가 남아 있으므로 **G1 통과와 `DEV-0201` 진입은 보류**한다. 통합 장면·검토 자료는 사용자 승인으로 `eabc705`에 저장했으며, 이번 검사 기록과 입력 보완도 검증 결과 검토 후 사용자가 커밋을 승인했다. 코드·자료의 커밋 승인은 이 관문 통과와 구분한다.

## 커밋 후 추가 정합성 검사 — 2026-09-06

사용자의 검사 지시에 따라 `eabc705`의 코드·공식 기준·검증 자료·다음 작업 조건을 대조했다. 아래 표는 수정 전 검사 결과이며, 이후 사용자 보완 지시에 따른 수정·검증은 아래 보완 결과에 기록했다.

| 검사 | 결과 |
|---|---|
| Godot 4.7.1 기존 스모크 장면 12개 재실행 | 모두 통과, 종료 코드 0 |
| 저장한 자동 기록과 이번 실행 비교 | 네 시나리오의 모든 필드 일치 |
| UI 버튼 클릭 후 실제 Tab 입력 추가 재현 | 가방이 열리지 않는 오류 1건 확인 |
| 활성 문서 검사 | 42개 문서, 상대 링크 1,009개·본문 위치 링크 154개·관련 경로 399개 통과 |
| 동결 원본과 보존 사본 | 9개 SHA-256 일치 |
| 구현 범위·다음 단계 | 시험 자료와 제품 코드 분리 유지. G1 통과 및 `DEV-0201` 진입 보류 |

실행 로그의 기존 샌드박스 인증서 저장소 접근 오류 외에 새 엔진 오류·경고나 스크립트 오류는 없었다. 문서 링크 수는 검사 기록을 추가하기 전 기준이다. 임시 입력 재현은 자동 검사이며 사람 플레이테스트로 집계하지 않는다.

### 발견한 오류: 분석 버튼 선택 후 가방이 열리지 않음

- 재현: 통합 장면에서 붕괴 잔해의 분석 범위에 접근하고, `정밀 분석` 버튼을 마우스로 클릭한 다음 `Tab`을 누른다. 분석으로 충전이 3에서 2로 줄어든 뒤에도 가방은 열리지 않고 탐험 시간이 계속 흐른다. 이후 붕괴 경고가 시작되어 분석 버튼이 다시 활성화되어도 같은 현상이 발생한다.
- 수정 전 원인: [가방 입력 처리](../../src/ui/inventory_panel.gd)가 열린 가방의 닫기만 `_input`에서 처리하고, 열기는 `_unhandled_input`에서 처리했다. 분석 버튼에 남은 키보드 포커스가 `Tab`을 먼저 소비해 가방 열기까지 전달되지 않았다.
- 영향: 하네스 분석 뒤 물품을 비교하거나 버리려는 정상 흐름이 막힌다. 붕괴 경고 중이라면 가방으로 시간을 멈추려던 플레이어가 계속 위험에 노출된다.
- 확인 근거: 임시 재현 검사에서 화면 크기를 1152×648로 설정하고 실제 마우스 누름·뗌과 Tab 입력을 전달했다. `charge=2`, `inventory_visible=false`, `paused=false`와 분석 버튼 포커스를 확인했다. 포커스를 해제하고 같은 Tab 입력을 보내면 `inventory_visible=true`, `paused=true`로 바뀌었다.
- 기존 검사가 놓친 이유: [통합 자동 검사](../../tests/smoke/g1_integration_playtest_smoke.gd)의 기존 네 경로는 분석 버튼의 `pressed` 신호를 직접 발생시켜 클릭으로 생기는 포커스를 재현하지 않았다. 키 이벤트에도 물리 키 코드만 넣어 기본 UI 포커스 이동을 재현하지 못했다. 닫기 포커스 검사는 가방 내부 버튼·목록에 한정되어 있었다.
- 보완 기준: 분석 버튼을 실제로 클릭한 직후와 위험 상태가 바뀐 뒤에도 Tab으로 가방이 열리고 탐험 시간이 멈춰야 한다. 기존 가방 닫기·일시정지 복원·확인 창 동작도 유지해야 한다.

### 보완 결과

사용자 지시에 따라 가방 열기와 닫기를 모두 `_input`에서 처리해 버튼의 Tab 포커스 이동보다 먼저 실행하도록 수정했다. 분석 버튼의 포커스를 강제로 해제하거나 입력 설정을 바꾸지 않았다.

통합 스모크 장면에 별도 입력 검사를 추가했다. 1152×648 화면에서 실제 이동으로 잔해에 접근하고 분석 버튼에 마우스 누름·뗌을 전달한다. 키 이벤트에는 논리 키와 물리 키 코드를 함께 넣는다. 클릭 뒤 비활성화된 분석 버튼과 경고 시작 뒤 다시 활성화된 버튼 양쪽에서 포커스가 남아 있음을 확인한 상태로 Tab 열기·닫기, 탐험 시간·붕괴 타이머의 정지·재개를 검사한다. 이 검사는 기존 네 경로의 비교 기록과 분리한다.

- 수정 전: 새 재현 검사에서 가방 열기·시간 정지가 실패하며 종료 코드 1을 확인했다.
- 수정 후: 같은 검사와 기존 스모크 장면을 합친 12개가 모두 통과했고 종료 코드 0을 확인했다.
- 회귀 확인: 시작 전·종료 후 가방 입력 차단, 가방 내부 포커스에서 닫기, 기존 일시정지 상태 복원, 일반 버리기 확인·취소·보호가 유지된다.
- 자료 확인: 기존 자동 실행 원본의 네 경로는 이번 실행과 모든 필드가 일치한다. 제품 수치·저장 형식 변경은 없다.

입력 보완의 구현·자동 검증을 마쳤으며 검증 결과 검토 후 사용자가 커밋을 승인했다. 다음은 사람 플레이 의견을 받아 GDD 20-1을 판단하는 절차다. 목표 탐험 시간과 무게 감속에 필요한 근거가 여전히 없으면 `Q-004`·`Q-005`를 임의 확정하지 않고 결정 시점을 사용자와 정한다.

## 직접 실행하기

저장소 폴더의 PowerShell에서 프로젝트 컨텍스트에 설정한 `GODOT_BIN`으로 실행한다.

```powershell
& $env:GODOT_BIN --path . --resolution 1280x800 res://tests/fixtures/g1_integration_playtest_space.tscn
```

현재 컴퓨터에서 환경 변수를 설정하지 않았다면 다음 명령을 사용할 수 있다.

```powershell
& 'C:\tmp\godot-4.7.1\Godot_v4.7.1-stable_win64_console.exe' --path . --resolution 1280x800 res://tests/fixtures/g1_integration_playtest_space.tscn
```

1. 시작 화면에서 가방 2칸 또는 3칸을 선택한다. 처음에는 2칸으로 자유롭게 돌아다닌다.
2. `WASD`로 이동하고 `E`로 회수한다. 오른쪽 미확인 장치는 첫 `E`가 조사, 다음 `E`가 회수다.
3. `Tab`으로 가방을 열어 가치·무게를 비교한다. 일반 물품 버리기는 확인 창을 거친다. 가방을 보는 동안 탐험 시간이 멈춘다.
4. 기본 분석은 무료다. 정밀 분석 버튼·`Q` 안정화·`Q` 비상 방전은 충전 3을 함께 쓴다. 아래쪽 붕괴 통로와 오른쪽 끝 우회로를 비교해 본다.
5. 왼쪽의 같은 입구로 돌아가 `E`를 누른다. 붕괴 범위에 남아 실패하는 경우도 별도 결과로 확인할 수 있다.
6. 결과의 `기록 복사` 버튼으로 기록을 복사하고 아래 질문에 대한 의견을 함께 남긴다. `조건을 다시 골라 시작`으로 가방 3칸을 선택해 같은 경로를 비교한다.

골렘은 추적과 일시 정지까지 구현되어 있으며 접촉 피해·실패를 일으키지 않는다. 붕괴는 경고 종료 시 범위에 남아 있는 플레이어를 포착한다. 이 제한은 이번 사람 평가에도 함께 고려해야 한다.

## 확인 공간과 시험 값

위쪽 통로에는 알려진 폐품 두 개, 아래쪽에는 붕괴 통로·가치가 알려진 정밀 부품·골렘·미확인 장치가 있다. 가운데 벽의 오른쪽 끝으로 돌아가면 붕괴 통로를 피할 수 있다. 모든 물품 이름·값·배치는 테스트 전용이며 출시 콘텐츠가 아니다.

| 항목 | 시험 값 | 해석 범위 |
|---|---|---|
| 가방 | 시작 시 2칸 또는 3칸 | 같은 배치에서 칸 수만 비교 |
| 무게 단계 | 부담 2.5 / 과적 4.0 | 두 가방 조건에서 동일 |
| 이동 속도 | 240 px/s | 무게에 따른 감속은 아직 없음 |
| 물품 무게 | 1.0 / 2.0 / 2.5 / 2.5 | 가벼운 폐품·무거운 폐품·정밀 부품·미확인 장치 |
| 충전 | 3, 각 행동 비용 1 | 분석과 대응 사이의 사용 선택 |
| 붕괴 경고 | 3초 | 기존 위험의 경고·포착 흐름 |
| 골렘 경고 / 정지 | 1.4초 / 2초 | 기존 경고·추적·비상 방전 흐름 |

미확인 장치의 실제 분류·가치는 플레이 화면과 회수 결과에서 숨긴다. 기본·정밀 하네스 분석은 잔해·골렘의 현재 상태를 읽으며 물품 감정을 대신하지 않는다.

## 자동 검사와 수집 기록

```powershell
& $env:GODOT_BIN --headless --fixed-fps 60 --path . --log-file "$env:TEMP/dungeon-g1-smoke.log" --quit-after 20000 res://tests/smoke/g1_integration_playtest_smoke.tscn
```

원본 결과는 [자동 실행 기록](g1_playtest_automated_results.json)에 보존했다. 아래 시간은 `--fixed-fps 60`에서 자동 입력이 만든 **시뮬레이션상의 탐험 시간**이다. 사람의 고민·읽기 시간, 실행에 걸린 실제 시간 또는 제품의 목표 런 시간으로 사용하지 않는다.

| 자동 시나리오 | 결과 | 가방 | 탐험 시간 | 버리기 / 가방 부족 | 최대 무게 | 남은 충전 | 회수 / 미확인 |
|---|---|---:|---:|---:|---:|---:|---:|
| 분석·안정화·골렘 정지 뒤 우회 귀환 | 생환 | 2칸 | 22.85초 | 2 / 2 | 5.0 | 0 | 2 / 1 |
| 동일한 우회 경로, 작은 가방 | 생환 | 2칸 | 15.93초 | 1 / 1 | 4.5 | 3 | 2 / 1 |
| 동일한 우회 경로, 여유 가방 | 생환 | 3칸 | 15.90초 | 0 / 0 | 5.5 | 3 | 3 / 1 |
| 폐품 회수 뒤 붕괴 범위에 잔류 | 실패 | 2칸 | 9.32초 | 0 / 0 | 1.0 | 3 | 손실 1개 |

가방 비교에 사용하는 두 우회 시나리오는 같은 물품과 경로를 사용하며 이동 거리도 각각 3,664 px로 같다. 2칸에서는 가벼운 폐품을 버려야 미확인 장치를 챙길 수 있었고, 3칸에서는 셋을 모두 챙겨 무게가 더 늘었다. 위험 대응 경로는 다른 행동을 수행하므로 가방 크기의 비교 자료로 섞지 않는다.

기록은 탐험 시간·가방 확인 시간, 이동 거리, 최대 무게·칸 수, 부담·과적 상태의 시간, 조사·회수·버리기·가방 부족, 충전 행동별 횟수, 골렘 경고·추적, 우회 통과와 최종 회수·손실을 포함한다. 사건 순서도 함께 남긴다. 가방 확인 시간은 탐험 시간에서 제외하며, 종료 뒤 수치와 사건 목록은 더 바뀌지 않는다. 복사본을 고쳐도 원본 기록은 유지된다.

자동 실행은 `source: automated`, 시작 버튼으로 사람이 플레이한 기록은 `source: human`으로 구분한다. 이 구분과 JSON 필드는 검사 자료용이며 제품 저장 형식이 아니다. 게임 상태를 저장하거나 다음 탐험에 이어 붙이지 않는다.

| 경비 골렘 1종 | 경고·추적·방전, 우회로를 이용한 이탈 | 통과 |
| 하네스 분석·안정화·방전 | 세 행동이 충전 3을 함께 소비 | 통과 |
| 임시 화면·결과 로그 | 시작 조건·상태 안내·결과·기록 복사·다시 시작 | 초기화·화면 확인과 추가 UI 입력 보완 검사 통과 |

시작·분석·결과 화면은 1280×800 렌더링으로 확인했다. 회수 결과의 긴 설명이 기록 영역을 침범해 자동 줄바꿈과 목록 최소 높이를 조정했다. 최종 배치에서 두 결과 패널이 겹치지 않고 기본 높이 648 px 안에 들어오는지도 확인했다.

## GDD 20-1 사람 검토

자동 입력으로 구조를 재현했다는 사실만으로 아래 항목을 통과 처리하지 않는다. 현재 실제 사람 응답은 없다.

## 수치 판단의 한계와 다음 확인

| 질문 | 이번 자료에서 알 수 있는 것 | 아직 필요한 것 | 상태 |
|---|---|---|---|
| `Q-004` 목표 런 시간 | 작은 비교 맵의 이동·행동 시간을 기록할 수 있음 | 15~25분 가안에 맞는 탐험 분량의 사람 검증 또는 결정 시점을 미루는 사용자 판단 | `provisional` 유지 |
| `Q-005` 칸 수·무게 단계·감속률 | 같은 경로에서 2칸은 교체를 요구하고 3칸은 더 무거운 적재를 허용함 | 사람의 선택 부담·가독성 평가, 이동 감속을 검토할 별도 근거 | `provisional` 유지 |

이 작은 맵을 오래 걷게 만드는 것만으로 목표 런 시간을 검증하지 않는다. 무게 감속이 없는 현재 결과에서 감속률 0을 제품 결정으로 채택하지도 않는다. 새 수치·세계관·성장·감정·저장 규칙을 결정 기록에 추가하지 않았다.

## 사람 기록 양식

```text
플레이 조건: 가방 2칸 / 3칸
복사한 결과 기록:
더 들어갈지 돌아갈지 고민한 지점:
버린 물품과 이유 / 두 가방 중 더 나았던 쪽:
위험 징후와 분석·충전 조작에서 헷갈린 점:
비전투 대응과 입구 귀환의 느낌:
원하는 탐험 길이와 그 이유:
```

사람 기록을 받으면 위 다섯 기준과 `Q-004`·`Q-005`를 다시 검토한다. 미확정 항목을 어떻게 처리할지 결정하고, 사용자가 정합성 결과를 검토해 진행을 지시한 뒤 다음 개발 작업을 시작한다.
