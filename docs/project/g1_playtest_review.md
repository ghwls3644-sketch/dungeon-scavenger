# G1 통합 플레이테스트와 검토 기록

## 현재 결과

`DEV-0111`의 통합 장면·자동 검사·검토 자료를 준비했다. **가방 입력 보완 `a1aae2f` 이후 발견한 긴 설명 잘림은 선택 물품 상세 영역으로 보완했다. 시험 조건도 조정해 같은 경로에서 충전 대응의 추적 감소 효과와 무료 통과를 함께 검증했다. 스모크 장면 12개가 통과했으며 사람 플레이테스트와 G1 최종 판단은 아직 끝나지 않았다.** 이 문서는 게임 규칙이나 제품 수치를 새로 확정하지 않는다.

2026-09-06 Godot 4.7.1에서 스모크 장면 12개가 모두 통과했다. 새 통합 검사는 좌표를 순간 이동시키지 않고 실제 이동 입력으로 벽·갈림길·위험 통로·우회로를 통과한다. 미확인 정보 보존, 충전 배분, 생환·실패와 종료 후 기록 고정도 함께 확인했다.

`정합성 검사: 지금`이다. 완료한 G1 기능과 GDD 15-2의 구조는 일치하며 이번 가독성·시험 조건 보완도 검증을 마쳤다. GDD 20-1의 사람 판단 및 `Q-004`·`Q-005`가 남아 있으므로 **G1 통과와 `DEV-0201` 진입은 보류**한다. 통합 장면·검토 자료는 `eabc705`, 입력 오류 보완은 `a1aae2f`로 사용자 승인 후 커밋했다. 이번 가독성·시험 조건 보완은 검증 결과 검토 후 사용자가 커밋을 승인했다. 코드·자료의 커밋 승인은 이 관문 통과와 구분한다.

## 커밋 후 추가 정합성 검사 — 2026-09-06

사용자의 검사 지시에 따라 `eabc705`의 코드·공식 기준·검증 자료·다음 작업 조건을 대조했다. 아래 표는 수정 전 검사 결과이며, 이후 사용자 보완 지시에 따른 수정·검증은 아래 보완 결과에 기록했다.

| 검사 | 결과 |
|---|---|
| Godot 4.7.1 기존 스모크 장면 12개 재실행 | 모두 통과, 종료 코드 0 |
| 저장한 자동 기록과 이번 실행 비교 | 네 시나리오의 모든 필드 일치 |
| UI 버튼 클릭 후 실제 Tab 입력 추가 재현 | 가방이 열리지 않는 오류 1건 확인 |
| 활성 문서 검사 | 42개 문서, 상대 링크 1,009개·본문 위치 링크 154개·관련 경로 399개 통과 |

실행 로그의 기존 샌드박스 인증서 저장소 접근 오류 외에 새 엔진 오류·경고나 스크립트 오류는 없었다. 문서 링크 수는 검사 기록을 추가하기 전 기준이다. 임시 입력 재현은 자동 검사이며 사람 플레이테스트로 집계하지 않는다.

### 발견한 오류: 분석 버튼 선택 후 가방이 열리지 않음

- 재현: 통합 장면에서 붕괴 잔해의 분석 범위에 접근하고, `정밀 분석` 버튼을 마우스로 클릭한 다음 `Tab`을 누른다. 분석으로 충전이 3에서 2로 줄어든 뒤에도 가방은 열리지 않고 탐험 시간이 계속 흐른다. 이후 붕괴 경고가 시작되어 분석 버튼이 다시 활성화되어도 같은 현상이 발생한다.
- 수정 전 원인: [가방 입력 처리](../../src/ui/inventory_panel.gd)가 열린 가방의 닫기만 `_input`에서 처리하고, 열기는 `_unhandled_input`에서 처리했다. 분석 버튼에 남은 키보드 포커스가 `Tab`을 먼저 소비해 가방 열기까지 전달되지 않았다.
- 영향: 하네스 분석 뒤 물품을 비교하거나 버리려는 정상 흐름이 막힌다. 붕괴 경고 중이라면 가방으로 시간을 멈추려던 플레이어가 계속 위험에 노출된다.
- 확인 근거: 임시 재현 검사에서 화면 크기를 1152×648로 설정하고 실제 마우스 누름·뗌과 Tab 입력을 전달했다. `charge=2`, `inventory_visible=false`, `paused=false`와 분석 버튼 포커스를 확인했다. 포커스를 해제하고 같은 Tab 입력을 보내면 `inventory_visible=true`, `paused=true`로 바뀌었다.
- 기존 검사가 놓친 이유: [통합 자동 검사](../../tests/smoke/g1_integration_playtest_smoke.gd)의 기존 네 경로는 분석 버튼의 `pressed` 신호를 직접 발생시켜 클릭으로 생기는 포커스를 재현하지 않았다. 키 이벤트에도 물리 키 코드만 넣어 기본 UI 포커스 이동을 재현하지 못했다. 닫기 포커스 검사는 가방 내부 버튼·목록에 한정되어 있었다.
- 보완 기준: 분석 버튼을 실제로 클릭한 직후와 위험 상태가 바뀐 뒤에도 Tab으로 가방이 열리고 탐험 시간이 멈춰야 한다. 기존 가방 닫기·일시정지 복원·확인 창 동작도 유지해야 한다.

### 보완 결과

사용자 지시에 따라 가방 열기와 닫기를 모두 `_input`에서 처리해 버튼의 Tab 포커스 이동보다 먼저 실행하도록 수정했다. 분석 버튼의 포커스를 강제로 해제하거나 입력 설정을 바꾸지 않았다.

통합 스모크 장면에 별도 입력 검사를 추가했다. 1152×648 화면에서 실제 이동으로 잔해에 접근하고 분석 버튼에 마우스 누름·뗌을 전달한다. 키 이벤트에는 논리 키와 물리 키 코드를 함께 넣는다. 클릭 뒤 비활성화된 분석 버튼과 경고 시작 뒤 다시 활성화된 버튼 양쪽에서 포커스가 남아 있음을 확인한 상태로 Tab 열기·닫기, 탐험 시간·붕괴 타이머의 정지·재개를 검사한다. 이 검사는 기존 네 경로의 비교 기록과 분리한다.

- 수정 전: 새 재현 검사에서 가방 열기·시간 정지가 실패하며 종료 코드 1을 확인했다.
- 수정 후: 같은 검사와 기존 스모크 장면을 합친 12개가 모두 통과했고 종료 코드 0을 확인했다.
- 회귀 확인: 시작 전·종료 후 가방 입력 차단, 가방 내부 포커스에서 닫기, 기존 일시정지 상태 복원, 일반 버리기 확인·취소·보호가 유지된다.
- 자료 확인: 기존 자동 실행 원본의 네 경로는 이번 실행과 모든 필드가 일치한다. 제품 수치·저장 형식 변경은 없다.

입력 보완의 구현·자동 검증을 마쳤으며 검증 결과 검토 후 사용자가 커밋을 승인했다. 다음은 사람 플레이 의견을 받아 GDD 20-1을 판단하는 절차다. 목표 탐험 시간과 무게 감속에 필요한 근거가 여전히 없으면 `Q-004`·`Q-005`를 임의 확정하지 않고 결정 시점을 사용자와 정한다.

## 화면과 자유 이동 검토 — 2026-09-06

사용자 지시에 따라 `a1aae2f`의 화면을 Godot 4.7.1 Compatibility 렌더러로 확인하고, 기존 자동 시나리오와 다른 선택으로 실제 이동·상호작용 입력을 실행했다. 아래 세 항목은 보완 전 검토 기록이다. 이 검토는 자동 실행과 화면 관찰이며 사람의 주관적 플레이 응답으로 집계하지 않는다. 이후 사용자 보완 지시에 따른 결과는 다음 절에 기록한다.

### 가방의 긴 설명 표시

1280×800 실제 렌더링에서 미확인 장치 행이 `미확인 물…`로 잘리고 뒤쪽의 `가치 미확인`·`보호 여부 미확인`은 행 안에 보이지 않는다. 1152×648 배치 검사에서도 같은 현상을 확인했다. [가방 목록](../../src/ui/inventory_panel.tscn)은 한 줄 표시이며 현재 미확인 물품의 문자열 폭은 785 px, 행의 사용 가능한 폭은 552 px다. 물품에 있는 정보가 소실되거나 실제 가치가 노출된 것은 아니지만, 화면에서 상태를 함께 비교하기 어렵다.

일반 물품 두 종류의 가치·무게는 같은 폭 안에 들어온다. 생환·실패 결과 패널도 기록 패널과 겹치지 않는다. 보완은 가방에서 선택한 물품의 상세 정보를 별도 영역이나 여러 줄로 보여주는 범위에 집중하는 것이 적절하다. 제품의 정보 공개 규칙이나 가방 수치를 바꿀 필요는 없다.

화면 확인용 물품 구성은 무거운 폐품·정밀 부품·미확인 장치이며, 표시 검사에만 사용했다. 이 화면의 즉시 생성한 회수 결과·시간은 플레이 경로 자료에 합산하지 않는다.

### 충전 없이 위험 경로를 왕복한 결과

가방 2칸으로 시작해 위쪽 폐품을 건너뛰고 아래쪽 붕괴 통로를 신속히 통과했다. 정밀 부품을 회수한 뒤 골렘 앞을 지나 미확인 장치를 조사·회수하고 같은 아래쪽 통로로 입구에 돌아왔다. 좌표를 순간 이동시키거나 골렘 앞에서 추적을 기다리지 않았다.

| 항목 | 추가 자동 실행 결과 |
|---|---|
| 생환·회수 | 정밀 부품과 미확인 장치 2개 회수 |
| 분석·안정화·방전 | 모두 0회, 충전 3/3 유지 |
| 버리기·우회로 | 모두 0회 |
| 골렘 | 경고 2회, 추적 0회 |
| 적재 | 최대 무게 5.0, 과적 상태 약 6.45초 |
| 이동 | 2,844 px, 막힌 경로 없음 |
| 탐험 시간 | 고정 60프레임 자동 입력의 시뮬레이션 시간 12.67초 |

이 시간은 사람의 탐험 시간이나 `Q-004`의 목표 시간 판단에 사용하지 않는다. 기존 네 시나리오와 경로·행동이 다르므로 가방 크기나 하네스 행동의 효율을 통제 비교한 자료도 아니다. 별도 탐색 사례로만 해석한다.

신속 통과와 무료 우회는 GDD 9-1에 있는 대응이므로, 하네스를 쓰지 않고 생환했다는 사실 자체는 오류가 아니다. 다만 현재 장면에는 무게에 따른 감속이 없고 골렘 접촉의 손실·실패도 없으며, 이 경로에서는 추적조차 시작되지 않았다. 따라서 안정화·방전·짐 버리기가 언제 도움이 되는지, 더 들어갈지 돌아갈지의 판단과 귀환의 안도감이 생기는지를 평가할 근거가 약하다.

### 다음 검토에 대한 제안

1. 가방의 긴 설명을 먼저 읽기 쉽게 보완한다.
2. 시험 맵의 거리·경고 시간·골렘 동선에서 충전 대응과 무료 회피의 장단점을 비교할 수 있는 조건을 검토한다. 무료 통과를 없애거나 행동을 강제로 사용하게 만들지 않는다. 제품 수치 확정, 무게 효과나 골렘 손실 판정 추가는 이번 검토에서 결정하지 않는다.
3. 사람이 직접 플레이한 뒤 망설인 지점, 버린 물품과 이유, 경고 인지, 대응의 유용성과 귀환 느낌을 확인한다. `Q-004`·`Q-005`의 최종 수치를 이 작은 맵만으로 확정하지 않는다.

검토 당시 판단은 가독성 보완과 시험 조건 검토가 필요하다는 것이었다. 사용자가 이 두 항목의 보완을 지시했으며 아래 범위에서 구현·검증했다.

## 가독성과 시험 조건 보완 결과 — 2026-09-06

가방 목록 아래에 선택 물품의 이름, 칸 수·무게, 공개된 분류·가치·보호 상태와 위험 정보를 여러 줄로 표시한다. 목록의 줄임표와 별개로 현재 미확인 장치의 정보가 모두 읽힌다. 더 긴 설명은 상세 영역 안에서 스크롤하며, 선택 변경·빈 가방에서 이전 정보가 남지 않는다. 미확인 물품의 실제 분류·가격·보호 상태는 상세 영역에서도 숨긴다.

1280×800 렌더링으로 상세 표시를 확인했다. 1152×648에서 가방은 `(276, 114)` 위치의 `602×426` 영역 안에 들어오며 생환·실패 결과 패널도 기록 패널과 겹치지 않는다. 긴 위험 설명, 선택 갱신, 미확인 정보 비노출과 스크롤 가능 여부를 기존 인벤토리 자동 검사에 추가했다.

시험 맵은 붕괴 경고를 3초에서 1.2초, 골렘 경고를 1.4초에서 0.7초, 추적 속도를 115에서 210 px/s로 조정했다. 플레이어 속도 240 px/s와 방전 정지 2초는 유지한다. 값은 통합 시험 장면에만 적용하며 일반 골렘·위험 모듈의 기본값, 무게 감속, 접촉 피해·실패, 최종 제품 수치는 바꾸지 않았다. 신속 통과와 무료 우회로는 여전히 생환 가능하다.

새 자동 비교 두 경로는 가방 2칸, 정밀 부품·미확인 장치 회수, 최대 무게 5.0, 이동 거리 2,844 px, 탐험 시간 12.70초가 같다. 좌표 순간 이동이나 추적 시작을 기다리는 입력 없이 같은 경로를 이동하며 한쪽만 안정화·방전을 각각 한 번 사용한다.

| 같은 경로의 대응 선택 | 남은 충전 | 골렘 추적 상태 시간 | 붕괴 경고 상태 시간 | 회수 결과 |
|---|---:|---:|---:|---|
| 충전 없이 신속 통과 | 3/3 | 7.28초 | 1.20초 | 2개 생환 |
| 안정화·방전 각각 1회 | 1/3 | 1.38초 | 0.05초 | 2개 생환 |

충전을 아끼는 선택과 경고·추적을 줄이는 선택의 차이를 확인했다. 대응 뒤에도 추적이 잠시 발생할 수 있으며, 이 값은 실제 피해 감소나 사람의 만족도를 측정한 것은 아니다. 붕괴 경고 시간은 위험 오브젝트가 경고 상태인 시간으로, 플레이어가 위험 범위에 머문 시간과 구분한다. 가방을 연 동안 두 상태의 기록 시간도 늘지 않으며 종료 뒤 고정된다.

기존 네 경로에 두 비교 경로를 더한 여섯 실행의 원본과 적용 조건을 [자동 실행 기록](g1_playtest_automated_results.json)에 갱신했다. 앞선 검사 기록의 수치는 당시 조건을 설명하는 이력이며 현재 값과 혼용하지 않는다. 전체 스모크 장면 12개가 통과했고, 앞서 고친 Tab 조작·일시정지 복원·버리기 확인과 보호·미확인 회수 결과도 유지된다.

이번 보완은 구현·검증 결과를 검토한 뒤 사용자가 커밋을 승인했다. 다음은 사람이 직접 플레이해 경고 시간이 충분한지, 충전 사용이 유용한지, 더 들어갈지 돌아갈지 고민했는지 확인하는 절차다. `Q-004`·`Q-005`와 G1 통과는 아직 결정하지 않는다.

## 직접 실행하기

저장소 폴더의 PowerShell에서 프로젝트 컨텍스트에 설정한 `GODOT_BIN`으로 실행한다.

```powershell
& $env:GODOT_BIN --path . --resolution 1280x800 res://tests/fixtures/g1_integration_playtest_space.tscn
```

현재 컴퓨터에서 환경 변수를 설정하지 않았다면 다음 명령을 사용할 수 있다.

```powershell
& 'C:\tmp\godot-4.7.1\Godot_v4.7.1-stable_win64_console.exe' --path . --resolution 1280x800 res://tests/fixtures/g1_integration_playtest_space.tscn
```

1. 시작 화면에서 가방 2칸 또는 3칸을 선택한다. 처음에는 2칸으로 자유롭게 돌아다닌다.
2. `WASD`로 이동하고 `E`로 회수한다. 오른쪽 미확인 장치는 첫 `E`가 조사, 다음 `E`가 회수다.
3. `Tab`으로 가방을 열어 가치·무게를 비교한다. 선택한 물품의 상세 정보를 목록 아래에서 읽고, 긴 설명은 그 영역 안에서 스크롤한다. 일반 물품 버리기는 확인 창을 거친다. 가방을 보는 동안 탐험 시간이 멈춘다.
4. 기본 분석은 무료다. 정밀 분석 버튼·`Q` 안정화·`Q` 비상 방전은 충전 3을 함께 쓴다. 아래쪽 붕괴 통로와 오른쪽 끝 우회로를 비교해 본다.
5. 왼쪽의 같은 입구로 돌아가 `E`를 누른다. 붕괴 범위에 남아 실패하는 경우도 별도 결과로 확인할 수 있다.
6. 결과의 `기록 복사` 버튼으로 기록을 복사하고 아래 질문에 대한 의견을 함께 남긴다. `조건을 다시 골라 시작`으로 가방 3칸을 선택해 같은 경로를 비교한다.

골렘은 추적과 일시 정지까지 구현되어 있으며 접촉 피해·실패를 일으키지 않는다. 붕괴는 경고 종료 시 범위에 남아 있는 플레이어를 포착한다. 이 제한은 이번 사람 평가에도 함께 고려해야 한다.

## 확인 공간과 시험 값

위쪽 통로에는 알려진 폐품 두 개, 아래쪽에는 붕괴 통로·가치가 알려진 정밀 부품·골렘·미확인 장치가 있다. 가운데 벽의 오른쪽 끝으로 돌아가면 붕괴 통로를 피할 수 있다. 모든 물품 이름·값·배치는 테스트 전용이며 출시 콘텐츠가 아니다.

가방 비교에 사용하는 두 우회 시나리오는 같은 물품과 경로를 사용하며 이동 거리도 각각 3,664 px로 같다. 2칸에서는 가벼운 폐품을 버려야 미확인 장치를 챙길 수 있었고, 3칸에서는 셋을 모두 챙겨 무게가 더 늘었다. 위험 대응 경로는 다른 행동을 수행하므로 가방 크기의 비교 자료로 섞지 않는다.

기록은 탐험 시간·가방 확인 시간, 이동 거리, 최대 무게·칸 수, 부담·과적 상태의 시간, 조사·회수·버리기·가방 부족, 충전 행동별 횟수, 골렘 경고·추적, 우회 통과와 최종 회수·손실을 포함한다. 보완 후에는 골렘 추적 상태와 붕괴 경고 상태의 지속 시간도 수집한다. 사건 순서도 함께 남긴다. 가방 확인 시간은 탐험 시간에서 제외하며, 종료 뒤 수치와 사건 목록은 더 바뀌지 않는다. 복사본을 고쳐도 원본 기록은 유지된다.

자동 실행은 `source: automated`, 시작 버튼으로 사람이 플레이한 기록은 `source: human`으로 구분한다. 이 구분과 JSON 필드는 검사 자료용이며 제품 저장 형식이 아니다. 게임 상태를 저장하거나 다음 탐험에 이어 붙이지 않는다.
